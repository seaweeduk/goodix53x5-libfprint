## Behavior

This is an alternate feature-bitmap construction path parallel to
`FUN_18006eff0`. It creates owned packed threshold bitmaps at feature offsets
`+0x08`, `+0x10`, and `+0x18`, and an unpacked matrix at `+0x20`.

This is the active profile-9/type-12 path.
`FUN_18004ae70:0x18004b2ae..0x18004b341` uses the predicate
`((type - 9) & 0xfffffff6) != 0`; type 12 satisfies it and calls this function
with half-resolution selector `1`. Types `9`, `10`, `17`, and `18` take
`FUN_18006eff0` instead.

In its half-resolution branch it divides the input width and height by two,
allocates the `+0x20` matrix through `FUN_180068700`, and fills it with nested
loops bounded strictly by those reduced dimensions. The allocation request has
no extra sentinel or halo byte and the fill does not write beyond the declared
matrix payload.

For type 12, the enhanced source is sampled at even/even coordinates into the
`52x44` temporary. `FUN_180071260` selects its threshold from values whose
corresponding `52x44` mask byte is nonzero, using target
`(205 * active_count + 128) >> 8`. Packing then sets a bit for every enhanced
pixel strictly greater than the selected threshold; the mask limits threshold
selection but does not gate output bits. Empty selection returns threshold `1`.
The selector's cumulative and distance comparisons are signed; in particular
bin zero above the target selects `0`. See [FUN_180071260](FUN_180071260.md).

## Half-Resolution Inputs And Ownership

Arguments are the half-resolution selector, base byte matrix, enhanced byte
matrix, full-resolution mask matrix, and feature object. The type-12 caller
`FUN_18004ae70` constructs the mask with `FUN_18007e4b0`, enhancement with
`FUN_18007eb30`, and the base matrix from the high bytes of the Q8 filtered
image before this call. This call precedes keypoint extraction and has no
minimum mask-support or feature-count admission test.
The mask producer is called with write selector `1`, magnitude threshold `110`,
and output value `1` (`FUN_18004ae70:0x18004b241..0x18004b25b`). Thus its output
is binary; zero support is not rejected before bitmap construction. The mask
and enhanced image derive independently from the same cropped byte image;
neither is constructed by thresholding the other.
The common-image producers permit bin zero to exceed the quantile target;
[FUN_18007e4b0](FUN_18007e4b0.md) describes a concrete same-image construction
with 46 sampled mask cells, 41 enhanced zeros, and target 37. Unmasked enhanced
ones remain eligible for output packing on that path.

For selector `1`, the temporary and feature `+0x20` matrix dimensions are input
width/2 and height/2. Source accesses use `2 * (source_stride * row + column)`.
The temporary first holds the base projection for `+0x08` (`value > 200`) and
`+0x18` (`value >= 56`) packing, then is overwritten with the enhanced projection
for `+0x10`. The mask projection is retained at `+0x20`. The input matrices are
not mutated. The temporary is freed through `FUN_180068b70`; output matrices are
feature-owned and existing allocations are reused.

The enhanced packed payload is written in row-major sample order, least
significant bit first. Each full group writes all eight bits from strict
unsigned-byte `value > threshold` comparisons; any residual group writes a
fresh byte with unused high bits zero. Type 12 has 2288 bits, exactly 286 bytes,
so its last byte is a complete group. Packing does not read the mask. A null
enhanced matrix instead sets feature `+0x10` to null; the populated type-12 path
supplies an enhanced matrix. Allocation success and compatible matrix storage
are caller preconditions for the sampled path.

## Retained Consumer

The enhanced plane remains feature-owned at `+0x10` after the temporary is
freed. [FUN_180040a70](FUN_180040a70.md) reads that matrix and writes tag `cf`,
including its dimensions, stride, element type, and all 286 payload bytes.
Serialization neither reapplies the mask nor recomputes the threshold. The
quantile value itself is not stored in the feature. Consequently thresholds
`0` and `1` differ in retained and serialized bits exactly at enhanced samples
equal to `1`, including samples excluded from the quantile histogram.

## Quantile Mask Versus Match Validity

The sampled byte matrix at `+0x20` is not the validity owner used by ordinary
enhanced-bitmap overlap. [FUN_180071d40](FUN_180071d40.md) calls
[FUN_1800721a0](FUN_1800721a0.md) on each feature's inline mask at `+0x28`,
then uses those expanded masks for both primary `+0x08` and enhanced `+0x10`
passes. Its secondary pass reuses the primary warped-validity allocation.

[FUN_180072b60](FUN_180072b60.md) constructs `+0x28` from each full-resolution
binary `4x4` validity block: at least eight admitted pixels sets one inline bit.
Mode-one expansion replicates that bit over a `2x2` half-resolution block.
This majority/expansion operation is neither equal to even/even sampling nor
generally a subset or superset of it. An admitted block can re-admit an excluded
even/even position; a rejected block can discard an admitted even/even position.
The sampling and reduction also have distinct lifetimes: bitmap selection uses
initial validity, whereas later broken-pixel clearing can precede inline-mask
construction. [FUN_18004ae70](FUN_18004ae70.md) owns that ordering.

Tag `ce` preserves `+0x28`; reload regenerates the expanded/packed rescue mask
`+0x140` from that inline owner, not from the unsaved `+0x20` byte matrix.
Its `FUN_180073950` representation is row-padded: each 52-bit row occupies
seven bytes, hence 308 bytes for 44 rows, with four unused high bits in each
row's final byte. It is not the contiguous 286-byte enhanced-bitmap layout.
Consequently a bitmap bit excluded during quantile selection must be evaluated
against the actual later expanded validity and warp footprint before treating
it as either consumed or irrelevant to overlap.

Re-admitted enhanced values of `1` are consumed as ordinary binary samples when
the selected threshold is zero. They can move overlap population from class
`00` to class `10` against a zero-valued direct target. The enhanced pass is
eligible to replace the primary returned score when its score is strictly
larger and its detail is strictly greater than 195; these re-admitted samples
can therefore change the returned overlap score, not only serialized payload.
See [FUN_180071d40](FUN_180071d40.md) for selection and
[FUN_180073540](FUN_180073540.md) for class ordering.

For a concrete common-image instance, use the line train and four-pixel widening
in [FUN_18007e4b0](FUN_18007e4b0.md), omit its distant intensity-one rectangle,
and instead set column 24, rows 33 through 49, to one. Sampling still gives
46 admitted cells, 41 enhanced zeros and target 37. Inline expansion admits
48 cells: it adds the six full-resolution sites `(36,24)` through `(46,24)`
in steps of two rows and discards four other sampled cells. Those six added
sites have enhanced value one. Against the same construction without the
intensity-one column, identity-affine ordinary overlap has enhanced classes
`[37,0,6,5]`, primary score 128 and selected enhanced score 214. Removing that
column gives classes `[43,0,0,5]` and selected score 246. The nonzero-mode
weights are `{3,2,3}`, context count is zero, and the optional masked and
filtered-count publication arguments are null. Both results retain primary
coverage 5 and selected detail 241.

Native feature reload through `FUN_18003d6c0` expects its three bitmap owners
at `+0x08/+0x10/+0x18` already allocated with matching `52x44`, type-eight
descriptors. Its `FUN_18003f060(..., allocate=0)` calls populate those owners;
they do not allocate missing bitmap descriptors. Reload need not reconstruct
the original sampled validity at `+0x20` for ordinary overlap.

The related current owner is `goodix_milan_feature_enhanced_bitmap()` in
