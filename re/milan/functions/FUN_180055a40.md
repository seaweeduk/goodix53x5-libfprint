# FUN_180055a40

## Identity And Interface

- Body: `0x180055a40..0x180057135`.
- Role: profile-9/type-12 feature traversal, candidate policy, score/evidence
  publication, match-time lifecycle mutation, and deferred-study admission.
- Callers: ordinary matcher dispatcher `FUN_18005edb0`, queued continuation
  `FUN_18005d330`, and wrapper `FUN_18005ef60`.

```c
int32_t FUN_180055a40(
    int32_t *score,
    void *probe,
    void *gallery,
    int32_t configuration[20],
    int32_t evidence[422],
    void *optional_result);
```

The evidence block is `0x698` bytes. Relevant fields are retained-entry count
`+0x640`, retained flag `+0x644`, selected feature `+0x648`, selected score
`+0x64c`, selected affine `+0x650`, strict active-relation count `+0x668`,
independent routed relation affine `+0x66c`, acceptance `+0x684`, rejection
`+0x688`, continuation state `+0x68c`, incoming blocker seed `+0x690`, and
matcher flags `+0x694`.

The gallery supplies feature count `+0x1c`, maximum features `+0x20`, feature
owners `+0x28`, stored traversal order `+0x87e8`, queue owners `+0x8d10`, ranks
`+0x8db0`, and queue state `+0x8e00`. A live feature's active marker `b5` is
`+0x110`, quality/coverage are `+0x11c/+0x120`, lifecycle word `be` is `+0x134`,
registration block pointer is `+0x160`, histogram owner is `+0x158`, and packed
class word `c7` is `+0x150`.

## Initialization And Ownership

Entry saves incoming blocker seed `+0x690`, then clears and initializes the
caller evidence and score fields. Each invocation owns fresh `180x180`
correspondence/layout matrices in its stack frame. The matrices
are reset for each gallery occurrence, borrowed by primary, alternate, sibling,
and overlap helpers, and expire on return. They are never retained in evidence,
the queue, or study state.

The probe histogram owner, when nonnull, is decoded by `FUN_180073830` into
three local bytes. Its first byte is an independent auxiliary class; it is not
the packed-`c7` low class or the match-level status counter. With a null owner,
all three bytes remain zero.

`FUN_180070d90` separately decodes configuration word 18 and each feature's
`c7`. Ordinary `FUN_18005edb0` initializes word 18 from probe `c7`; queued
`FUN_18005d330` forces it to zero. The decoded probe low/high classes and the
histogram class remain independent inputs.

## Cross-Gallery Probe Ownership

For ordinary type-12 identification, the live probe is a read-only input to
matching. Neither this function nor its reachable probe consumers rewrite its
geometry, record count `+0xf0`, record storage `+0xf8`, partition `+0x118`,
quality/coverage `+0x11c/+0x120`, inline mask `+0x28`, packed bitmap owners,
rescue mask `+0x140`, histogram `+0x158`, anti-fake owner `+0x160`, or `c7`.
The same extracted object can therefore be passed from a nonpositive gallery
comparison to the next gallery without restoration or re-extraction.

The writable destinations on these paths are distinct from the probe:

| Path | Writable Owner |
| --- | --- |
| `FUN_18005a3c0`, `FUN_180057900` correspondence construction | Caller stack correspondence/layout matrices, local nearest-neighbor arrays, candidate metrics, and affine outputs |
| `FUN_18005b900` consensus and orientation filtering | Copied point/orientation arrays, local inlier/index arrays, and affine output; `FUN_180057140` invalidates local pair indexes, not source records |
| `FUN_180074e80` transformed-record metrics | Metric output only; transformed coordinates remain scalar temporaries |
| `FUN_180072860` refinement | Two lazily allocated record-index maps in this invocation's local refinement context, plus candidate/affine outputs |
| `FUN_180071d40`, `FUN_180070c70` overlap | Newly expanded masks and unpacked bitmap copies; `FUN_180073a90` allocates rather than exposing the packed bitmap payload as writable storage |
| `FUN_18005d9e0` aggregate rescue | A deep copy of probe rescue mask, local accumulators, score, and evidence |
| `FUN_18003a3e0` anti-fake comparison | Local mask intersection, allocated correspondence/distance arrays, and caller metric outputs |
| `FUN_1800462a0` queue insertion | The current gallery's queue owner and ranks; `FUN_180045a50` deep-copies from probe to queue feature |
| `FUN_18005d5f0` fallback | Local candidate/affine/score state using the same read-only probe |

`FUN_180037690`, reached by the queue copier, sorts a local record-rank array
if truncation is required and partitions only the destination feature. Its
record-tail clearing also targets the destination. It never sorts, truncates,
partitions, or clears the live probe's records. Ordinary type-12 probe record
count and each queue feature's record capacity are bounded by 150.

Gallery lifecycle increments and order sorting target the current gallery,
not the probe or a different gallery. Queue features are separately allocated
owners, so a rejected gallery cannot retain a writable alias to the shared
probe through enqueue.

At entry `0x180055a85`, the incoming blocker seed is saved locally. The full
evidence clear is `0x180055b34..0x180055b3d`; sentinel, affine, score, and
continuation initialization follow at `0x180055b42..0x180055b7d`. The seed's
per-gallery producer is documented in `FUN_18005edb0.md`. Accumulated classes,
late-status counts, contribution sums, retained candidates, and fallback
workspaces are invocation-local, not previous-gallery input.

With nonzero live record count, this type-12 body returns status zero directly
or returns the terminal fallback's status. The fallback's only nonzero status
is also the zero-live-record case (`0x80000006`). Rejection scores are therefore
successful matcher returns, not gallery-error returns. Dispatcher policy errors
for unsupported flags or type are outside the ordinary flags-zero/type-12
invocation; a valid preceding gallery cannot create those errors by changing
the shared probe.

## Traversal And Pre-Primary Skip

The function reads physical feature indices from gallery order `+0x87e8` and
does not validate their range or uniqueness before dereferencing owners. Live
record ownership remains keyed by physical feature index; a sparse live-owner
array changes only the records for that index and never replaces traversal
order. Appends add the old feature count at the order tail, replacements do not
move their target, and final sorting belongs to `FUN_1800607b0` after matching
and queued continuation.

At `0x180055d80..0x180055db9`, an occurrence is skipped when:

```text
configuration[13] == 0 && feature_index != configuration[14]
||
((gallery.feature_count == gallery.maximum_features || evidence[+0x688] == 1)
 && evidence[+0x644] == 1
 && feature.b5 == 1)
```

The state tests in the second arm are exact equality with one. The first arm
makes queued matching trigger-only: `FUN_18005d330` supplies word 13 zero and
the current continuation index in word 14.

This skip precedes feature-`c7` decoding, accumulated-high mutation, and the
one-shot continuation latch. A skipped occurrence performs none of those
updates. A non-skipped occurrence decodes first, sets the current capped state
to `min(5, prior_high + feature_high)`. At `0x180055e00..0x180055e0c`,
it updates accumulated high to `max(prior_high, feature_high)` only when
`feature_high > 3`; feature highs zero through three leave it unchanged.
Candidate rejection later in the occurrence does not undo these updates.

The one-shot branch at `0x180055e12..0x180055e34` observes status-one returns
from earlier non-skipped occurrences only. When the status counter is greater
than five, accumulated high class is below five, and the latch is zero, it
increments the class, sets the latch, and clears the local retention gate at
`RBP-0x50`. It does not write evidence `+0x68c`.

At `0x180056313..0x180056360`, the late-status tuple is assembled as
`[updated_accumulated_high, histogram_class, saved_capped_sum]`. Word zero
includes both the conditional feature-high update and any one-shot increment;
word two retains the sum computed before either update. It is not recomputed
from the updated accumulator. If the one-shot arm is not taken and the prior
status counter exceeds ten, `0x180055e36..0x180055e3a` exits traversal before
candidate construction.

The accumulator never decreases. The status counter starts at zero at
`0x180055cb1`; only a status-one return from `FUN_180058700` increments it,
once per call. If the one-shot arm executes, its prior count is exactly six:
the first non-skipped occurrence after the sixth status either takes that arm
or has already reached class five, which cannot later decrease. After eleven
status returns, no further occurrence reaches candidate construction. Skipped
occurrences may still advance the order cursor before the next non-skipped
occurrence takes the cutoff. The final counter is therefore at most eleven.
The one-shot branch requires at least seven non-skipped occurrences, and the
cutoff requires at least twelve. With ordinary permutation order, gallery
counts at most six and at most eleven respectively exclude those branches.
The trigger-only queued caller admits at most one occurrence per invocation,
so neither counter-dependent branch can execute there.

## Candidate Construction

For each admitted occurrence, the type-12 order is:

```text
zero the 77-word candidate and initialize the affine to identity
FUN_18005a3c0 primary/alternate construction
FUN_180057900 sibling construction
word1 = max_signed(word1, word2), retaining word1 on equality
require word1 > 4 and word10 >= 30
require FUN_1800624c0(selected_affine, decoded_probe_low, 12) == 0
recompute words 4, 5, 9, and 12..14
require FUN_18005b440(...) == 0
run the first FUN_180054ec0 classification
optionally refine through FUN_180072860 and refresh words 4, 5, 9..11, 66..76
copy the selected affine to words 15..20
run the second FUN_180054ec0 classification
unless flag60 == 2 && accumulated_high <= 1:
    populate low-bitmap words 6..8
    call FUN_180053220
call FUN_180058700
```

The complete candidate ownership before policy is:

| Words | Owner |
|---|---|
| `0..2` | primary/alternate/sibling construction, then signed max for `1/2` |
| `3` | zero |
| `4,5` | overlap recomputation or refinement |
| `6..8` | low-bitmap metrics, or zero on the exact bypass |
| `9` | Q8 coverage recomputation or refinement |
| `10,11` | transformed-record percentages |
| `12..14` | affine penalties |
| `15..20` | selected affine |
| `21..65` | zero |
| `66..70` | valid count, retained count, topology, geometry, average distance |
| `71..76` | zero for type 12 |

The affine is materialized before the second classifier, which reads only words
`0..14`. Refinement is not followed by another count/topology gate and may
therefore publish topology below 30 after initial admission. Invalid primary,
alternate, or sibling models have no value-level error encoding; callers must
not consume indeterminate affine/result state from an invalid model.

The type-12 refinement publication at `FUN_180072860:0x180072a2d..0x180072b02`
does not write candidate words zero through two. It reads word one for the
transformed-record helper, then replaces overlap/coverage, transformed-record
outputs and affine. The retained-count admission at `0x180055f0d` therefore
continues to bound the contribution numerator after refinement.

`FUN_180071d40` supplies overlap score in word 4, selected detail in word 5,
and primary coverage contributes to Q8-scaled word 9. Its transform, selected
count, and complete returned overlap object remain one owner: ranking must not
combine one affine with another model's count or overlap fields.

## Policy And Contribution

`FUN_180053220` receives the completed candidate, probe quality and coverage,
the 20-word configuration, and flag outputs at stack `+0x60/+0x64`. Word 19 is
mutable recognition state. Ordinary calls initialize it to one; the queued
caller does not initialize it. Its late-eligibility call requires incoming
flag60 zero and word 19 exactly one.

The pre-dispatch classifier `FUN_180054ec0` supplies flag60 in `0..2` and
Boolean flag64, with nonzero flag60 implying flag64 one. Its promotion at
`0x1800551d2..0x1800551f6` changes one to two only for raw candidate
`word0 >= 8 && word1 >= 12 && word11 >= 36`. This is a strength flag, not
the identity of the primary, alternate, or sibling affine producer.
The dispatcher skips initial OR classification when both flags are nonzero;
late eligibility runs only with flag60 zero. It cannot OR one into a surviving
two. Subsequent clear-only stages preserve nonzero-match-implies-candidate.

When word 18 is positive, type is 12, and one of these strict pairs holds, the
caller clears both flags before late policy:

```text
(word0 < 9 && word11 < 12)
(word0 < 8 && word11 < 14)
(word0 < 7 && word11 < 16)
(word0 < 6 && word11 < 18)
(word0 < 5 && word11 < 20)
```

`FUN_180058700` receives the unchanged probe, candidate, type 12, selected
affine, state `[updated_accumulated_high, histogram_class,
saved_capped_sum]` as defined above, the shared status counter,
and flag60. Return one increments that counter and immediately continues to the
next occurrence, skipping `FUN_1800553f0`, contribution, evidence, lifecycle,
and fallback staging. Return zero proceeds with flag64 unchanged and flag60
preserved or cleared. The callee consumes probe `+0x120` in its quality role and
`+0x11c` in its coverage role.

After status zero, `FUN_1800553f0` may only clear flags. Contribution is:

```text
flag64 == 1
|| (candidate[4] > configuration[0] + 207 && candidate[5] > 195)
```

For a contributor:

```text
term = (candidate[1] * 256 + 21) / 42
q8_sum += term
contributor_count++
```

All operations use wrapped dword arithmetic where emitted as dword operations;
signed divisions truncate toward zero. The candidate winner is a complete
77-word copy, separate from the selected feature/count/affine in evidence.
Its ranking key is candidate words `[5,1,9]`: overlap detail, retained count,
then Q8 coverage. At `0x1800563ef..0x180056404`, these are loaded from candidate
offsets `+0x14/+0x04/+0x24`. The comparisons are signed and lexicographic;
equality is not a better rank.

Replacement also depends on the evidence entering the contribution:

| Prior Evidence | Replace Candidate Winner When |
| --- | --- |
| Rejection `+0x688 == 0`, acceptance `+0x684 == 0` | `flag60 != 0 || flag64 != 0 || better_rank` |
| Rejection `+0x688 == 0`, acceptance `+0x684 != 0` | `flag60 != 0 || (flag64 != 0 && better_rank)` |
| Rejection `+0x688 != 0` | `flag60 != 0 && better_rank` |

These branches are at `0x180056425..0x180056602`. Exact ties retain the earlier
winner only when no unconditional flag arm applies. Contribution and winner
mutation occur before later relation, retained-evidence, and blocking decisions
and are not rolled back by those later paths.

Retained evidence has a separate predicate:

```text
(candidate[0] > 6 && candidate[5] > 208) || flag64 != 0
```

Direct selected feature/count/affine replace only when nonzero flag64 accompanies
candidate word 1 strictly greater than evidence selected count `+0x64c`. Equal
count retains the earlier selected owner. Independently, every contributing
nonzero flag64 relatches score from the current prefix:

```text
score = (q8_sum * 100 / contributor_count) >> 8
```

Thus lower/equal-count direct results can change score without changing selected
feature or affine; zero-flag contributors extend the prefix but do not relatch
until a later nonzero flag64.

With ordinary retained counts `5..42` and at most 40 feature occurrences,
each term is `30..256`, the total is at most `10240`, and the percentage
product is at most `1024000`. No dword overflow occurs in this prefix
calculation. Every nonempty relatch is in `11..100`; adding zero-flag
contributors cannot turn an earlier positive latch into zero because those
contributors do not write the score. For prefix sum `S` and count `K`, a
latched score at most 40 is exactly `100*S < 10496*K`. This bounds the prefix
average, not the separately selected greatest retained count.

Evidence stores at `0x180056e71..0x180056ea3` are logical-OR Boolean stores:
nonzero final flag64 makes acceptance `+0x684` exactly one, and nonzero final
flag60 makes rejection `+0x688` exactly one. Active relation ownership is
independent: for a contributing candidate with nonzero flag64 and live `b5==1`,
candidate word 1 must strictly exceed relation count `+0x668` before the count
and `FUN_1800619a0`-routed affine `+0x66c` are replaced. Equal count retains the
earlier relation owner. Rescue can later replace selected feature/affine without
replacing this relation owner.

## Blocking

Matcher entry reads incoming evidence `+0x690` before clearing/reinitializing
the evidence object. Blocking requires that saved seed nonzero, both probe and
gallery registration blocks nonnull, and both coverages above 40. The read-only
`FUN_18003a3e0` result has five signed dwords: zero, mutual-pair count, symmetric
Q12 support, directional Q12 support, and lower-median detail. This caller reads
words one through four.

Persisted scalar deltas use wrapping dword subtraction followed by signed
comparison:

```text
texture_delta  = gallery[+0x12c4] - probe[+0x12c4]
shape_delta    = gallery[+0x12c8] - probe[+0x12c8]
boundary_delta = gallery[+0x1ab0] - probe[+0x1ab0]
boundary_score = gallery[+0x1ab4]
```

One type-12 rejection term is `shape_delta > 415 && boundary_delta > 318`.
The complete predicate family is at `0x180056794..0x180056c1c`. On a hit,
`0x180056c22..0x180056c26` increments blocker count and adds
`wrap32(detail + adjustment)` to blocker sum. Adjustment starts at `-20`, becomes
`-10` for nonsentinel boundary score below 70, and becomes zero for score below
60 or `boundary_delta > 100 && boundary_score < 75`. Blocking occurs after
contribution but before direct evidence and `be` publication.

## Post-Loop Selection

The ranked 77-word candidate is not an input to direct score relatching,
selected-count or affine publication, active-relation routing, lifecycle
increments, or queue admission. Its nonnull optional-result consumer at
`0x180056cc1..0x180056ce5` copies ranked candidate word 9 to result `+0x20`,
but copies the affine from evidence `+0x650`, not from that candidate.
Ordinary `identifyImage` supplies a null optional result through
`FUN_18005edb0`: `0x180001de6` and `0x180001e9b` zero `ECX` before the
argument-seven store at `0x180001e12`. This optional scalar/affine projection
is therefore absent in the ordinary image caller.

`FUN_18005d9e0` rescue runs before queue admission when contributor count
is greater than one, rejection evidence is zero, type is neither 11 nor
21, and blocker count is zero. The count tested at `0x180056c75` is stack
`+0x7c`, incremented at `0x1800563fb` only on contribution; it is not the
number of completed candidate rows. It consumes the physical-indexed candidate table,
including completed rows whose late-status return skipped contribution. Rescue
may publish score, selected feature, affine, and acceptance evidence. It adds no
new lifecycle increment and does not overwrite an earlier strict relation owner.

The rejection test at `0x180056c80..0x180056c87` precedes the optional clear
at `0x180056cb4..0x180056cba`. A surviving nonzero flag60 that has latched
rejection therefore blocks this rescue even when the local retention gate is zero.
Acceptance is not tested. Prior direct-selected affine can enter rescue only
with no latched rejection and at least two contributors; a candidate-positive,
flag60-zero publication is not excluded by these gates.

If score is still zero, no-direct/fallback finalization is entered only when:

```text
accumulated decoded c7 high class < 4
histogram class < 2
configuration[13] != 0
```

No-direct winner validation additionally requires at least one contributor,
configuration word 18 zero, blocker count zero, and nonzero
`FUN_1800608b0(winner, configuration)`. The call at `0x180057029` receives the
ranked candidate copy at stack-frame `RBP+0x10`, not the selected-count or
active-relation owner. It does not test acceptance or rejection evidence.
The return is reduced to a zero/nonzero gate at `0x180057031..0x180057038`;
its numeric score is not published. Nonzero takes the physical contributor-mask
increment loop at `0x180057050..0x18005706d`, sorts gallery order through
`FUN_1800607b0`, and publishes the final-prefix Q8 score at
`0x180057089..0x180057095`. Neither the increment mask nor that score depends
on which ranked vector passed. Selected feature may remain `-1`. Zero enters
`FUN_18005d5f0` with the separately staged fallback workspaces, not the ranked
vector. Positive fallback likewise may leave selected feature `-1` and adds no
lifecycle owner.

At this zero-score, zero-blocker compact boundary, an earlier contributing
candidate-positive publication is excluded by the positive-prefix bound above.
The remaining contributors have final flags zero and entered through the metric
arm (`word4 > configuration[0]+207 && word5 > 195`). Under ordinary word-zero
configuration, these are overlap greater than 207 and detail greater than 195.
This metric arm does not itself test the compact validator's low-bitmap detail,
coverage minimum, or affine-penalty sum; the latter predicates remain owned by
`FUN_1800608b0`.

After the fallback call at `0x1800570df`, a positive score sets acceptance
`+0x684` to one and returns immediately with the fallback status. It is not
overridden by a nonzero blocker count. Only a nonpositive fallback score is
replaced with `-65536` when blocker count is positive. This differs from the
separate count-and-sum blocking override used when the outer zero-score/class
admission condition is false. Neither fallback exit publishes its local winner
index or affine, changes rejection `+0x688`, or revisits queue admission.
The optional result's coverage at `+0x20` is overwritten by the fallback's
winner-carried coverage, while its previously copied affine stays unchanged.

The fallback-enable array is caller-zeroed. A per-feature fallback workspace is
published by `FUN_180079060`; staging requires retained count at least three,
configuration word 13 exactly one, and acceptance evidence still zero. A
candidate rejected before direct admission can stage immediately after meeting
the count requirement. A directly admitted candidate stages only after all
status/policy handling completes without latching acceptance. Invalid candidate
or affine state must not be staged.

## Lifecycle Mutation

The only writes to live gallery feature `be/+0x134` are:

- `0x180056f72`: unchecked 32-bit increment for every final direct-positive
  occurrence, in stored traversal order.
- `0x180057058`: unchecked 32-bit increment for each physical contributor after
  successful no-direct finalization.

Both wrap modulo `2^32`. Valid direct and no-direct increment loops are mutually
exclusive. Selected feature is not the lifecycle mask definition. Rescue keeps
all earlier direct increments but adds none; rescue without earlier direct
positives adds none. Positive fallback and rejection add none. Matcher writes
are not rolled back when a later selector or study action fails.

## Deferred-Study Producer

After rescue and the optional rejection clear, `0x180056cf5..0x180056d4b`
calls `FUN_1800462a0` exactly when:

```text
evidence[+0x688] == 0
configuration[13] == 1
decoded probe low class == 0
probe.coverage > 65
probe.quality > 15
accumulated high class < 4
probe histogram class < 3
gallery.queue_state == 0
```

Admission does not require a positive score, selected feature, or final match.
Normal aggregate/fallback publication occurs afterward and cannot undo an
insertion. `+0x688` is the same word later used as the study action gate.

Continuation evidence `+0x68c` starts at one. For nonzero probe `c0/+0x14c`,
`FUN_18005e480` can replace it; ordinary image extraction explicitly leaves
`c0` zero. A separate local retention gate at `RBP-0x50` is initialized to
`configuration[4] != 0 && evidence[+0x68c] != 0`, then cleared when the
`FUN_180073060` decoded probe high mode is nine. The one-shot branch can also
clear that local gate. Immediately after rescue,
`0x180056cb4..0x180056cc1` tests the local gate and clears rejection `+0x688`
when it is zero; it does not test or clear `+0x68c` there. The local gate also
controls whether a direct-positive occurrence exits or continues to fallback
workspace processing.

For ordinarily extracted probes, the packed low field decodes to `0`, `2`, or
`3`, and the packed high field is in `0..5`. Queue admission requires the
packed dword to be in `{0x000,0x100,0x200}`: raw high three decodes to four,
and raw highs four and five decode to five. The accumulator starts at that
decoded probe high and never decreases, so those values cannot pass its strict
`<4` gate. This is a necessary class-domain condition, not sufficient queue
admission. Insertion preserves the admitted dword
in queued `Q+0x150`; it is not forced to zero. The producer enters with an empty
queue in the ordinary adapter lifecycle, so it creates only physical slot zero,
rank zero and cannot exercise duplicate replacement or full-queue eviction.

The producer requires `+0x688 == 0`, whereas `templateStudy` dispatches only
when the same word is nonzero. A Q inserted in this match therefore cannot be
consumed by this match's study. Ordinary adapter cleanup destroys the live
gallery and transient Q after action zero, and the next transaction freshly
unpacks all ranks as `-1`. Only a direct DLL caller that retains and reuses the
same live handle can carry Q to a later positive-primary consumer invocation.
Consumer traversal and action-five behavior remain contracts of
`FUN_18005d330`; they are not reachable through ordinary adapter persistence.

## Failure Behavior

The function assumes valid gallery order, feature owners, matrices, and helper
outputs. Out-of-range stored order can fault during owner lookup. Allocation or
materialization failures in callees are not transactionally rolled back here.
Evidence, contribution, lifecycle, queue, and gallery writes made before a later
failure remain live. Other template families use different matcher paths and
are outside this type-12 contract.
