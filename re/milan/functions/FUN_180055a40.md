## Matrix Lifetime Across Ordinary And Queued Calls

`FUN_18005edb0` ordinary calls and `FUN_18005d330` queued calls enter the same
matrix ownership path. A queued call does not inherit matrices from the primary
call: it allocates fresh stack arrays and recomputes them for each feature of the
already primary-mutated shared live gallery. Study scalar/tag-only writes cannot
invalidate a cache because no matrix cache exists; append/replacement and live
record mutation instead affect the next recomputation directly.

The immediate `FUN_180057900` call receives the matrices populated for the
current gallery feature. The later low-bitmap call's success return is ignored
before policy; therefore a native security-gateway implementation must reject on
low-bitmap materialization failure rather than consume untouched default words.
The complete ownership and failure contract is
`re/milan/MATCH-MATRIX-CONTRACT.md`.
