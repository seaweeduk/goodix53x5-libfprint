# FUN_180055a40

## Identity And Interface

- Body: `0x180055a40..0x180057135`.
- Role: profile-9/type-12 feature traversal, candidate policy, score/evidence
  publication, match-time lifecycle mutation, and deferred-study admission.
- Callers: ordinary matcher dispatcher `FUN_18005edb0`, queued continuation
  `FUN_18005d330`, and wrapper `FUN_18005ef60`.

```c
int32_t FUN_180055a40(
    int32_t *score,
    void *probe,
    void *gallery,
    int32_t configuration[20],
    int32_t evidence[422],
    void *optional_result);
```

The evidence block is `0x698` bytes. Relevant fields are retained-entry count
`+0x640`, retained flag `+0x644`, selected feature `+0x648`, selected score
`+0x64c`, selected affine `+0x650`, strict active-relation count `+0x668`,
independent routed relation affine `+0x66c`, acceptance `+0x684`, rejection
`+0x688`, continuation state `+0x68c`, incoming blocker seed `+0x690`, and
matcher flags `+0x694`.

The gallery supplies feature count `+0x1c`, maximum features `+0x20`, feature
owners `+0x28`, stored traversal order `+0x87e8`, queue owners `+0x8d10`, ranks
`+0x8db0`, and queue state `+0x8e00`. A live feature's active marker `b5` is
`+0x110`, quality/coverage are `+0x11c/+0x120`, lifecycle word `be` is `+0x134`,
registration block pointer is `+0x160`, histogram owner is `+0x158`, and packed
class word `c7` is `+0x150`.

## Initialization And Ownership

Entry saves incoming blocker seed `+0x690`, then clears and initializes the
caller evidence and score fields. Each invocation owns fresh `180x180`
correspondence/layout matrices in its stack frame. The matrices
are reset for each gallery occurrence, borrowed by primary, alternate, sibling,
and overlap helpers, and expire on return. They are never retained in evidence,
the queue, or study state.

The probe histogram owner, when nonnull, is decoded by `FUN_180073830` into
three local bytes. Its first byte is an independent auxiliary class; it is not
the packed-`c7` low class or the match-level status counter. With a null owner,
all three bytes remain zero.

`FUN_180070d90` separately decodes configuration word 18 and each feature's
`c7`. Ordinary `FUN_18005edb0` initializes word 18 from probe `c7`; queued
`FUN_18005d330` forces it to zero. The decoded probe low/high classes and the
histogram class remain independent inputs.

## Traversal And Pre-Primary Skip

The function reads physical feature indices from gallery order `+0x87e8` and
does not validate their range or uniqueness before dereferencing owners. Live
record ownership remains keyed by physical feature index; a sparse live-owner
array changes only the records for that index and never replaces traversal
order. Appends add the old feature count at the order tail, replacements do not
move their target, and final sorting belongs to `FUN_1800607b0` after matching
and queued continuation.

At `0x180055d80..0x180055db9`, an occurrence is skipped when:

```text
configuration[13] == 0 && feature_index != configuration[14]
||
((gallery.feature_count == gallery.maximum_features || evidence[+0x688] == 1)
 && evidence[+0x644] == 1
 && feature.b5 == 1)
```

The state tests in the second arm are exact equality with one. The first arm
makes queued matching trigger-only: `FUN_18005d330` supplies word 13 zero and
the current continuation index in word 14.

This skip precedes feature-`c7` decoding, accumulated-high mutation, and the
one-shot continuation latch. A skipped occurrence performs none of those
updates. A non-skipped occurrence decodes first, sets the current capped state
to `min(5, prior_high + feature_high)`, and stores
`max(prior_high, feature_high)` for later occurrences. Candidate rejection later
in the occurrence does not undo those class-state updates.

The one-shot branch at `0x180055e12..0x180055e34` observes status-one returns
from earlier non-skipped occurrences only. When the status counter is greater
than five, accumulated high class is below five, and the latch is zero, it
increments the class, sets the latch, and clears continuation state `+0x68c`.

For each admitted occurrence, the type-12 order is:

```text

FUN_180057900 sibling construction

optionally refine through FUN_180072860 and refresh words 4, 5, 9..11, 66..76

run the second FUN_180054ec0 classification
unless flag60 == 2 && accumulated_high <= 1:
    populate low-bitmap words 6..8
    call FUN_180053220
call FUN_180058700
```

The complete candidate ownership before policy is:

| Words | Owner |
|---|---|
| `0..2` | primary/alternate/sibling construction, then signed max for `1/2` |
| `3` | zero |
| `4,5` | overlap recomputation or refinement |
| `6..8` | low-bitmap metrics, or zero on the exact bypass |
| `9` | Q8 coverage recomputation or refinement |
| `10,11` | transformed-record percentages |
| `12..14` | affine penalties |
| `15..20` | selected affine |
| `21..65` | zero |
| `66..70` | valid count, retained count, topology, geometry, average distance |
| `71..76` | zero for type 12 |

The affine is materialized before the second classifier, which reads only words
`0..14`. Refinement is not followed by another count/topology gate and may
therefore publish topology below 30 after initial admission. Invalid primary,
alternate, or sibling models have no value-level error encoding; callers must
not consume indeterminate affine/result state from an invalid model.

`FUN_180071d40` supplies overlap score in word 4, selected detail in word 5,
and primary coverage contributes to Q8-scaled word 9. Its transform, selected
count, and complete returned overlap object remain one owner: ranking must not
combine one affine with another model's count or overlap fields.

## Policy And Contribution

`FUN_180053220` receives the completed candidate, probe quality and coverage,
the 20-word configuration, and flag outputs at stack `+0x60/+0x64`. Word 19 is
mutable recognition state. Ordinary calls initialize it to one; the queued
caller does not initialize it. Its late-eligibility call requires incoming
flag60 zero and word 19 exactly one.

When word 18 is positive, type is 12, and one of these strict pairs holds, the
caller clears both flags before late policy:

```text
(word0 < 9 && word11 < 12)
(word0 < 8 && word11 < 14)
(word0 < 7 && word11 < 16)
(word0 < 6 && word11 < 18)
(word0 < 5 && word11 < 20)
```

`FUN_180058700` receives the unchanged probe, candidate, type 12, selected
affine, state `[accumulated_high, histogram_class,
min(5, accumulated_high + current_feature_high)]`, the shared status counter,
and flag60. Return one increments that counter and immediately continues to the
next occurrence, skipping `FUN_1800553f0`, contribution, evidence, lifecycle,
and fallback staging. Return zero proceeds with flag64 unchanged and flag60
preserved or cleared. The callee consumes probe `+0x120` in its quality role and
`+0x11c` in its coverage role.

After status zero, `FUN_1800553f0` may only clear flags. Contribution is:

```text
flag64 == 1
|| (candidate[4] > configuration[0] + 207 && candidate[5] > 195)
```

For a contributor:

```text
term = (candidate[1] * 256 + 21) / 42
q8_sum += term
contributor_count++
```

All operations use wrapped dword arithmetic where emitted as dword operations;
signed divisions truncate toward zero. The candidate winner is replaced by
strict lexicographic comparison of candidate words `[4,1,8]`; exact ties retain
the earlier winner. Contribution and winner mutation occur before later
relation, retained-evidence, and blocking decisions and are not rolled back by
those later paths.

Retained evidence has a separate predicate:

```text
(candidate[0] > 6 && candidate[5] > 208) || flag64 != 0
```

Direct selected feature/count/affine replace only when nonzero flag64 accompanies
candidate word 1 strictly greater than evidence selected count `+0x64c`. Equal
count retains the earlier selected owner. Independently, every contributing
nonzero flag64 relatches score from the current prefix:

```text
score = (q8_sum * 100 / contributor_count) >> 8
```

Thus lower/equal-count direct results can change score without changing selected
feature or affine; zero-flag contributors extend the prefix but do not relatch
until a later nonzero flag64.

Evidence stores at `0x180056e71..0x180056ea3` are logical-OR Boolean stores:
nonzero final flag64 makes acceptance `+0x684` exactly one, and nonzero final
flag60 makes rejection `+0x688` exactly one. Active relation ownership is
independent: for a contributing candidate with nonzero flag64 and live `b5==1`,
candidate word 1 must strictly exceed relation count `+0x668` before the count
and `FUN_1800619a0`-routed affine `+0x66c` are replaced. Equal count retains the
earlier relation owner. Rescue can later replace selected feature/affine without
replacing this relation owner.

## Blocking

Matcher entry reads incoming evidence `+0x690` before clearing/reinitializing
the evidence object. Blocking requires that saved seed nonzero, both probe and
gallery registration blocks nonnull, and both coverages above 40. The read-only
`FUN_18003a3e0` result has five signed dwords: zero, mutual-pair count, symmetric
Q12 support, directional Q12 support, and lower-median detail. This caller reads
words one through four.

Persisted scalar deltas use wrapping dword subtraction followed by signed
comparison:

```text
texture_delta  = gallery[+0x12c4] - probe[+0x12c4]
shape_delta    = gallery[+0x12c8] - probe[+0x12c8]
boundary_delta = gallery[+0x1ab0] - probe[+0x1ab0]
boundary_score = gallery[+0x1ab4]
```

One type-12 rejection term is `shape_delta > 415 && boundary_delta > 318`.
The complete predicate family is at `0x180056794..0x180056c1c`. On a hit,
`0x180056c22..0x180056c26` increments blocker count and adds
`wrap32(detail + adjustment)` to blocker sum. Adjustment starts at `-20`, becomes
`-10` for nonsentinel boundary score below 70, and becomes zero for score below
60 or `boundary_delta > 100 && boundary_score < 75`. Blocking occurs after
contribution but before direct evidence and `be` publication.

## Post-Loop Selection

`FUN_18005d9e0` rescue runs before queue admission when aggregate-candidate
count is greater than one, rejection evidence is zero, type is neither 11 nor
21, and blocker count is zero. It consumes the physical-indexed candidate table,
including completed rows whose late-status return skipped contribution. Rescue
may publish score, selected feature, affine, and acceptance evidence. It adds no
new lifecycle increment and does not overwrite an earlier strict relation owner.

If score is still zero, no-direct/fallback finalization is entered only when:

```text
accumulated decoded c7 high class < 4
histogram class < 2
configuration[13] != 0
```

No-direct winner validation additionally requires at least one contributor,
configuration word 18 zero, blocker count zero, and positive
`FUN_1800608b0(winner, configuration)`. It does not test acceptance or rejection
evidence. On success it publishes the final-prefix Q8 score while selected
feature may remain `-1`. Positive `FUN_18005d5f0` fallback likewise may leave
selected feature `-1` and adds no lifecycle owner.

The fallback-enable array is caller-zeroed. A per-feature fallback workspace is
published by `FUN_180079060`; staging requires retained count at least three,
configuration word 13 exactly one, and acceptance evidence still zero. A
candidate rejected before direct admission can stage immediately after meeting
the count requirement. A directly admitted candidate stages only after all
status/policy handling completes without latching acceptance. Invalid candidate
or affine state must not be staged.

## Lifecycle Mutation

The only writes to live gallery feature `be/+0x134` are:

- `0x180056f72`: unchecked 32-bit increment for every final direct-positive
  occurrence, in stored traversal order.
- `0x180057058`: unchecked 32-bit increment for each physical contributor after
  successful no-direct finalization.

Both wrap modulo `2^32`. Valid direct and no-direct increment loops are mutually
exclusive. Selected feature is not the lifecycle mask definition. Rescue keeps
all earlier direct increments but adds none; rescue without earlier direct
positives adds none. Positive fallback and rejection add none. Matcher writes
are not rolled back when a later selector or study action fails.

## Deferred-Study Producer

After rescue and the optional rejection clear, `0x180056cf5..0x180056d4b`
calls `FUN_1800462a0` exactly when:

```text
evidence[+0x688] == 0
configuration[13] == 1
decoded probe low class == 0
probe.coverage > 65
probe.quality > 15
accumulated high class < 4
probe histogram class < 3
gallery.queue_state == 0
```

Admission does not require a positive score, selected feature, or final match.
Normal aggregate/fallback publication occurs afterward and cannot undo an
insertion. `+0x688` is the same word later used as the study action gate.

Continuation state `+0x68c` starts at one. Immediately after rescue,
`0x180056cb4..0x180056cc1` clears rejection `+0x688` when that state is zero.
For nonzero probe `c0/+0x14c`, `FUN_18005e480` can replace the initial state;
ordinary image extraction explicitly leaves `c0` zero, so that general path is
not reached. The state also controls whether a direct-positive occurrence exits
or continues to fallback workspace processing.

For ordinarily extracted probes, the packed low field decodes to `0`, `2`, or
`3`, and the high field is `0..5`. Applying the producer gates gives admitted
packed `c7` exactly `{0x000,0x100,0x200,0x300}`. Insertion preserves that dword
in queued `Q+0x150`; it is not forced to zero. The producer enters with an empty
queue in the ordinary adapter lifecycle, so it creates only physical slot zero,
rank zero and cannot exercise duplicate replacement or full-queue eviction.

The producer requires `+0x688 == 0`, whereas `templateStudy` dispatches only
when the same word is nonzero. A Q inserted in this match therefore cannot be
consumed by this match's study. Ordinary adapter cleanup destroys the live
gallery and transient Q after action zero, and the next transaction freshly
unpacks all ranks as `-1`. Only a direct DLL caller that retains and reuses the
same live handle can carry Q to a later positive-primary consumer invocation.
Consumer traversal and action-five behavior remain contracts of
`FUN_18005d330`; they are not reachable through ordinary adapter persistence.

## Failure Behavior

The function assumes valid gallery order, feature owners, matrices, and helper
outputs. Out-of-range stored order can fault during owner lookup. Allocation or
materialization failures in callees are not transactionally rolled back here.
Evidence, contribution, lifecycle, queue, and gallery writes made before a later
failure remain live. Other template families use different matcher paths and
are outside this type-12 contract.
