## Behavior

The function builds the watershed class map through `FUN_18003d1a0`, retains
only class `2`, and thins that binary map in place through
`FUN_18003b6d0(..., 100)`. It then computes:

```text
maximum = max residual at rows 1..rows-2, columns 2..columns-3
          where class != 0xfe
difference_sum = sum abs(residual[p] - residual[q])
                 for every directional 8-neighbor class-2 pair
                 at rows 3..rows-4, columns 3..columns-4
adjacent_count = number of those directional pairs
denominator = adjacent_count * maximum
numerator = difference_sum * 1000
score = denominator == 0
          ? numerator
          : idiv32(wrap32(numerator + sar32(denominator, 1)),
                   signed32(denominator))
```

The final arithmetic block at `0x18003afab..0x18003afc8` keeps both products and
the rounding addition as dwords. The divisor half is an arithmetic `SAR`,
including negative odd wrapped divisors, before signed `IDIV` truncates toward
zero. A zero divisor returns the wrapped numerator.
The eight neighbor offsets visit northwest, north, northeast, east, southeast,
south, southwest, west. Only the center is restricted to the three-pixel inset;
a neighbor may lie one pixel outside it. Thus an undirected pair is counted
twice when both endpoints lie in the center domain and once when only one does.
The residual difference accumulator also wraps as a dword. Reordering its
pure additions does not change that wrapped sum.

The maximum is measured from the full class map **before** thinning and excludes
only `0xfe`, not queued `0xfd`, conflict `0xff`, or bright class 1. The thinning
input keeps exactly class 2 as value 2 and replaces all other labels with zero.
Neither input residual, dense mask nor retained contrast plane is modified.

Both allocated byte planes are freed before final ratio arithmetic. There is
no returned error status or allocation validation. The signed division can
fault for `INT32_MIN / -1`; a zero denominator instead follows the explicit
wrapped-numerator return. The builder stores the returned dword at `+0x12d0`
without a subsequent overwrite; see `FUN_1800392f0.md`.
