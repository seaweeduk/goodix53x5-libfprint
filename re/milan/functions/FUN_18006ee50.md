## Recovered Behavior

The function performs an in-place insertion sort of `count` adjacent 8-byte
pairs. Both words are signed 32-bit. The first word is ascending candidate
strength; when strengths tie, the second word is ascending original materialized
index (`0x18006ee91..0x18006ee9d`). It shifts only when the predecessor is
strictly greater by that lexicographic order, so the native sort is stable.
Because generated original indices are unique, the production ordering is total
and deterministic. Counts zero and one are unchanged; negative direct counts
also return unchanged because the native count is signed 32-bit.

`FUN_18004bbb0` stores negative absolute contrast as the first word and scan
order as the second. Therefore a type-12 truncation retains strongest candidates
first, and exact-strength ties retain original scale/row/column/collision order.

`0x18004a100..0x18004a15e`. Current source implements the same total order in
`drivers/goodix53x5/milan/feature/materialization.c:559..569` and applies it only
when `count > capacity` at lines `584..593`. Its C-library `qsort` is not stable,
so duplicate `(strength,index)` pairs could permute, but
`feature_materialize_candidate()` assigns unique increasing indices `0..count-1`.
Duplicate rank pairs are malformed intermediate state, not a synthetic-valid
output of the owner chain; there is no production tie/order defect.
