## Behavior

The decoder validates the outer `0x87/0x86` framing and CRC, allocates and
zeroes the live template, decodes top-level tags into offsets `+0x00..+0x24`,
then decodes feature tag `0x95` through `FUN_18003d6c0`. Feature pointers are
stored from `+0x28`, the decoded feature count is at `+0x1c`, and relation
storage starts at `+0x1b8`. After parsing it materializes packed masks and runs
the applicable feature normalization passes. Relation closure at
`0x18003e8ac..0x18003e8bd` is gated by
`(live_type - 9) & 0xfffffff6 == 0`, so it runs only for types `9`, `10`, `17`,
and `18`. Profile-9 live type 12 skips closure and retains omitted non-star slots
as unset identity.

The complete fixed header mapping, relation framing, graph block, tail block,
and CRC domain are maintained in `../OUTER-TEMPLATE-CODEC.md`. Decoder context
is nullable. Null context preserves serialized maximum `+0x20` and selects two
150-record limits. Nonnull context selects unsigned `min(40, *context)`.
Before parsing children, allocation uses the larger of the selected and
serialized maximum and the larger of 150 and serialized `9e`. After parsing,
`FUN_18003fef0` applies the selected maximum and sets both live record limits
to 150. See `FUN_180040700.md`.

The serialized `91` count is not the loop bound: after allocation the decoder
resets live count `+0x1c` to zero. Each successfully decoded `95` increments it;
when live count reaches serialized maximum `+0x20`, further feature elements are
skipped by their encoded lengths. For a valid producer template, the header
count equals its feature-element count and does not exceed serialized maximum.
Null-context decoding therefore cannot enter the subsequent count-shrink path.

Before parsing relations it initializes the physical matrix region to
`[leading=-1, affine identity]`. `FUN_18003f740` returns packed tag `e3` as an
absolute live slot, and this function copies the decoded 28-byte record directly
to `+0x1b8 + e3*0x1c`. Packed feature scalar `b6` restores each feature's row
base. The logical 50-feature pair capacity is 1,225 slots, numbered `1..1225`.
The initialized physical table has indices `0..1225`; index 0 is the permanently
unused one-based-index sentinel, not end slack. Native relation index `k` maps to
production `GoodixMilanRelationMatrix.slots[k-1]`.

Packed relations are applied in encounter order. This decoder does not sort or
deduplicate `e3`; a repeated index overwrites the same live slot and the last
record wins. Natural type-12 output is a unique ascending reference star, while
production persisted-print validation enforces uniqueness and star membership.
See `../RELATION-MATRIX-AND-PROJECTION.md` for the complete admission boundary.

The geometry tags map as follows: `0x98 -> live +0x00` (subtype),
`0x9a -> live +0x08` (rows), and `0x9b -> live +0x04` (columns), at
`0x18003e5ff`, `0x18003e614`, and `0x18003e62a`. Type-12 geometry is
subtype/rows/columns `12/88/104`.

## Serialized Cache State

Before header parsing the decoder defaults `+0x8e00` to 1. Top-level tags
`0xfa` and `0xfb`, at fixed header offsets `0x41` and `0x46`, restore live
`+0x8e00` and `+0x8e04` respectively before `FUN_18003f8b0` allocates feature
storage. No tag restores cache pointers, ranks, or feature bodies.

Consequently pack/unpack with state 0 preserves only enabled state/counter and
returns 20 allocated but empty slots; state 1 returns no cache allocations.
This is deliberate serialization scope, not missing decoder logic.

The fixed header is exactly 13 five-byte tagged raw-`u32` values after the
10-byte envelope. `fa` is tag offset `0x41`, value offset `0x42`, live
`+0x8e00`; `fb` is tag offset `0x46`, value offset `0x47`, live `+0x8e04`.
Configured maximum is tag `97` at `0x23` (value `0x24`, live `+0x20`), while
current count is tag `91` at `0x1e` (value `0x1f`, live `+0x1c`).

The variable-position tag-`93` graph block has payload length 20 and contains
four five-byte raw-`u32` fields at relative tag/value offsets
`+5/+6`, `+10/+11`, `+15/+16`, and `+20/+21`: `f2/f3/f4/f5` restore live
`+0x87d8/+0x87dc/+0x87e0/+0x87e4`. Constructor defaults are
`-1/-1/-1/0`. For type 12, `f2` is the graph reference, `f5` is graph
established, and `f3/f4` are opaque round-trip companions with no non-codec
accesses.

The decoder is not a safe semantic validator. It defaults missing `fa` to 1,
accepts state 2, arbitrary counters, arbitrary `f3/f4`, and graph flag 2.
Out-of-range graph references can fault in post-decode graph/normalization code.
Safe persisted inputs use canonical 0/1 `f5` and `fa`, with `f2` equal to `-1`
or in range when unestablished and strictly in range when established. `fb`
is unrestricted `uint32_t`; `f3/f4` remain opaque signed dwords.

## Failure Ownership And Current Mapping

An unknown fixed-header tag sets status `0xffff0006` at `0x18003e6c8`.
The test at `0x18003e71c` branches directly to `0x18003e876`, bypassing
`FUN_180037860` even though the `0x8e08` object has already been allocated.
Storage-allocation failure and negative child-parser returns set the later
failure flag and reach the destructor at `0x18003e871`. These exits are not a
single transactional cleanup path.

The call to `FUN_18003fef0` at `0x18003e891` would return a nonzero status
directly, without deep destruction, but the callee's only nonzero return is
`0x80000001` for a null template. This decoder already excludes null.
`FUN_180047550` at `0x18003e920` calls `FUN_180047120` for type 12 and returns
zero for a nonnull template without propagating a normalization status. Its
null-input status is likewise unreachable here. The public `templateUnPack`
wrapper publishes its handle only for status zero; on failure it frees only the
public eight-byte wrapper, not a surviving unpublished internal object.

Current representation is split across
`drivers/goodix53x5/milan/template/codec.c` (`goodix_milan_template_unpack`,
borrowed feature slices and copied outer metadata), `print.c`
(`goodix_milan_print_validate_template`, persisted admission), and
`match/lifecycle.c` (`goodix_milan_match_serialized_feature_result_internal`,
writable fresh-gallery normalization and fresh-only partition repair), with
`milan_match_decode_imported_angles` providing the fresh signed-angle adjustment
from `FUN_18003fef0`. It retains the exact live words independently of the
quantized packed projection; see `../OUTER-TEMPLATE-CODEC.md`.
Retained gallery identity and independent live records are owned by
`study/queue.c`; retained matching bypasses fresh reconstruction.
