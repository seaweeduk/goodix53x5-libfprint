## Inputs And Dispatcher

The selector reads these evidence fields:

- retained count `+0x640`;
- retained flag `+0x644`;
- matched physical feature index `+0x648`;
- primary transform `+0x650`;
- relation transform `+0x66c`;
- action gate `+0x688` is consumed by the dispatcher, not this function.

Evidence relation count `+0x668` is not consulted. Relation mutation consumes
the six affine dwords at `+0x66c` directly.

The type-12 matcher initializes retained flag `+0x644` to zero and updates it
as a logical OR with `feature.b5 != 0` for accepted direct evidence. The store
at `FUN_180055a40:0x180056eb3..0x180056ed2` therefore produces only literal
zero or one, even when a live `b5` contains another nonzero dword. Ordinary
Action 2 reaches this selector with retained flag zero; values other than zero
or one require a non-ordinary evidence producer.

For live type 12, `FUN_180044fc0:0x180045049..0x1800450aa` first refreshes
retained entries when retained count is positive and retained flag is exactly
one. Pre-selector normalization requires the full conjunction
`retained_count > 0 && retained_flag == 1 && feature_count == maximum`.
Capacity alone is insufficient: count zero or flag zero skips this prepass.
It calls this function only when all of the following hold:

- evidence action gate `+0x688` is nonzero;
- dispatcher mode is nonzero;
- probe quality `+0x11c` is strictly greater than 15;
- probe coverage `+0x120` is strictly greater than 65.

Dispatcher mode zero disables the call. Mode two permits append/study but passes
`replacement_enabled=0`; mode one and every other nonzero value pass
`replacement_enabled=1`.

The primary dispatcher supplies post-refresh, post-normalization live
`+0x128` and `+0x148` values only under that conjunction; otherwise selection
consumes the current live values. The queued caller enters this
function directly and therefore supplies its current live values without that
prepass.

The ordinary adapter cannot supply a full-capacity graphless gallery to Action
2. Default profile-9 enrollment publishes at 12 features, below the configured
maximum of 40. Subsequent ordinary growth uses this selector's append path, and
the first append while graph-established is zero sets the matched feature as
reference, sets graph-established to one, and activates both matched and new
features before return. A 40-feature graphless object is accepted by the generic
enrollment engine, but requires a nondefault direct-export enrollment chronology
rather than the adapter's producer lifecycle.

## Shared Entry

`0x180046a10..0x180046ad3` rejects matched index `-1`. Otherwise, when both
anti-fake objects exist, it copies matched-owned dwords at anti-fake offsets
`+0x12c8`, `+0x12c4`, `+0x1ab0`, and `+0x1ab4` into the probe object before
append/replacement admission. A successful append or replacement subsequently
deep-copies the probe anti-fake object.

## Append Path

When unsigned live feature count `+0x1c` is below maximum `+0x20`,
`0x180046ad3..0x180046c8f` assigns action 1 and appends the probe. The new index
is the old feature count. The new feature inherits matched `be/+0x134` and
matched post-refresh `b5/+0x110`.

If the old graph-established field `+0x87e4` was zero, the function writes the
matched index to reference `+0x87d8`, sets graph-established to one, and sets
matched and appended `b5` to one. If matched `b5` is then exactly one, it stores
the evidence relation for the appended feature. Positive retained count is
replayed only in this first-graph branch. An append reaching maximum capacity
invokes `FUN_180047120`; a smaller append does not.

Existing type-12 gallery features have already been decoded: a packed endpoint
`b7 == record_count` becomes `record_count-1`. The appended live probe bypasses
that decoder and retains its own `b7`, including `b7 == record_count` and the
one-record endpoint `1`. Capacity normalization does not apply the decode clamp
to this new feature. See `FUN_1800456b0.md` for the copy and lifecycle boundary.

## Full-Capacity Admission

At capacity, replacement requires nonzero `replacement_enabled` and probe
quality strictly greater than 15. For type 12, a matched quality of at least 60
requires:

```text
probe_quality * 10 > matched_quality * 6
```

Both products are low-dword products and the comparison is signed. Equality
rejects. Matched quality below 60 bypasses this ratio test.

`FUN_180045530` then chooses the primary candidate. If it returns a candidate,
that candidate is marked primary. If it returns `-1`:

- retained flag zero falls back to the matched feature only when the full
  `104x88` primary-transform footprint satisfies
  `area * 100 > (104 * 88) * 80`;
- any nonzero retained flag invokes `FUN_180046ef0`; its best half-resolution
  footprint must be at least 80 percent, or at least 60 percent while template
  counter `+0x8cf8` is strictly greater than 1000.

The full-domain products and `area * 100` are wrapped dword operations followed
by signed comparisons. The full-domain path uses the unhalved transform. The
geometric path uses a `52x44` domain and arithmetic-right-shifts both
translations by one.

## Action 4 Selection

Action 4 requires retained flag exactly one and a primary candidate returned by
`FUN_180045530`; an accepted geometric fallback receives action 3 instead.

Primary selection is:

1. If matched live `+0x128` is zero, choose the matched feature immediately.
2. Otherwise scan physical indices from zero upward. Eligible features have
   `b5/+0x110 != 0` and are not the live reference `+0x87d8`.
3. Rank by signed lowest `+0x128`, then signed lowest coverage `+0x120`, then
   signed highest `+0x148`. A complete tie retains the earlier index.
4. The initial best tuple is `(0xfffff, 0xfffff, 0)` with no selected index; a
   feature must strictly beat it.
5. With retained flag nonzero, compute the probe-mask residual left uncovered
   by all other features having `b5 != 0` and `ba/+0x124 != 5`. Missing relation
   slots contribute their identity affine. Counts below 20 become zero.
6. If template counter `+0x8cf8` is strictly greater than 700, add 20 to the
   residual with dword wrap. Keep the candidate when this adjusted signed value
   is greater than or equal to candidate `+0x128`.

The selected target need not be the matched feature. The matched feature owns
the copied anti-fake scalars and `be`; the selected target owns the preserved
lifecycle and relation-row fields; the probe owns replacement feature data and
the new relation affine.

## Action 4 Mutation

`0x180046dce..0x180046e15` writes action 4 before invoking the void mutation
helpers. Mutation order is:

1. Copy matched `be/+0x134` to the selected target.
2. `FUN_1800458c0` replaces probe-owned feature content.
3. `FUN_180045d40` installs or composes the six-dword evidence relation.
4. `FUN_180047120` normalizes the complete gallery before return.

The replacement preserves selected-target `b5/+0x110`, relation row base
`b6/+0x114`, and optional `c7/+0x150`. Target `ba/+0x124` remains zero or is
promoted from any nonzero value to literal two. Target `bc/+0x12c` becomes
`configured_maximum-1`; the ordinal loop visits configured slots, decrementing
each signed old `bc` greater than the target's signed old `bc` once. Ordinary
full-capacity Action 4 has live count equal to that maximum. Template `+0x8cf8`
and target `bd/+0x130` each increment once. These increments and decrements wrap
as dwords.

Probe records, maps, inline feature data, mask `+0x140`, quality `+0x11c`, and
coverage `+0x120` replace their target counterparts. Record copying is bounded
by the live maximum; an over-bound probe is ranked and repartitioned. Probe
`c0/+0x14c` replaces target `c0` only when it is nonzero and odd. The complete
probe anti-fake object is copied when present, after the four matched-owned
anti-fake dwords were installed at entry.

For a nonreference target, replacement first clears every incident relation to
the unset identity sentinel. The relation helper then creates exactly the
target/reference slot with leading value zero, storing the evidence affine
directly when target index is above the reference and its inverse otherwise.
For a reference target, incident leading values and cardinality are preserved.
With evidence affine `X` and stored star affine `S`, each defined edge below
the reference receives `compose(S, X)`; each defined edge above the reference
receives `compose(invert(X), S)`.

Normalization resets each feature's live `+0x148` to zero and `+0x128` to the
half-domain area before processing active features. For every active feature it
starts from that feature's mask, removes the rectangular footprints of every
other active feature through their graph transforms, stores the remaining bit
count at `+0x128` with values below 20 reduced to zero, and increments `+0x148`
for each footprint whose full-scaled area is strictly greater than 40 percent
of `104x88`. This normalization does not exclude `ba == 5` features.

Affine composition uses signed dword coefficients widened to signed 64-bit
products, signed 64-bit addition, arithmetic right shift by eight, and low-dword
translation addition. Raster coordinate multiply/add, bounds, areas,
percent products, counters, and policy products use wrapped dword arithmetic;
their policy and clipping comparisons are signed. Translation halving is an
arithmetic right shift. Signed division truncates toward zero.

## Other Replacement Actions

- Action 3 uses an accepted geometric fallback under retained flag exactly one.
  It has the same replacement, relation, and normalization mutation as action 4.
  Ordinary enrollment can produce an established two-active-feature graph with
  positive residuals that rejects the primary candidate yet accepts the
  reference's complete geometric footprint; see `FUN_180046ef0.md`.
- Action 2 handles every retained-flag value other than exact one. Ordinary
  matcher-produced Action 2 has retained flag zero. A zero-residual matched
  feature is selected immediately. Otherwise `FUN_180045530` ranks a primary
  candidate and applies its flag-zero validation; if none survives, the
  full-domain fallback may select the matched feature. The geometric fallback
  is reachable only for a non-ordinary retained-flag value that is nonzero but
  not one.
- After target selection, Action 2 requires probe coverage to be at least
  `matched_coverage - 10`. The subtraction wraps as a dword and the comparison
  is signed; equality admits replacement. Failure restores the returned index
  to `-1`, leaves the caller-initialized action unchanged, and performs no
  replacement.
- Successful Action 2 invokes `FUN_1800458c0`, then writes selected `b5` to
  zero. It does not copy matched `be`, install the evidence relation, or invoke
  post-replacement normalization. A nonreference target has all incident
  relations cleared by `FUN_1800452e0`; a reference target retains its incident
  relations. The selected target keeps its old `be`, `b6`, `bb`, and optional
  `c7`, while probe records, matrices, inline content, mask, quality, coverage,
  conditional `c0`, and anti-fake content replace their target counterparts.

## Dispatcher Completion

After a nonnegative primary return, `FUN_180044fc0` may run queued continuation
before capacity shutdown. The selected primary action is preserved unless the
continuation reports action 5, which replaces the published action. At full capacity the
dispatcher then sets queue state `+0x8e00` to one and clears its transient queue
entries if it was previously zero.

When evidence finalization gate `+0x684` is nonzero, type 12 runs
`FUN_1800607b0` and increments dword counter `+0x8cf4`. Ordering is descending
by signed `b5`, then signed `be`, then signed `bc`. Each pass keeps the earliest
strict maximum, but its in-place selection swaps make the complete sort
globally unstable.

## Failure Behavior

Admission or candidate failure returns `-1`, leaves the action at its
caller-initialized value, and performs no live template replacement. The earlier
four-dword probe anti-fake patch is transient in that case. Replacement and
relation helpers are void and mutate in place. Their allocations are not checked
before later use, so there is no recoverable native rollback or clean
allocation-failure result. Successful selection returns the inserted or replaced
physical index with its corresponding action 1 through 4.
