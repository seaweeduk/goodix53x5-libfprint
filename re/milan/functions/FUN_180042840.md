This function snapshots the original count and list pointer, then partitions
without sorting:

1. `0x18004287d..0x1800428b2` includes only candidates whose feature `+0x110`
   active word equals exactly `1`.
2. If that active list is nonempty, `0x1800428d1..0x1800428f7` routes it through

3. If it is empty, `FUN_180042180` is called only when context `+0x87e4` equals

4. After any activation above, `0x18004291c..0x180042951` rebuilds a list from
   the original candidates whose active word now equals exactly zero. Values
   other than zero or one belong to neither partition.
5. If inactive candidates remain, `FUN_180042ac0` is used when graph-established
   equals zero or the current feature active word equals zero. Otherwise

The inactive list in step 4 is a fixed snapshot for the subsequent helper call.
`FUN_180043110` consumes it literally and does not recheck active markers, so an
entry activated by an earlier bridge iteration remains eligible for its own
later direct-current bridge processing.

This repartition is what permits first-reference establishment and same-call
bridging of the remaining inactive admitted priors. When a graph is already
established, active direct candidates have absolute routing preference over
even stronger inactive candidates: `FUN_180041f60` chooses only within the
active partition, and inactive candidates are handled afterward.

The runtime graph reference is context `+0x87d8`; graph-established is
`+0x87e4`. They serialize as `f2/f5`. Header `fb` is independently the queue
transaction counter at live `+0x8e04`.

## Relation Publication

Initial establishment preserves the selected direct slot's leading count.
Established routing preserves every nonnegative leading word in the
current/reference slot and changes only a negative sentinel to zero. Bridge
relations are zero-leading. The type-12 serializer later emits only nonnegative
slots incident to the live reference, in ascending feature order; relation count
is therefore the number of materialized reference-star edges, at most
`feature_count - 1`.

A direct zero-count call is also outside the native caller contract. This
function sees no active candidate and calls `FUN_180042180`, which dereferences
the first list entry: nonnull stale storage can establish a phantom reference,
and a null list faults. `FUN_180042c30` bypasses this function for zero admitted
candidates.
