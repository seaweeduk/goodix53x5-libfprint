## Recovered Behavior

It enumerates triples lexicographically as `(first,second,third)`, with
`first=0..count-3`, `second=first+1..count-2`, and
`third=second+1..count-1`. The admitted-triangle counter is tested against
`0x3b2` only before each new `first` body and increments after all three edge
and orientation gates but before the solver. It is therefore a soft outer-loop
threshold, not a 946-solve cap. With the production maximum 42 and no accepted
model, the largest possible admitted/solved total is
`C(41,2)+C(40,2)=820+780=1600`; the next outer body is then suppressed. The
counter is therefore a soft threshold rather than a solve cap.

The first two edges compute dword `dx` and `dy`, wrap each dword square,
arithmetic-shift each square by two, and then wrap the dword addition. The third
`(second,third)` edge instead wraps both dword squares and their dword sum before
one arithmetic `>>2`. The first form is at `0x18007804e..0x180078089` and
`0x1800782b3..0x1800782d4`; the second is at
`0x180078327..0x180078340`. Each ratio gate then evaluates, in order,
`source*5 <= target*6`, `target*5 <= source*6`, `source > 0x2ffff`, and
`target > 0x2ffff`, branching at the first failure. All four products use
32-bit-destination `LEA`/`ADD`, discard carry modulo `2^32`, and are compared as
signed dwords by `JG`/`JL`; no overflow flag participates. The three ratio/gate
sites are `0x180078078..0x1800780c2`, `0x1800782d7..0x18007830c`, and
`0x180078340..0x180078379`. Both 5:6 equalities are inclusive. Within the
canonical sensor coordinate range, the exact distance threshold is not
representable by the first form: the nearest values are `0x2fffd` and
`0x30000`, so the latter is the first reachable passing magnitude.

For each selected pair, `enrolled_orientation-probe_orientation` is normalized
once: values strictly above the half-period subtract one period and values
strictly below its negative add one period; equality is unchanged. The three
dword differences are summed with dword arithmetic and divided by three with
signed truncation toward zero. Every deviation must be within inclusive
`[-tolerance,+tolerance]`. If that first test fails in mode 1, a local retry copy
adds the half-period to each original difference, applies the same one-step
normalization, recomputes the truncating average, and tests once more. Retry
state is local and never mutates caller orientations.

After `FUN_1800683d0`, the candidate must satisfy strict
`abs(a-d)<50`, `abs(c+b)<50`, and `abs(a),abs(b),abs(c),abs(d)<300` gates.
Thus 49 and 299 pass while 50 and 300 reject. Scoring forms each transformed
coordinate with signed 64-bit coefficient products and `+0x80` before `>>8`,
then performs target subtraction and translation addition as dwords. Absolute
dword components must be at most 640 (`<0x281`), and the wrapping dword sum of
dword squares must be strictly below `0x64000`. Component 640 already squares
to the rejected equality `0x64000`; component 641 fails both gates. `0x63fff`
is not a sum of two integer squares; the nearest reachable value below is
`0x63ffd`.

Candidates below argument-9 minimum inliers are discarded before residual,
ranking, or validation. Otherwise residual is `(sum+(count>>1))/count`, with
the zero-inlier sentinel `0x190000`. A candidate is eligible only for strictly
more inliers or equal inliers with strictly lower residual; exact ties preserve
the earlier triple. `FUN_180080130(affine,401,163)` runs only after that rank
test, so an invalid nominal winner preserves the earlier valid model. The
candidate affine is temporarily written to the supplied affine buffer before
ranking/validation, but common completion republishes the saved winner or six
zeros. A successful replacement atomically commits affine, residual, and the
42-byte mask.

Early exit tests the retained best count strictly above 20 after rank and
validity processing. Twenty continues searching; 21 exits immediately with the
first accepted 21-inlier model, so no later lower-residual transform is visited.

Profile-9 mode uses period `0x3244`, half-period `0x1922`, and orientation
tolerance `0x400`. Argument 9 is the fixed minimum inlier count 2.
`FUN_180080130` validates the affine with bounds `401` and `163`.

therefore preserves the poison, while the production wrapper observes mask zero.
Exact count/residual ties retain the earlier triangle.

## Dependency Unit 5 Failure Contract

The estimator has no return status. Its output families are:

- no accepted model: residual `0x190000`, six affine zeros, caller-owned mask;
- accepted model: fitted affine, accepted inlier mask, and rounded residual;
- early success: the same accepted outputs when best inlier count exceeds 20.

Degenerate solves, coefficient pre-gate rejection, `FUN_180080130` rejection,
and search exhaustion all converge on the same no-model output. The estimator
temporarily writes a candidate affine before the validator call, but if no model
is accepted the epilogue overwrites it with zero. Model validity must therefore
be carried explicitly by native code; neither all-zero, identity, residual, mask,
nor later retained count is a validity test.

Profile-9/type-12 fixes count to `3..42`, minimum inliers to 2, and mode to 1.
Count below three initializes residual and reaches the no-model affine-zero
epilogue without reading point arrays. A count above 42 is malformed: once any
triangle reaches scoring, mask index 42 calls the non-returning bounds handler at
`0x18007873d`. Null residual faults at entry; null affine faults at final
publication; point/orientation pointers fault only when their count-driven paths
read them. Production wrapper arguments exclude these native crash surfaces.

## Current Source Status

Direct synthetic-valid recognition controls with unsigned-16-bit Q8 coordinates
witness both directions of the third-edge discrepancy: using the uniform
separate-shift form can admit a model that the DLL's add-before-shift form rejects,
or reject one that the DLL admits. Three pairs with neutral orientations isolate
the estimator because orientation filtering preserves the mask and refinement is
not entered.

Separate synthetic-valid controls witness the wrapped ratio contract: modulo
`2^32` 5:6 products can reject edges admitted by widened mathematical products
and admit edges those products reject. Current `milan-dev` spells these products
as signed `int32_t` multiplication, so overflow is undefined C even when the
release compiler happens to emit the DLL's dword operations; UBSan reports the
overflow on the direct control.

The pending one-file production patch defines both behaviors explicitly: the
first two edges shift each wrapped square before addition, the third adds wrapped
squares before shifting, and all four ratio products wrap independently before
signed comparison in native branch order. Current `milan-dev` does not yet
contain that patch. Canonical robust estimation, winner selection, output
ownership, orientation filtering, affine validity, and least-squares behavior
otherwise match the DLL. No retained natural affine output in the audited corpus
triggered either arithmetic distinction; natural reachability remains unresolved.
