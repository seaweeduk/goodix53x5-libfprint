## Recovered Behavior

The recognition-evidence prefix is an array of 32-byte entries followed by its
count at evidence `+0x640`. Each entry contains a feature index at `+0x00`, a
six-word affine at `+0x04..+0x18`, and one unused-by-this-helper dword at
`+0x1c`. The helper loops exactly `count` entries with no internal count or index
validation.

For every entry it first inverts the entry transform and composes the evidence
relation transform at `+0x66c` after that inverse
(`0x1800464a6..0x1800464b6`). It then writes literal `1` to the indexed live
feature's active/retained field at `+0x110` (`0x1800464d5`), before mutating
relations against the template reference at `+0x87d8`. Relation storage begins
at `+0x1b8`; the exact direction and clearing rules are below.

The exact slot is `feature[max(index,reference)].b6 + min(index,reference)`.
When the indexed feature is not the reference, the helper first resets all of
that feature's incident slots to `[leading=-1, affine identity]`, then writes the
reference edge with `leading=0`; it inverts only when needed for canonical
higher-index-to-lower-index storage direction. When the indexed feature is the reference, it
composes the refresh through every already-defined reference edge and preserves
their leading values.

The helper does not consult the matched feature at evidence `+0x648`, matcher
direct-positive flags, the final winner, or the study update code. Its feature
set is exactly the indices in the retained-evidence array. It neither reads nor
writes template order `+0x87e8`; the later type-12 sorter consumes the resulting
`b5` values but does not create them.

`FUN_180044fc0` calls this helper before append/replacement only when
`evidence+0x640 > 0 && evidence+0x644 == 1`. `FUN_1800469f0` has a second call
used only by its graph-unestablished append fallback when that append first
establishes the graph and evidence count is positive. The second call does not
test `+0x644`.

For each ordered entry affine `T`, the exact transform before relation mutation
is `X = compose(evidence_relation, inverse(T))`. For a nonreference entry, the
helper clears every incident edge and writes leading zero. It stores `X` when
the entry index is above the reference and `inverse(X)` when the entry index is
below it, preserving canonical higher-to-lower direction. For a reference entry,
it preserves leading words and composes all defined star edges: lower-index
edges receive `compose(old, X)`, while higher-index edges receive
`compose(inverse(X), old)`.

The first-graph caller makes helper ordering observable. With retained flag one,
`FUN_180044fc0` first invokes this helper against stale `f2` while `f5==0`.
`FUN_1800469f0` then sets `f2=matched`, creates the appended anchor, and invokes
this helper again. If the list contains the future reference, a first-pass
stale-reference edge can survive because the second-pass reference case composes
rather than clears it. Implementations must execute the two ordered passes; a
single replay against the final reference is not equivalent. With flag zero,
only the post-anchor fallback pass runs.

Reference reanchoring visits lower physical indices before higher indices.
The signed leading-word tests at `0x18004652f..0x180046538` and
`0x1800465a4..0x1800465ad` skip every negative value, not only literal `-1`.
Only the affine words of admitted slots change; leading words are preserved.
The helper does not validate the entry count or indices and has no rollback or
status return. See `FUN_180045d40.md` for the shared reference arithmetic.
