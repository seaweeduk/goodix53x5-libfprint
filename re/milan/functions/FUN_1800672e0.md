## Behavior

- When initialization global RVA `0x1efbf8` is zero, initializes the application,
  auxiliary, and secondary-auxiliary gain maps to Q13 unity (`0x2000`).
- For the production mode-bit-clear path, selects update threshold 3 and scalar
  controls 8000/6400 unless the packed subtype is 4 or 11.
- Profile-9 subtype 12 therefore fixes the optional reciprocal-plane numerator
  used by `FUN_1800668f0` to `8000 * 8192`; it is not the binary's initial 2000
  value before generation initialization.
- If initialization is still zero once the sample counter exceeds the selected
  threshold, normalizes the application map by its rounded full-frame mean and
  marks initialization complete.
- Independently of initialization state, a nonzero workspace sample count at or
  below the selected threshold fills the application gain map with Q13 unity.
  For profile-9 subtype 12 the threshold is 3. This write occurs before
  `FUN_180067500` derives its application-adjusted primary auxiliary-map input.
  It is therefore a per-call low-count reset, not only fresh-generation
  initialization (`0x180067418..0x18006742c`).
- Its scalar inputs are distinct: the workspace sample count is the first dword
  at RVA `0x219670`, RVA `0x1efbf4` counts accepted auxiliary-map samples, and
  RVA `0x1efbf8` records initialization. A zero workspace sample count clears
  the workspace calibration map, resets the auxiliary count, and restores all
  three persistent gain maps to unity before marking initialization complete.
- This helper does not increment the workspace sample count. The accepted
  auxiliary count is incremented later by `FUN_180063a80`, and the workspace
  sample count is incremented later still by `FUN_180067050`.
- The persistent ready scalar at RVA `0x1efbfc` is not written here. This helper
  owns Q13 map initialization and the auxiliary/initialization resets; the ready
  transitions occur later in `FUN_180067500`. Treating initialization state or
  nonzero calibration-map samples as a ready substitute is therefore incorrect.
- Fresh-generation map/counter reset at `0x1800673cf..0x180067413` does not own
  or clear ready. The profile scalar therefore crosses every call that causes
  this initializer to rebuild generation-local planes.
- `FUN_18006c510` temporarily forces the workspace sample count to 5 around its
  post-render `FUN_1800668f0` call, then restores the saved count. Internal map
  arithmetic observes 5, but the workspace increment does not persist. The
  auxiliary count may still advance, so this path can make it exceed the
  workspace count but cannot create auxiliary count zero with workspace count
  greater than 5.
- The forced value 5 bypasses the low-count application-map reset. In a clean
  retained chronology, a later normal call with workspace count `1..3` resets
  that map to unity before its auxiliary update, while each forced-count nested
  call continues to observe 5. The process-global auxiliary counter is neither
  forced nor restored by the nested-call sequence.
