## Recovered Behavior

The matched feature's live `+0x128` field is the first branch. If it is zero,
the helper returns the matched feature immediately. Otherwise it considers
features whose `b5` at `+0x110` is nonzero, excluding the live reference index
at template `+0x87d8`, and ranks them lexicographically by:

1. lowest live `+0x128`;
2. lowest coverage at `+0x120`;
3. highest derived residual metric at `+0x148`.

Every comparison is a signed strict comparison, so a complete tie keeps the
earlier feature index. The scan does not seed itself from the first eligible
feature. Its initial `(residual, coverage, overlap)` tuple is
`(0xfffff, 0xfffff, 0)`, with selected index `-1`; an eligible feature must
strictly beat that tuple lexicographically before it becomes the candidate. A
sentinel-equal control therefore leaves the enclosing selector at action 0 with
the index unset. Production commit `f6e97782` preserves this initialization
rather than treating the first eligible feature as an implicit winner.

When the evidence flag supplied by `FUN_1800469f0` is zero, the ranked
candidate is retained only if its `+0x128` is zero and at least three active
features have `+0x128 == 0`. When the flag is any nonzero value,
`FUN_180046780` computes the probe residual not covered by the other active
gallery features. Template
counter `+0x8cf8 > 700` adds 20 to that result. The candidate is retained when
the adjusted result is greater than or equal to its `+0x128`; strict less-than
rejects it.

The `+20` is a wrapped dword `ADD` at `0x18004566b`, followed by a signed
comparison. There is no saturation or overflow guard. Production commit
`89dd6c43` implements the same modulo-`2^32` addition with a defined signed
reinterpretation.

The flag-zero count uses exact `b5 == 1` at
`0x180045620..0x180045635`, while scan eligibility uses `b5 != 0` at
`0x1800455a3..0x1800455aa`. These predicates are equivalent for normal
Boolean-produced type-12 state, but they are not interchangeable in the generic
contract.

Production source at head `7e92c8f5` interchanged them before the 2026-08-18
correction:
`goodix_milan_study_policy_select()` counts `active != 0` at
`drivers/goodix53x5/milan/study/policy.c:175-178`. Neither feature parsing nor
profile-9 print validation restricts packed `b5` to zero/one, so this is a
synthetic-valid parity defect rather than a malformed-input difference. All
known native and DLL producers still write Boolean values, so it is not a
confirmed naturally generated defect.
