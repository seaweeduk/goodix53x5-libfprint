## Recovered Behavior

The caller rebuilds one inactive-candidate snapshot after its anchor/routing
step (`0x18004291c..0x180042962`), then passes that snapshot here. Thus a newly
established anchor can bridge the remaining admitted priors in the same call.
The direct-relation producer appends admitted prior indices while scanning
physical features upward, so the reachable snapshot and this function's loop
are ascending physical index. This function nevertheless consumes the supplied
array literally (`0x180043170`): it does not sort, deduplicate, rebuild, or
recheck `feature+0x110`. Several candidates can therefore be admitted in one
call. If an earlier candidate's propagation activates a later snapshot entry,
the later entry is still evaluated and can overwrite its propagated
reference relation with its direct-current route before propagating again.

For each snapshot candidate, the bridge calls `FUN_180071d40` on the current
feature, candidate feature, and their stored direct relation. It admits only a
return value strictly greater than 208 (`0x1800431a1..0x1800431c1`): equality

compared value is the function return, not either detail/coverage out-parameter
used by direct pair admission. The bridge passes the distinct strict threshold

the current feature is newest. The bridge inverts it to candidate-to-current,

candidate_to_current, candidate_to_reference)` at

## Propagation Handoff

`FUN_1800411f0` visits physical candidates below the pivot in descending order,
skipping only active words equal to one. Its worklist initially contains the
pivot. Each candidate tries worklist nodes newest-to-oldest, requiring a
nonnegative relation count and overlap strictly above the supplied threshold.
A successful candidate is activated, receives a zero-leading reference edge,
and is appended to the worklist. An unsuccessful candidate is not appended.

For a candidate admitted through worklist position `k`, native initially loads
the node-to-candidate transform. It walks earlier worklist positions backward
to compose a pivot-to-candidate path. The child position starts at `k`; an
earlier node with a negative relation to that child is skipped without advancing
the child. Only a nonnegative edge causes composition and makes that earlier
node the new child (`0x1800413d3..0x180041444`, especially the conditional
`MOV R9,RBX` at `0x18004143b`). This is not an unconditional traversal of
adjacent worklist pairs. Native then inverts the assembled path and composes
the exact supplied pivot-to-reference transform after it. Canonical reference
storage and zero-leading publication precede appending the candidate.

The lower worklist is strictly descending in physical index. Each appended
entry has a qualifying relation to some earlier worklist entry, selected by
the newest-to-oldest search at `0x18004128b..0x18004131a`; appending at
`0x180041538..0x180041559` does not require selection of the last entry.
The first appended entry necessarily selected the pivot, since that is then
the only worklist node. On the ordinary established-graph caller path the
reference is already active and is not in this worklist. The only relation
writes during lower propagation are candidate/reference slots
(`0x180041478..0x180041544`), so they do not fill missing relations between
worklist nodes.

When the selected position is zero, no backward composition is required. At
position one, the single backward edge is the first appended entry's qualifying
pivot edge and is nonnegative. Conditional child retention can first affect a
later lookup at selected position two or higher: an undefined edge is skipped,
then another earlier node is considered with the same child. This requires at
least three existing worklist nodes plus the new candidate. The established
reference and the incoming enrollment feature are distinct from all four, so
this route condition requires at least six live features on the ordinary
bridge caller path.
