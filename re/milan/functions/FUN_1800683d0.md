## Recovered Behavior

It loads three Q8 point pairs and solves destination from source. Source
coordinate subtraction is wrapping dword arithmetic followed by signed extension.
Each destination coordinate is first shifted left by ten as a dword; subsequent
destination subtraction therefore also wraps before signed extension. Products,
determinants, and numerators are signed 64-bit. Nonzero determinants use signed
`IDIV`, hence quotient truncation toward zero. Each quotient is narrowed to its
low signed dword before the linear coefficient is arithmetic-shifted right by
two, producing Q8 `[a,b,tx,c,d,ty]`.

Every completed solve therefore publishes each linear coefficient in
`[-0x20000000,0x1fffffff]`, including wrapped quotients and the singular sentinel.
The dword `SAR ...,2` instructions are at `0x180068565`, `0x18006857b`,
`0x180068602`, and `0x180068617`. No linear coefficient can be `INT32_MIN`.
For two such coefficients their difference lies in
`[-0x3fffffff,0x3fffffff]` and their sum in
`[-0x40000000,0x3ffffffe]`. Consequently the recognition caller's two symmetry
expressions and four absolute values cannot overflow or encounter the signed
absolute-value exception. Its strict `<300` tests establish actual magnitudes
at most299, rather than merely accepting a wrapped negative absolute value.

The first translation uses destination point 0 and the second uses point 2.
Each subtracts the narrowed pre-`>>2` Q10 coefficients times the corresponding
source coordinate from the wrapped Q10 destination coordinate, then applies a
signed 64-bit `>>10` and narrows to dword. A zero determinant substitutes
`INT32_MAX` independently for both row coefficients and still computes the
translation; it does not return failure. The result is therefore an
`INT32_MAX`-derived affine, not identity, zero, or a status value.

Evidence is the determinant and first row at `0x1800684bd..0x180068576`, followed by the second row through `0x18006864c`.

## Estimator Integration

Degenerate determinants produce four linear coefficients equal to `0x1fffffff`.
Recognition rejects them at its coefficient-consistency gates. Enrollment has
no such pre-gate, but a candidate that reaches `FUN_180080130` is rejected:
each wrapped square is `-1073741823`, so the validator's trace is negative.
An all-collinear source set therefore cannot install a model in either caller.
Only the estimator epilogue owns final no-model affine zero; this solver has no
status and never owns the caller-visible failure affine.

Production callers supply unsigned-16-bit Q8 coordinates, so dword coordinate
shift/subtraction overflow is excluded there. A small nonzero determinant still
permits large quotient coefficients; the coordinate bound alone does not provide
the recognition caller's coefficient-consistency guarantee to enrollment.
For example, source Q8 points `(10240,2560)`, `(2240,10560)`,
`(2432,10384)` and destination points `(2560,16000)`, `(2576,2784)`,
`(5472,3088)` produce `[46341,46342,-2314520,211,-211,9624]`.
All coordinates are in the type-12 frame, aligned to 16 Q8 units, and each
triangle's points are separated by more than one pixel. The first two linear
coefficients have individually negative wrapped squares; their signed-64 sum
is `-4294865347`, not the positive low dword `101949`. See
`FUN_180080130.md` for the resulting discriminant/trace rejection.

Null pointers fault; the helper has no count or capacity argument with which to
validate them.
