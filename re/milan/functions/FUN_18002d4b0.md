## Result Ownership

- `enrolAddImage == 0x83` destroys the whole enrollment session through
  `FUN_18002bea0` and stores adapter status `0x8009` at
  `0x18002d686..0x18002d6b3`.
- Any other nonzero add result stores `0x8010` at
  `0x18002d6bd..0x18002d6d2`. Neither nonzero path invokes one-image rollback.
- Only an add result of zero reaches post-insertion policy. The insertion has
  already incremented session used count and published its two overlap metrics.

## Count And Metric Ownership

The two count inputs are distinct:

- `P = signed16(*param_4)` is synchronized pre-insertion count
  `DAT_1801ce1a8`, passed by `FUN_180032990`. This function does not update it.
- `N = signed16(session + 0x0a)` is live algorithm count after a successful
  `enrolAddImage`. On the synchronized exported path before policy, `N = P + 1`.

Threshold selection reads `N` at `0x18002d790..0x18002d79e`. Rollback
eligibility separately compares `P > 2` at `0x18002d7f8..0x18002d806`.

## Mode-0 Decision Table

The policy first computes a bad-capture Boolean from the post-insertion session:

```text
if signed16(session.used_count) < 7:
  bad = signed32(session.overlap_at_0x14) > uint8(threshold_at_0x1800f240c)
else:
  bad = signed32(session.overlap_at_0x14) > uint8(threshold_at_0x1800f240c)
        and signed32(session.previous_overlap_at_0x10)
              > uint8(threshold_at_0x1800f240d)
```

The count split is `0x18002d790..0x18002d79e`; the strict signed metric
comparisons are `0x18002d7a0..0x18002d7e7`. Equality does not set `bad`.
Post-insertion count 6 therefore tests only `+0x14`; count 7 is the first stage
that requires both `+0x14` and `+0x10` to exceed their thresholds.
`enrolAddImage:0x180001796..0x1800017b5` derives those dwords as
`M10 = 100 - (stage_metric >> 24)` and
`M14 = 100 - (stage_metric & 0xff)`. The packed metric's low/high-byte
algorithms and masks are owned by `FUN_180042c30.md`.
`FUN_18002b240` installs both unsigned-byte thresholds from adapter attach
arguments at `0x18002b467..0x18002b483`. Normal `EngineAdapterAttach` copies
configuration bytes `DAT_1800f1421/DAT_1800f1422` through context
`+0x132/+0x133`; the pinned profile-9 configuration is `0x55/0x4b` (85/75).
The data globals' pre-attach image values are `0x55/0x46` and are not the normal
attached second threshold.

Let `S` mean the caller suppression byte is nonzero. After a successful add:

```text
B = N < 7  ? M14 > 85
           : M14 > 85 && M10 > 75
R = !S && P > 2 && B
```

`M14` and `M10` are signed session dwords `+0x14/+0x10`. Thresholds are
unsigned bytes. One-image rollback requires all three adjacent gates, in this
order:

1. caller suppression byte equals zero (`0x18002d7ec..0x18002d7f6`);
2. signed synchronized pre-count is greater than 2
   (`0x18002d7f8..0x18002d806`);
3. the computed bad-capture Boolean is nonzero
   (`0x18002d808..0x18002d80f`).

Only that conjunction calls `enrolDeleteImage` and stores adapter status
`0x8008` at `0x18002d811..0x18002d825`. Graph state, extraction quality,
preprocessing coverage, and relation presence are not independent adapter
rollback gates.

| Add/policy condition | Live count after policy | Adapter status |
| --- | --- | --- |
| add returns `0x83` | session destroyed | `0x8009` |
| add returns other nonzero | unchanged | `0x8010` |
| add succeeds, `S` | `N` | `0` |
| add succeeds, `!S && P <= 2` | `N` | `0` |
| add succeeds, `!S && P > 2 && B == false` | `N` | `0` |
| add succeeds, `!S && P > 2 && B` | `P` after deletion | `0x8008` |

The third insertion has `P=2` and cannot roll back, regardless of its metrics.
The fourth insertion (`P=3`, provisional `N=4`) is the earliest normal
rollback. Count 7 is the first insertion to use both metric thresholds.

For a real policy-generated `0x8008`, the following combinations are impossible
on the synchronized exported path: `P <= 2`, suppression active, `B == false`,
no deletion, or live count remaining at `N`. Since unsuppressed means both
outer counters are below their limits and `P > 2`, outer publication in
`FUN_180032990` is also mandatory. A policy-generated `0x8008` without a
directional detail and both counter increments is therefore impossible.

Session count/progress rewind and retained overlap fields are owned by
`enrolDeleteImage.md`; template deletion and retained graph/pair-score/order
state are owned by `FUN_180037a30.md`.

## Completion Boundary

Completion is checked later by `FUN_18002d8b0`, not by this rollback policy.
That function compares the signed 16-bit session counts and packs when
`used_count >= requested_count`. Normal profile-9/type-12 attach supplies a
requested count of 12, so a rolled-back image does not reduce the requirement
of 12 accepted images.
