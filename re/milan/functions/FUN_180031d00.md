# FUN_180031d00

## Identity

- DLL: `GoodixEngineAdapter.dll`
- Address: `0x180031d00`
- Role: bridge one sample-carried image-base frame into `_InitPreProcessor_E`
  and retain preprocessor initialization state in the engine context.

## Call Graph

- Sole direct caller: `FUN_18001f610`, call at `0x18001fef2`.
- Direct preprocessing callee: `FUN_18002bfa0`.

## Audit Findings

- Argument 2 is the sample's single full-size 16-bit image-base frame; argument
  3 is its byte length (`0x4a40` for `108x88`).
- Hardware sensor ID is forwarded from engine context `+0x4a`.
- Engine context `+0x98 == 1` is converted to a local `needupdatecali` value and
  passed to `FUN_18002bfa0`, but that callee only logs the value.
- On successful preprocessing, the initialized byte returned by
  `FUN_18002bfa0` is stored at context `+0x7c`, and frame length is stored at
  `+0x80`.
- `FUN_18002bfa0` reads the sensor-keyed local calibration blob, calls
  `preprocess_load_calidata` when its sensor ID matches or
  `preprocess_init_calidata` otherwise, and then calls `preprocessor_init`.
  After successful setup it immediately calls `FUN_18002aef0`, which serializes
  the current calibration blob back to the local file.
- The blob includes workspace sample count `DAT_180219670` and its calibration
  planes. It does not include profile-9 gain globals `0x1801efbf4..0x1801efbfc`.
  A setup refresh can therefore replace the workspace sample count while
  retaining auxiliary-count, initialization, and ready globals.
- Context `+0x7c` is zeroed by `EngineAdapterAttach` (`FUN_18001e5b0`). Normal
  probes therefore initialize once per engine attach; `FUN_18001f610` can
  explicitly call this function again when the sample's one-shot base-refresh
  marker is set.

## Lifetime

- The engine context retains calibration state, not this temporary frame
  allocation. `FUN_18001f610` frees the copied frame after the call.
- The adapter's only direct `preprocess_save_calidata` call is the setup-time
  save above. Starting from a zero calibration file, it does not persist sample
  counts accumulated by later live calls.
- Setup refresh is not equivalent to loading the DLL afresh. A production-order
  save/live/load/init control retained non-gain process state that changed 55
  processed bytes relative to a fresh current generation, while status,
  quality, coverage, ready, counters, and monitored gain-map hashes matched.
  That output difference is therefore independent of the gain-ready scalar.
- Adapter detach reaches `preprocessor_exit` through
  `FUN_180030f40 -> FUN_18002b7e0`, clearing the global `0x3048c` calibration
  workspace and calibrated flag.
- `EngineAdapterAttach` is an externally registered callback with no direct
  in-DLL caller. It initializes context `+0x7c` to zero once per adapter attach.
- `EngineAdapterDetach` is `FUN_18001ed10`; it calls `FUN_180030f40` at
  `0x18001ee7d`, then frees the complete engine context on success. A new attach
  therefore cannot inherit `+0x7c` from the old engine context.
- UMDF hardware D0 transitions occur in `usbinterface.dll` and have no direct
  call edge to adapter detach or `preprocessor_exit`. Whether WBF schedules an
  adapter detach for service idle or a particular system-power transition is
  external to these binaries.
