# FUN_180031d00

## Identity

- DLL: `GoodixEngineAdapter.dll`
- Address: `0x180031d00`
- Role: bridge one sample-carried image-base frame into `_InitPreProcessor_E`
  and retain preprocessor initialization state in the engine context.

## Call Graph

- Sole direct caller: `FUN_18001f610`, call at `0x18001fef2`.
- Direct preprocessing callee: `FUN_18002bfa0`.

## Behavior

- Argument 2 is the sample's single full-size 16-bit image-base frame; argument
  3 is its byte length (`0x4a40` for `108x88`).
- Hardware sensor ID is forwarded from engine context `+0x4a`.
  `EngineAdapterAttach` obtains the surrounding 0x30-byte sensor-information
  object through `GoodixEngineAdapter.dll` `FUN_18001d3b0`, which issues vendor
  IOCTL `0x442004` to `usbinterface.dll`. The returned verified OTP bytes begin
  at response `+0x02`; the first 16 bytes at `+0x02..+0x11` are copied into
  engine context `+0x4a..+0x59` and used as the persisted sensor key.
- Engine context `+0x98 == 1` is converted to a local `needupdatecali` value and
  passed to `FUN_18002bfa0`, but that callee only logs the value.
- On successful preprocessing, the initialized byte returned by
  `FUN_18002bfa0` is stored at context `+0x7c`, and frame length is stored at
  `+0x80`.
- `FUN_18002bfa0` reads the sensor-keyed local calibration blob, calls
  `preprocess_load_calidata` when its sensor ID matches or
  `preprocess_init_calidata` otherwise, and then calls `preprocessor_init`.
  After successful setup it immediately calls `FUN_18002aef0`, which serializes
  the current calibration blob back to the local file.
- The blob includes workspace sample count `DAT_180219670` and its calibration
  planes. It does not include profile-9 gain globals `0x1801efbf4..0x1801efbfc`.
  A setup refresh can therefore replace the workspace sample count while
  retaining auxiliary-count, initialization, and ready globals.
- On a successful one-shot reentry, `_InitPreProcessor_E` performs the same
  sensor-ID-qualified load at `0x18002c4f4`, calls `preprocessor_init` at
  `0x18002c65e`, and saves the resulting workspace at `0x18002c76c`. The setup
  call reaches `FUN_18006d540` at `0x18000294d`; its setup branch runs
  `FUN_180064bb0` and returns before the live `FUN_1800668f0` gain path or the
  type-12 classifier.
- The successful reload replaces the persisted workspace sample count,
  calibration/setup planes, and retained classifier packet without resetting
  temporal-stability scalar `DAT_1801efbf0`, auxiliary count
  `DAT_1801efbf4`, gain-initialization scalar `DAT_1801efbf8`, ready scalar
  `DAT_1801efbfc`, coarse reference `DAT_1801f9520`, primary auxiliary map
  `DAT_1801fbb70`, application map `DAT_180205490`, or secondary auxiliary map
  `DAT_18020edb0`. Those fields retain their process-lifetime values across the
  setup call and are consumed by the next live `FUN_1800668f0` call.
- Context `+0x7c` is zeroed by `EngineAdapterAttach` (`FUN_18001e5b0`). Normal
  probes therefore initialize once per engine attach; `FUN_18001f610` can
  explicitly call this function again when the sample's one-shot base-refresh
  marker is set.

## Classifier Lifetime Across Refresh

`preprocess_load_calidata` replaces the packet at workspace `+0x26488`, but it
does not reset the type-12 import latch `DAT_1801dc9a8` or any classifier
global. `FUN_1800508a0` tests the latch at `0x180050a9f` and calls packet
importer `FUN_1800501d0` only while it is zero. Every entered classifier call
then serializes the globals through `FUN_18004ff40` at `0x180050ed3` and sets
the latch to one at `0x180050edc`.

Consequently, after any pre-refresh type-12 classifier call, one-shot setup
reload can replace and immediately resave an older packet, but the next live
classifier skips that packet and continues from process-global state. Its final
serializer overwrites the workspace packet from the surviving globals. The
loaded packet is authoritative only for the first type-12 classifier call in a
fresh DLL lifetime.

The surviving classifier state relevant to ordinary profile-9 behavior is:

| Native process state | Role |
| --- | --- |
| `DAT_1801dc9a0`, `DAT_1801eaf60` | component-age count and per-pixel ages |
| `DAT_1801dc9a4`, `DAT_1801dc9b0`, `DAT_1801e62d0` | retained-reference count, reference, and support ages |
| `DAT_1800f28f0`, `DAT_1800f28f4` | adaptive reference threshold and average |
| `DAT_1801dc990`, three slots from `DAT_1801ce3e0` | extraction retained-plane count and planes |
| `DAT_1801dc994`, `DAT_1801dc998`, `DAT_1801dc99c` | extraction prior coverage, hysteresis, and prior merged high class |

The packet transports the three retained-plane prefixes, component/reference
counts, component/support ages, and downsampled reference. It does not transport
the two adaptive reference scalars or the extraction prior-coverage/hysteresis
scalars. The extraction append occurs after packet serialization.

`DAT_1801dc9a8` is the importer mechanism itself. `DAT_1801dc9ac` is prior
coverage used only when selected-plane value 2 is supplied. The normal sample
path fixes the mode argument to zero at `FUN_18002004a`, and `preprocessor`
writes that mode to workspace `+0x26484` at `0x180002be5` before every live
call. Workspace `+0x26484` is therefore an entry value supplied by the export,
not retained prior-call selection on the ordinary path.

Across successful one-shot reinitialization, persisted workspace fields are
reloaded while the gain, classifier, and extraction globals above retain their
process-lifetime values. Once the type-12 import latch is set, the next live
classifier consumes those surviving globals rather than reimporting the
reloaded packet, then serializes the surviving state back into the workspace
packet. `FUN_180064170:0x180064297..0x1800642f4` can increment stability state,
`FUN_180067500:0x1800679f2..0x180067a05` can set and clear ready, and the
classifier update functions mutate retained counts, planes, and adaptive
scalars without a setup-path reset.

## usbinterface.dll Hardware Marker Provenance

The hardware side is in `usbinterface.dll` 2.0.310.900, SHA-256
`619f1b708be2d724f4bbe3d08f656586ccb4153afa97a18f659fa8338515e07f`.
Profile-9 worker `usbinterface.dll` `FUN_18000df20` maps FDT events `0x0f`,
`0x10`, and `0x11` to device actions 0, 1, and 4. Their installed
down/up/reverse handlers reach `usbinterface.dll` `FUN_180013da4` at
`0x180014ffe`, `0x180014b6a`, and
`0x180014698`/`0x18001480d` respectively.

`usbinterface.dll` `FUN_180013da4` clears hardware base-valid byte `+0x232` at
`0x180013dfa`, synchronously calls `usbinterface.dll`
`MilanHV_update_allbase` (`FUN_180015c60`) at `0x180013e01`, and sets one-shot
byte `+0x236` at `0x180013e11` only when the refresh restored `+0x232` to one.
`usbinterface.dll` `OnCaptureData` (`FUN_180021978`) registers
`usbinterface.dll` `CaptureFramedone` (`FUN_18001fb40`) through
`usbinterface.dll` `FUN_18000ebcc` at
`0x180021ece..0x180021ee1`.
Device action `0x15` passes retained TX-on base `+0x248`, live frame `+0x340`,
live length `+0x34c`, and marker `+0x236` to that callback at
`0x18000e629..0x18000e652`, then clears the marker at `0x18000e661` after the
callback returns. `CaptureFramedone` stores callback argument 5 at sample
payload byte zero (`0x18001fbdf`), copies the live frame at
`0x18001fca0..0x18001fcb7`, and copies the retained base at
`0x18001fcbc..0x18001fcd9`. This is the complete binary-qualified producer and
handoff chain for the marker consumed by `GoodixEngineAdapter.dll`
`FUN_18001f610`.

The hardware refresh does not call the engine preprocessor setup path directly.
It only latches the marker for a later device-action-`0x15`
`CaptureFramedone`/`EngineAdapterAcceptSampleData` callback. A finger-up refresh
after the final enrollment extraction therefore cannot reload the workspace
packet before `EngineAdapterCommitEnrollment` unless another sample callback
first enters the engine. Without that callback, commit saves the packet already
serialized by the final live preprocessor call, which contains the extraction
ring from before that call's later append.

`EngineAdapterAcceptSampleData` consumes that marker by calling this function
before its synchronous preprocessing/extraction path. The same callback then
finishes the live state mutation before returning. Hardware refresh therefore
cannot replace the workspace of an already active sample callback; only a later
sample callback can initialize the refreshed setup.

## Lifetime

- The engine context retains calibration state, not this temporary frame
  allocation. `FUN_18001f610` frees the copied frame after the call.
- `FUN_18002aef0` has two direct callers. This setup path calls it at
  `0x18002c76c`, before any later live preprocessing can evolve the just-loaded
  state. The second caller, `FUN_180030b40`, is a post-live save wrapper reached
  by successful `EngineAdapterCommitEnrollment` at `0x180022af4` and by a
  successful identify-template update during `EngineAdapterDeactivate` at
  `0x180031c1e`. Those later saves can persist the workspace sample count and
  calibration plane accumulated by live preprocessing.
- Adapter detach reaches `preprocessor_exit` through
  `FUN_180030f40 -> FUN_18002b7e0`, clearing the global `0x3048c` calibration
  workspace and calibrated flag.
- `EngineAdapterAttach` is an externally registered callback with no direct
  in-DLL caller. It initializes context `+0x7c` to zero once per adapter attach.
- `EngineAdapterDetach` is `FUN_18001ed10`; it calls `FUN_180030f40` at
  `0x18001ee7d`, then frees the complete engine context on success. A new attach
  therefore cannot inherit `+0x7c` from the old engine context.
- UMDF hardware D0 transitions occur in `usbinterface.dll` and have no direct
  call edge to adapter detach or `preprocessor_exit`. Whether WBF schedules an
  adapter detach for service idle or a particular system-power transition is
  external to these binaries.
