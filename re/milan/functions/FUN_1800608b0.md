### Type And Penalty Dispatch

Template type is read as an unsigned dword from configuration `+0x3c`.
Denominator is 42 exactly for types `12`, `13`, `16`, and `22`, the set bits of
`0x413000`; every other value, including 23 and arbitrary values above 22, uses
31. Types 11 and 21 first compute, with dword wrap:

```text
penalty = metric12 + metric13 + metric14 + (metric0 < 5)
detail = metric5 - 3 * penalty
low_detail = metric8 - 3 * penalty
combined = detail + low_detail
```

The alternate-policy branch at configuration `+0x44` has priority over the
ordinary type-11/21 branch. Profile-9/type-12 configuration supplies template
type 12 and nonzero alternate policy.

### Alternate Policy

If `metric0 < metric1`, subtract two from both detail words before testing.
Accept exactly when all three signed conditions hold:

```text
metric1 >= 8
detail + low_detail - 4 * (metric12 + metric13 + metric14) >= 417
metric9 >= 96
```

The type-11/21 penalties happen before this mutation; the explicit four-point
penalty uses only words 12..14. Input metrics are never modified.

### Ordinary Type 11/21 Policy

With alternate policy zero, type 11 or 21 accepts when at least one complete
path is true. `combined` is the post-penalty sum above:

```text
metric0 >= 5 && metric1 >= 8 && combined >= 425 && metric11 >= 42
metric0 >= 3 && metric4 >= 235 && metric9 >= 120 && combined >= 400
metric0 >= 6 && metric9 >= 61 && combined >= 415 && metric11 >= 41
```

This is the exact grouping of `0x180060a4f..0x180060a98`; equality at every
shown threshold passes. Successful scoring always uses denominator 31 and the
special numerator rounding constant 15.

### Score Arithmetic And Trust

After a successful alternate/generic path:

```text
q = ((denominator >> 1) + (metric1 << 8)) / denominator
score = (q * 100) >> 8
```

The type-11/21 ordinary path instead uses
`q = ((metric1 << 8) + 15) / 31`. Shifts, additions, and multiplication wrap as
32-bit dwords; division is signed and truncates toward zero; the final shift is
arithmetic. Rounding therefore occurs before percentage scaling. No metric is
range-checked, so wrapped penalty sums and accepted malformed values are
consumed as-is and can produce negative or otherwise non-policy scores.

Failure returns zero. There is no status output, score cap, or context mutation.
Null metrics or configuration pointers fault immediately in the DLL. Production
callers provide nonnull vectors with small caller-produced values; malformed
null/extreme behavior is not production-reachable.

## No-Direct Caller Finalization

At `FUN_180055a40:0x180057005..0x180057038`, this helper validates a retained
winner only when no direct score has already been latched, contributor count is

this block. The helper's numeric result is used only as a zero/nonzero gate
at `0x180057031..0x180057038`; it is never published as the final score.

After a nonzero result, the caller visits physical feature indices in ascending
order and increments every nonzero contributor slot at
`0x18005703a..0x18005706d`. For type 12 it then sorts gallery order through
`FUN_1800607b0` and publishes the all-contributor aggregate at


updates do not require a selected feature, so the selected feature can remain

`FUN_180055a40.md`. The post-loop `FUN_18005d9e0` rescue is a separate path and
does not call this helper.
