## Recovered Behavior

It lifts every cropped byte to unsigned Q8 (`byte << 8`) and constructs six
same-sized unsigned-16 scale planes. The generic type-12 path uses the caller
marker as the first Gaussian filter ID and then applies the next five IDs. Thus
the ordinary pass uses `0..5`, while the low-count retry uses `100..105`. Plane
zero filters the lifted image; each later plane filters the preceding plane.

Arguments are the byte-image descriptor, an array of six word-image descriptor
pointers, the pass marker, and sensor type. Type 12 takes the six-plane branch.
The lift reads the byte count at source descriptor `+0x0c` and pixels at `+0x18`,
writing directly into plane zero's pixel storage before filtering it in place.
Each later call reads the previous descriptor and writes the next one. All image
storage belongs to the caller; this owner returns no status and assumes valid,
same-sized descriptors, sufficient preallocated planes and successful internal
filter allocations. The byte source remains unmodified.

Every row sums exactly to `0x10000`. `FUN_18007be70` dispatches each ID through
`FUN_18007d800` and `FUN_18007dd20`. The weighted horizontal backend at
`FUN_18007d9c0` and weighted vertical backend at `FUN_18007d260` use reflect-101
borders (`-1 -> 1`, `length -> length-2`), unsigned 32-bit multiply/add with
modulo-`2^32` lane behavior, and logical `>>16` with no rounding bias. The
horizontal intermediate is 32 bits; the vertical result is narrowed to 16 bits.
The horizontal backend accumulates taps in coefficient order. The vertical
backend starts with the central coefficient, then adds symmetric row pairs
times the matching positive-offset coefficient. Both have four-lane loops and
scalar tails with the same arithmetic. The symmetry and nonnegative coefficients
make that vertical grouping equivalent to a full ordered dot product.

For any unsigned-16 input, not merely byte-derived Q8 input, every partial sum
is at most `65535 * 65536 = 0xffff0000`. A symmetric pair is at most `131070`;
pair formation does not overflow a dword. Horizontal truncation therefore yields
at most `65535`, so storing it in a word loses no information before the second
pass. For lifted bytes, the stronger upper bound is `65280` throughout all six
planes. Each plane consumes the preceding plane's already twice-truncated words;
there is no single combined two-dimensional accumulation.
