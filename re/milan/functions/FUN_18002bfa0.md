# FUN_18002bfa0

## Identity

Production adapter setup owner `_InitPreProcessor_E`, called by
`FUN_180031d00` and calling `preprocessor_init` at `0x1800027b0`.

## Profile-9/Type-12 Contract

- `DAT_1800f2408` is the adapter algorithm-profile index supplied by
  `FUN_18002b240` to `ppp_param_init`. Its value is 9 on the type-12 path;
  it is not the packed preprocessing sensor-type value 12. The dimension row
  at `DAT_1800f2410 + 9*8` supplies columns 108 and rows 88. Profile-9
  `ppp_param_init` independently selects the preprocessing parameters carrying
  sensor type 12.
- The adapter derives rows and columns from this profile table, requires an
  exact `rows * columns * 2` input, and constructs the setup object with frame,
  rows, and columns at `+0x18`, `+0x24`, and `+0x28`.
- It loads persisted calibration only when the 16-byte sensor ID matches;
  otherwise it initializes default calibration before `preprocessor_init`.
- `preprocess_load_calidata` validates the `0x224b0`-byte payload version and
  both full-frame checks before mutating state, then restores the workspace
  calibration/setup planes, sample count, and three external retained blocks.
  Its exact field table and failure semantics are documented in
  `preprocess_load_calidata.md`.
- A direct preprocessor setup object matches this ABI and size but does not by
  itself model the adapter's sensor-ID-qualified calibration persistence; an
  exported WBF attach path reaches the load gate before setup initialization.
- The setup argument is one full 16-bit frame. No list, pair, mean, or other
  reference aggregate is passed to `preprocessor_init`.
- `preprocessor_init` is called at `0x18002c65e`. On failure it is retried once
  at `0x18002c6be` with the same setup object and same frame; the retry does not
  acquire or combine another frame.
- If both calls fail, the function writes adapter status `0x8002` at
  `0x18002c71f..0x18002c72d`. It does not set the caller-provided initialized
  byte and does not save calibration. A first-call failure followed by a
  successful retry sets the initialized byte and follows the normal save path.
- A successful call sets the caller-provided initialized byte and immediately
  saves the sensor-ID-prefixed calibration object through `FUN_18002aef0`.
- A nonzero load result falls back to `preprocess_init_calidata`; fallback
  failure would map to adapter status `0x8002`, although the analyzed fallback
  body has no nonzero return. Successful load or fallback proceeds through the
  same setup initialization and save sequence. See
  `preprocess_init_calidata.md` for its exact writes and omitted fields.
- The nominal `needupdatecali` input is read for the entry log but does not
  control any branch in this function. Refresh is selected by the sample marker
  in `FUN_18001f610` before this function is called.
