## Recovered Behavior

The function allocates and populates a `0x168`-byte owned feature object from a processed image and profile configuration. It builds the high, enhanced, low, validity, and packed masks, invokes `FUN_180049b90` for candidate and descriptor materialization, applies later descriptor transformations, and calls `FUN_180037480` to partition active records. The resulting object stores its active record count at `+0xf0`, a pointer to `0x38`-byte records at `+0xf8`, and owned matrices at `+0x08`, `+0x10`, `+0x18`, `+0x20`, and `+0x140`.

For profile 9/type 12, optional packed field `c7` has two producers. The call to
`FUN_18006fb10` occurs at function entry, directly on the incoming
processed-image descriptor, before cropping, map construction, record
materialization, or any other image helper. Its decoded dword is retained in a
local. Later, when the auxiliary extraction context is present, the call to
`FUN_180048260` receives that local by pointer and may overwrite it from
extraction classification state. The final value is written to live feature
`+0x150` near function exit.

At the exported identify call, stack argument 6 is the first candidate's
internal template/configuration and stack argument 8 is the same preprocessor
auxiliary workspace passed to `identifyImage`. The authoritative profile-9
configuration words are `[12,104,88,1,1,150,150]`. Immediately before
`FUN_180048260`, this function combines those words with raw processed geometry,
the three zero-extended auxiliary bytes, entry-decoded low/high classes, and
coverage into the exact configuration documented in `FUN_180048260.md`.

The extraction classifier runs before `FUN_180049b90` record materialization
and before the final feature store. Its process-global history mutations are not
rolled back by later extraction or matching failure.

An order-discriminating low-quality control has an invalid alternating metadata
prefix: `FUN_18006fb10` returns zero, but `FUN_180048260` subsequently changes
the local to `512` (`high=2`, `low=0`) before the `+0x150` store. The value is
already `512` at the pre-anti-fake `identifyImage:0x180001dbd` boundary and
remains unchanged by both gallery matches. A native implementation that models
only the entry decoder therefore drops a real extraction-stage scalar.

## Match-Matrix Input Ownership

This function produces live feature count `+0xf0`, record pointer `+0xf8`, and
stored physical boundary `+0x118`, which are the complete feature-owned inputs
to later matrix production. It does not allocate or store either `180x180`
matrix. Feature masks, bitmaps, and active state are negative-control inputs to
the producer itself, although they can affect upstream record materialization.
