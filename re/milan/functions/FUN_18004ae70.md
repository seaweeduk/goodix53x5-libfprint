## Feature Object

The function allocates and populates a `0x168`-byte owned feature object from a
processed image and profile configuration. It builds high, enhanced, low,
validity, and packed masks; calls `FUN_180049b90` for record materialization;
applies descriptor transformations; and calls `FUN_180037480` to partition
active records. The object stores record count at `+0xf0`, a pointer to
`0x38`-byte records at `+0xf8`, and owned matrices at `+0x08`, `+0x10`,
`+0x18`, `+0x20`, and `+0x140`.

For profile 9/type 12, optional packed field `c7` has two producers.
`FUN_18006fb10` decodes the incoming processed-image descriptor before
cropping, map construction, or record materialization. Later,
`FUN_180048260` receives that local value by pointer and may overwrite it from
extraction classification state. The final value is stored at live feature
`+0x150`.

At the exported identify call, stack argument 6 is the first candidate's
template/configuration and stack argument 8 is the preprocessor auxiliary
workspace. The profile-9 configuration words are
`[12,104,88,1,1,150,150]`. Immediately before `FUN_180048260`, this function
combines those words with processed geometry, three zero-extended auxiliary
bytes, entry-decoded low/high classes, and coverage.

`FUN_180048260` runs before record materialization and final feature
publication. Its process-global history mutation is not rolled back by a later
extraction or matching failure.

## Broken-Mask And Inline-Mask Ownership

The processed-image broken-pixel mask is distinct from both feature-owned mask
representations. `FUN_18006fb10` decodes it before centered width reduction.
`FUN_18006fef0` has already sampled initial validity into the owned `52x44`
matrix at feature `+0x20` by `0x18004b341`.

When decoded-mask construction succeeds,
`0x18004b590..0x18004b5fa` selects radius 2 for decoded high class below 4, or
radius 5 plus clearing for high class 4 or 5, and calls `FUN_18004db10`. Mode 1
clears the separate `104x88` validity matrix; it does not revisit feature
`+0x20`. This occurs after record materialization and before `FUN_180072b60`,
record transformation, and partitioning. The decoded `108x88` mask is freed at
`0x18004b603`.

The predicate at `0x18004b58b..0x18004b590` tests decoded-mask availability,
not live record count. It passes the allocated record pointer and
`&feature->count` even when count is zero. `FUN_18004db10` then returns at
`0x18004db49..0x18004db4e` before neighborhood construction or mode-1 clearing
unless signed count is positive. A zero-record feature therefore retains its
pre-filter `104x88` validity matrix.

The broken-mask filter receives original width 108 at `0x18004b5f6` and uses
record coordinates without adding the two-column centering offset. Its separate
feature-mask width is 104 from `0x18004b5ea..0x18004b5f0`.

`FUN_180072b60` at `0x18004b613` reduces finalized `104x88` validity to the
72-byte row-contiguous `26x22` mask at feature `+0x28`. `FUN_1800721a0` at
`0x18004b629` expands it in mode 1 to a temporary `52x44` byte plane;
`FUN_180073950` packs that plane into the owned 308-byte row-strided one-bit
matrix at `+0x140`. `FUN_18005d9e0` later clones `+0x140` for aggregate rescue.

Anti-fake and rescue consume different owners. `FUN_1800392f0` reads feature
`+0x20`, so anti-fake sees the pre-filter half-resolution sample. Rescue sees
`+0x140`, derived from finalized inline mask `+0x28` after mode-1 clearing.
`FUN_180040a70` serializes only the 72-byte `+0x28` mask as tag `ce`;

## Record Limit And Transform

For type 12 and valid coverage `0..100`, the record limit is
`max(1, coverage * configured_limit / 100)` with integer truncation. The
separate `+50` rounded branch at `0x18004afce..0x18004afff` applies to types 9,
10, 17, and 18, not type 12. Record materialization can return zero or fewer
records than the limit; its `FUN_180049b90` callee performs the limit comparison
and truncation before returning the selected records.

### Ordinary Identify Record Bound

`identifyImage` supplies the first live gallery template as configuration and
mode one, selecting its `+0x18` record maximum at
`0x18004af22..0x18004af38`. Every ordinarily unpacked type-12 gallery has both
`+0x14` and `+0x18` equal to 150: `FUN_180040700` selects literal `0x96` for
type 12, and `FUN_18003fef0:0x18004022a..0x180040240` writes both fields even
when no feature-count shrink occurs. Thus the first candidate and any later
matched candidate have the same record maximum.

Ordinary preprocessing supplies coverage in `0..100`, not an arbitrary byte.
The type-12 route through `FUN_180044900` reaches `FUN_180044300`, whose
`0x1800444a4..0x1800444bd` clamps coverage to that interval.
`FUN_18006d540` preserves coverage after that call; its low-coverage policy
changes quality only. Exported `preprocessor` writes the coverage byte into
the processed-image descriptor, and `identifyImage` zero-extends it for this
function.

At `0x18004af41..0x18004af6d`, type 12 therefore computes
`L = max(1, trunc(150 * coverage / 100))`, so `1 <= L <= 150`. The product is
at most 15000 and cannot wrap. Type 12 bypasses both the rounded-limit branch
and the later budget rewrite at `0x18004b4f6..0x18004b528`.

`0x18004b528..0x18004b562` passes `L` as configuration word one to
`FUN_180049b90`. Its type-12 path at `0x18004a097..0x18004a17b` leaves a
materialized count at most `L` unchanged; otherwise it ranks the candidates,
copies exactly `L` records, and writes `L` to feature `+0xf0`. The retry pass
precedes this clamp and does not change `L`.

After materialization, type 12 bypasses `FUN_180048b00`: bit 12 is clear in the
dispatch mask at `0x18004b56f..0x18004b57d`. The only remaining count-writing
callee is `FUN_18004db10`, which removes records or leaves the count unchanged.
Mask construction does not alter record count. `FUN_180047ae0` transforms one
existing record at a time; `FUN_180037480` partitions records and writes the
zero-flag boundary at `+0x118`, not total count `+0xf0`.

Consequently the extracted ordinary identify probe has
`0 <= feature[+0xf0] <= L <= 150`. In replacement record copier
`FUN_180037690:0x1800376f8..0x180037732`, the over-limit branch is a strict signed
`count > maximum` test. Equality 150 takes the direct-copy branch, which copies
all `count * 0x38` record bytes and preserves the probe's zero-flag boundary
`+0x118`. The over-limit rank/truncate branch is not reached by this producer
when copying into an ordinary type-12 gallery.

The final transform loop at `0x18004b680..0x18004b6a4` passes caller argument 5
to `FUN_180047ae0`. It does not derive transform mode from subtype or
configuration. Exported WBF enrollment reaches the loop with mode 0;
`identifyImage` reaches it with mode 1. Mode 1 derives record spans
`+0x24..+0x27` and `+0x30..+0x37`; type-12 serialization omits those spans.

Transformation follows final inline-mask generation. `FUN_180037480` then
partitions complete 56-byte records and publishes `+0x118` at `0x18004b6a9`.
Final mask generation and record partitioning have no shared predicate.
