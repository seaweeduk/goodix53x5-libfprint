## Recovered Behavior

This function enriches candidate records already constructed by
`FUN_18003b0b0`; it does not create or change their count. It converts the
supplied 16-bit residual to clamped 8-bit intensity (`/12`, or `/20` for chip
type 17), builds orientation/magnitude support planes, then iterates the count
at anti-fake `+0x12c0`.

For each 48-byte candidate it preserves coordinates at `+0x00/+0x04`, samples
the orientation plane at those coordinates, builds a descriptor through
`FUN_18004cc70`, transforms it with `FUN_180047ae0`, and writes the remaining
40 bytes at `+0x08..+0x2f`. The loop bound is the existing count; there is no
append, suppression, or count store in this body.

The source geometry comes from the live feature's first matrix descriptor and
is `104x88` for profile 9/type 12. The function consumes exactly `104*88`
sequential `uint16_t` values from the supplied residual pointer, converts each
to `min(value / 12, 255)`, and uses that same `104x88` geometry for dense
orientation, magnitude, gradient orientation, and candidate-coordinate
sampling. It does not row-crop or restride the original `108x88` residual here.

For subtype 12, residual conversion is exactly unsigned `min(source[i]/12,255)`
for sequential indices `0..9151`. The frame then has three dense row-major
support planes with width 104 and height 88:

- `FUN_18007ebe0(frame, dense_orientation, 104, 88, 7)` writes one orientation
  byte per pixel.
- A 32-bit plane receives `frame[i] << 8`, and `FUN_18004cad0` writes centered
  interior gradients to a zeroed `uint32_t` magnitude plane and zeroed
  `int16_t` gradient-orientation plane.
- The one-pixel magnitude/orientation borders remain zero, while dense
  orientation is defined for the complete plane.

Support-plane construction precedes the count check even when count is zero.
The local descriptor configuration at `0x18004b977..0x18004ba06` is
`[12, 0, 300, 40, 0, 0xc117, 32, 4, 0, 32, 1, 0, 0]`.
At `0x18004ba0e`, every invocation initializes the process-global Hadamard
table at `0x180257520` through `FUN_180047610`, before the signed count gate
at `0x18004ba13..0x18004ba19`. It passes this table and the local configuration
to every descriptor call. Empty calls therefore still construct and release
the support planes and initialize the table; only record iteration is skipped.

The function zero-initializes its reusable 56-byte temporary feature record
before the record loop. Each iteration reads the candidate x/y low words,
forms Q8 signed-word coordinates `x<<8` and `y<<8`, and samples
`dense_orientation[y*104+x]`; produced type-12 coordinates are `x=4..103` and
`y=4..83`, so no narrowing changes them. It computes

```text
degrees = (270 - dense_orientation[y*104+x]) % 180
orientation = degrees * 0x6488 / 360
```

with truncation toward zero. This yields descriptor feature orientation in
`[0,0x31fc]`. Foreground and strength remain zero. `FUN_18004cc70` receives the
integer coordinate, fixed descriptor scale `0xc117`, and dense magnitude and
gradient-orientation matrices. It completely defines temporary bytes
`+0x10..+0x37`; no prior candidate metric or temporary payload survives.

Transformation precedes projection. `FUN_180047ae0(record,1)` first performs
the nibble rearrangement, clears and bit-reverses the first descriptor tail,
and expands the second tail. The owner then copies these exact spans:

```text
anti-fake +0x08..+0x17 <- temporary feature +0x28..+0x37
anti-fake +0x18..+0x27 <- temporary feature +0x10..+0x1f
anti-fake +0x28..+0x2f <- temporary feature +0x20..+0x27
```

This overwrites the candidate metric formerly at anti-fake `+0x18`; only the
original dword x/y at `+0x00/+0x04` are retained. Every published 48-byte record
is therefore fully defined. After this function returns, `FUN_1800392f0` writes
signed dword `-1` to pair score `+0x1ab4` at `0x1800397a0`; this function does
not initialize or score record pairs.
