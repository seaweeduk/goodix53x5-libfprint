## Recovered Behavior

It initializes only residual (`0x190000`) and a private candidate mask, then
enumerates every triple lexicographically as `(0,1,2)`, `(0,1,3)`, and so on.
There are no edge-length, orientation, coefficient-consistency, minimum-inlier,
or triangle-count gates and no `0x3b2` cap. Every triple reaches
`FUN_1800683d0` and every solved affine is scored.

For each pair, mapped coordinates are signed 64-bit
`((a*x+b*y)>>8)+tx` and `((c*x+d*y)>>8)+ty`; unlike recognition there is no
`+0x80` before either shift. At `0x180079490..0x1800794ae`, branchless signed
absolute value is followed by signed `CMP/JGE`; before target subtraction it
therefore rejects either mapped coordinate whose signed-64 absolute value is at
least `0x100000000`. This is not an unsigned comparison. Residual components
then use signed 64-bit subtraction and must each be at most 640 (`<0x281`), in
branch order, before the signed-64 squares and sum at
`0x1800794e3..0x1800794f5`; the sum must be strictly below `0x64000`.
Accepted squared values accumulate in a dword, which is overflow-free for the
production maximum. Mean residual is `(sum+(count>>1))/count`, or `0x190000`
for zero inliers.

Ranking is strict larger inlier count, then equal count with strict lower mean;
an exact tie preserves the first triple. `FUN_180080130(affine,401,163)` is
called only after that rank test, so a nominal winner that fails validity leaves
the prior valid winner unchanged. Successful replacement atomically commits
affine, residual, and all 42 mask bytes. The strict early exit occurs after
validity/commit when retained best count becomes greater than 20: 20 continues,
while 21 owns the first accepted model and suppresses all later triples.

On ordinary completion, no accepted model publishes six affine zeros and leaves
residual `0x190000`; the supplied output mask remains caller-owned/untouched.
An accepted model publishes its saved affine, mask, and residual. The function
has no return status or separate count output; callers count committed mask
bytes.

Evidence includes triple enumeration at `0x18007937f`, affine solve near `0x180079455`, residual scoring through `0x18007953f`, validity at `0x1800795b8`, and the strict `>20` exit around `0x18007961d`.

## Recognition Difference

Recognition `FUN_180077e20` adds three edge gates, two-pass orientation
consistency, coefficient limits, minimum inliers 2, and the soft outer-loop
triangle threshold. Recognition mapping rounds with `+0x80`; this enrollment
helper truncates after signed `>>8`. Recognition is followed by orientation
mask filtering and optional least-squares refinement; enrollment has neither.
Both use the same component/squared gates, winner ordering, validator, strict
`>20` exit, solver, no-model affine/residual publication, and first/equal
ownership.

The production enrollment caller supplies at most 31 selected pairs and invokes
relation handling only from five pairs upward. Current
`goodix_milan_estimate_relation()` writes relation index, best inlier count, and
six affine words only after a model is accepted; every validation, count, and
no-model failure returns `-1` without writing the relation. It intentionally
does not publish the native helper's mask or residual. A five-pair small-triangle
set can therefore produce a valid enrollment relation even though recognition
rejects the same pairs at its edge gate.

## Bounds And Failure

Counts at most two (including malformed negative counts) skip enumeration,
publish affine zero/residual sentinel, and leave mask bytes untouched. Mask
storage is fixed at 42: a malformed count above 42 calls the non-returning bounds
handler at `0x180079683` once a triple reaches scoring. Null residual faults at
entry; null affine faults during candidate or final publication; coordinate and
mask pointers fault on their count-driven paths. The pre-subtraction
`2^32` check bounds ordinary large solved coordinates but does not make arbitrary
pointer/count inputs safe. All such cases are excluded by the 31-pair production
caller.

Current `goodix_milan_estimate_relation()` omits the native pre-subtraction
`2^32` check and spells later signed residual squaring in C. For ordinary solved
models the component gates keep accepted arithmetic bounded and outputs are
exact. A singular or near-singular triple can create huge intermediate
coordinates before affine validity rejects it, however, making the current
signed square a theoretical undefined-C surface; UBSan reports overflow for
synthetic singular candidates. The DLL's signed mapped-coordinate precheck runs
before target subtraction and residual squaring, while the current source omits
that precheck.

Valid five-pair inputs, including singular and near-singular candidates, yielded
no stable DLL/current output discriminator and no accepted-input native crash.
The candidates still converge on rejection without committing a relation, and
canonical enrollment estimation, winner selection, validity, and output behavior
match the DLL. This is not evidence for a production correction. Whether a valid
profile-9 input can turn the current language-level overflow into a stable
semantic difference remains unresolved; malformed pointer/count inputs retain
the crash surfaces above.
