## Cache-Queue Initialization

After gallery-feature allocation, the constructor sets all 20 ranks at
`+0x8db0` to `-1`, zeroes the qword at `+0x8e00` (`state=0`, `counter=0`), and
preallocates 20 complete `0x168` cache feature owners at `+0x8d10`. Each cache
feature receives the same geometry-specific matrix and record allocations as a
gallery feature. State 0 therefore means enabled/allocated, not occupied.

For profile-9/type-12, direct controls confirm initial allocated/occupied counts
`20/0`. Ownership remains with the live template until capacity shutdown or
destruction. Evidence: `0x180037fc8..0x180038168`.

The qword zero at `+0x8e00` is two independent dwords: queue enabled/disabled
state `fa=0` and queue transaction counter `fb=0`. It is not capacity or graph
state. Unit-6 controls independently vary both words after construction.

Native `GoodixStudyQueue` construction now requires those two explicit scalars.
State 0 allocates 20 empty owners with rank `-1`; state 1 allocates none; any
other state fails. The counter is `uint32_t` and is preserved, not reused as an
insertion rank, continuation cursor, capacity flag, or graph reference.
