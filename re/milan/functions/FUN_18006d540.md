# FUN_18006d540

## Audit Scope

Internal live-preprocessing routine called by the exported `preprocessor` and
already identified as the caller of `FUN_18006c510`. This note was created
before first Ghidra decompilation during the scoped production argument
provenance audit.

## Questions

- Is the optional `0x4c98` auxiliary object reset or populated for profile 9,
  packed subtype 12, and production purpose `1`?
- Which branch forwards the purpose pointer to `FUN_18006c510`?

## Audit Findings

- Exported purpose argument 2 reaches this function as argument 10 and is
  forwarded as the first argument of `FUN_18006c510`.
- Any nonnull auxiliary argument is cleared with `memset(aux, 0, 0x4c98)` on
  every live call before the profile-qualified auxiliary branch.
- Packed subtype 12 is included in the auxiliary branch mask.
- Fresh profile-9 purpose-1 captures leave all `0x4c98` bytes zero; SHA-256 is
  `97563c5069ede573b4100ce8aef42f4fa1d3e46d8f5f1011d43704596a855a2d`.
- Before candidate selection, profile 9 builds a third mask from the primary
  contrast image through `FUN_18007e4b0` with strict threshold `100`. Packed bit
  2 is clear, so `FUN_18006e7f0` uses this generated mask rather than the
  profile rendering mask.
- `FUN_180069820` receives the copied canonical u16 input before setup or live
  processing. For packed subtype 12 it clamps to 12 bits without applying
  `4095 - sample`. Setup uses the nonvalidated branch, which conditionally
  repairs invalid second-from-edge samples. Live uses the validated branch,
  which copies only the outer edge and deliberately retains invalid
  second-from-edge samples.
- Caller `preprocessor` at `0x180002ab0` builds packed chip info from initialized
  profile globals and passes it as argument 5. The subtype selector recovered
  here is not the source descriptor's separate `0x10` format byte.
- Setup calls (`calibrated == 0`) run `FUN_180064bb0` and return before live
  rendering. Live calls therefore depend on the initialized `0x3048c`-byte
  generation workspace; a reset state plus setup frame is not equivalent to a
  production `preprocessor_init` call.
- On the live path, workspace `+0x1cb64` is cleared and passed as the output of
  `FUN_18006b510`, making it the primary contrast plane. A second candidate
  plane lives at `+0x217f4`. The selected-plane scalar is workspace `+0x26484`.
  At function exit, scalar zero copies `+0x1cb64` to the exported result;
  nonzero copies `+0x217f4` instead.
- The selected-plane scalar at `+0x26484` is read into a local before the current
  call invokes `FUN_18006e7f0`. The current selector then overwrites the
  workspace scalar, but `FUN_18006b290` receives the saved entry value and emits
  its low byte as auxiliary byte 1. A zero-initialized preprocessing workspace
  therefore emits zero on the first live use; later successful calls emit the
  preceding call's selected plane. In Linux, snapshot
  `state->selected_refined` on entry before replacing it at successful exit.
- The saved value also enters classifier context `+0x10`. Value 2 suppresses
  both retained-reference initialization and `FUN_1800512c0` update for that
  call; values 0/1 permit the normal lifecycle. The current selection cannot
  affect these transitions until the next live call.
- `FUN_1800392f0` always consumes primary contrast `+0x1cb64` for boundary-score
  classification, independently of the selected-plane scalar. Enrollment-1
  sequence 2 selects the refined output: primary contrast SHA-256 is
  `42fed78fdcb95ae0472910945be1eb94914af03e06292ff9b5d4fbe104d17d4b`,
  selected/exported output SHA-256 is
  `d619d53174c67813f9315a6dd5f71142a5b72a655c9f8d6199f55d3655dd0d2d`,
  and they differ in `8,351/9,504` bytes.
- For subtype 12, the normal `FUN_1800668f0` call allocates two temporary
  16-bit planes and passes their pointer pair as argument 5. The pair reaches
  `FUN_18006c510` as argument 3 and is freed immediately after that helper
  returns. The nested post-render `FUN_1800668f0` call passes `NULL` for the
  pair, so it cannot replace the planes while they are being evaluated.
- The cloned mask structure produced by `FUN_18006bce0`, not the earlier normal
  update mask, is argument 6 of `FUN_18006c510` and becomes the aliased workspace
  of the nested update.
- Return `0x7531` from `FUN_18006c510` writes 2 to caller result field 0 and sets
  bit 3 of result field 9 after downstream quality processing.
