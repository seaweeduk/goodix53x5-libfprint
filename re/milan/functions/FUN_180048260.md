## Recovered Behavior

The function's first matrix argument is the normalized `104x88` image on the
profile-9/type-12 path. It allocates three one-byte temporaries at that geometry,
so each temporary is 9,152 bytes. It clears the first and third temporaries,
derives binary and enhanced/classification planes, and updates extraction-global
classification history.

The destination is different. `FUN_18004ae70` allocates feature `+0x158` from
the dimensions of feature matrix `+0x08`, which are `52x44` on this path:
exactly 2,288 bytes. Destination writes are mode-specific:

- Modes 3 and 4 project the enhanced `104x88` temporary to `52x44` by selecting
  even rows and even columns on the profile-9 projection path.
- Mode 5 requires the optional source pointer at configuration `+0x28`; when it
  is present, the destination is projected from that source. The projection
  selector at configuration `+0x20` chooses direct coordinates or even/even
  coordinates.
- Modes 0, 1, and 2 do not populate a destination plane. The final
  `FUN_180073fd0` call writes only bytes 0, 1, and 2 from the three local state
  words. Every byte from offset 3 through 2,287 remains prior allocator residue.

The ordinary v3 probes select mode 0 and observe those first three bytes as
`00 00 00`. That proves the decoded auxiliary tuple, including the external
class later passed to candidate policy, is zero; it does not make the remainder
of the allocation defined.
