`FUN_18007eb30` on the profile-9/type-12 path. Its second matrix is the `104x88`

temporaries, derives current and history-conditioned class planes, and updates

The destination is different. `FUN_18004ae70` allocates feature `+0x158` from
the dimensions of feature matrix `+0x08`, which are `52x44` on this path:
exactly 2,288 bytes. Destination writes are mode-specific:

- Modes 3 and 4 project the enhanced `104x88` temporary to `52x44` by selecting
  even rows and even columns on the profile-9 projection path.
- Mode 5 requires the optional source pointer at configuration `+0x28`; when it
  is present, the destination is projected from that source. The projection
  selector at configuration `+0x20` chooses direct coordinates or even/even

  `FUN_180073fd0` call writes only bytes 0, 1, and 2 from the three local state

Those three bytes are not overwritten before matching. `FUN_180055a40` loads
the probe feature's `+0x158` pointer at `0x180055cda` and immediately calls
`FUN_180073830`, which zero-extends bytes 0..2 into three matcher state dwords.
The first dword remains the independent primary histogram class used by later

not part of the packed probe template, so a mode-summary divergence can leave
serialized probe bytes identical while still reaching same-operation matcher
policy. That reachability alone does not establish a complete score, candidate,
or lifecycle difference.

The fourth argument is an in/out packed-classification dword owned by
`FUN_18004ae70` and later stored as live feature `+0x150` / packed tag `c7`.
After current-frame and persistent-history classification, this function calls
`FUN_180073820` at `0x180048624` with the retained low class from configuration
`+0x10` and the final high class in `R14D`. The helper writes
`high_class * 0x100 + low_class` to the caller's dword. This is independent of
the mode-specific `+0x158` destination-plane projection.

When entry metadata decodes to zero and the final high/low classes are `2/0`,
the function produces packed value `0x200`. The extractor stores that value at

## Component And History Planes

The scalar path uses three temporary `104x88` byte planes:

1. A current class plane starts at zero. A threshold plane is `0xff` where the
   enhanced first matrix is below `0x80`. `FUN_180047820` retains pixels in the
   three largest four-connected components strictly larger than 500 pixels;
   those pixels become current class 1.
2. The threshold plane is rebuilt as `0xff` where the enhanced first matrix is
   at least `0x80` and the validity/classification mask is nonzero. The same
   component pass retains its three largest components; those pixels become
   current class 2.
3. A history-conditioned plane starts at zero. Once three retained planes are
   available, each `FUN_180047820` call requires the current component pixel to
   have the same class in all three retained planes, labels that stable mask,
   and writes the requested class for pixels in the three largest components
   strictly larger than 350 pixels. Class 1 is written first; class 2 only fills
   still-zero pixels.

The history-conditioned plane is then canonicalized: class 1 and class 2 pixels
are counted separately and both become byte 2; every other pixel becomes byte
1. These two counts drive the current class/mode seed:

- If stable class-1 count is above 600, seed 2 becomes 5, seed 1 becomes 4, and
  seed 0 becomes 3.
- When stable class-1 count is at most 600, stable class-2 count above 600
  promotes seed 0 to 3.
- If neither strict-600 promotion applies, either stable count above 300
  promotes seed 0 to 2.

The current class plane, not the canonicalized history-conditioned plane, is
what is appended to retained history. Its pixels are exactly 0, 1, or 2.

## Scalar State Machine

Let `current` be the promoted byte-0 seed, `high` the decoded entry high class,
`low` the decoded entry low class, and `aux2` auxiliary byte 2:

1. `high = max(high, current)`.
2. If `high < 2` and `aux2 > 0`, increment `high` once.
3. If auxiliary byte 1 is 2, replace `high` with
   `max(high, DAT_1801dc99c)`. Otherwise update `DAT_1801dc998`: increment it up
   to 5 when any of `high`, `current`, or `aux2` is above 1; decrement it when
   all three are below 2 and the counter is nonzero.
4. Store the merged `high` in `DAT_1801dc99c`.
5. If `DAT_1801dc998 >= 3`, clamp `high` to at least 1.
6. Call `FUN_180073820(packed_c7, low, high)`.

Thus the exact packer operands at `0x180048615..0x180048624` are
`EDX=config[+0x10]` and `R8D=R14D`, the final value after every transition
above. Operands `low=0` and `high=2` produce `0x200`; no constant `0x200`
exists in this path.

Each ring slot has generic stride `0x4c90`, although this call copies only the
current `104*88 = 9,152` bytes. There is no row-wise `108`-to-`104` remap at
this boundary: extraction consumes and replaces the contiguous 9,152-byte
prefix, while preprocessor import/export treats the retained plane as 9,504
profile-9 pixels. A call with current coverage at least 75 appends when the
selector is not 2. With selector 2, append instead requires both current
coverage at least 75 and retained `DAT_1801dc994` coverage below 75. Counts
0..2 select the corresponding slot. At count 3, slot 1 is copied to slot 0,
slot 2 to slot 1, and the new plane is copied to slot 2. The count then
increments and saturates at 3.

The scalar is packed before this append. Current-call `c7` therefore observes
only the previously retained planes; its newly built current class plane can
affect extraction classification starting with a later call.

`DAT_1801dc990` and the three planes are shared with the profile-9 preprocessor
state packet: `FUN_1800501d0` can import them and `FUN_18004ff40` serializes
them. Serialization precedes this extraction append, so a newly appended plane
first appears in the workspace packet on the next preprocessor call.
`DAT_1801dc994`, `DAT_1801dc998`, and `DAT_1801dc99c` have no xrefs outside this
function and are neither imported nor serialized. No explicit reset writes any
of the four extraction globals or ring planes in the analyzed DLL. They begin
