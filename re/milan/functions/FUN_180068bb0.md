## Inverse Construction

For adjusted transform `[a,b,tx,c,d,ty]`, determinant construction is wrapped
dword arithmetic:

```text
det = int32(a*d - b*c)
```

For nonzero `det`, it computes wrapping 64-bit numerators and signed division
truncating toward zero, then retains each quotient's low dword:

```text
ixx = ( d * 0x40000) / det
iyx = (-c * 0x40000) / det
itx = ((ty*b - d*tx) * 0x400) / det
ixy = (-b * 0x40000) / det
iyy = ( a * 0x40000) / det
ity = ((c*tx - ty*a) * 0x400) / det
```

The translation products, subtraction and multiplication by `0x400` wrap before
signed division (`0x180068c8b..0x180068cb9`). In particular, widening the
determinant or treating the translation numerator as unbounded changes sampling.

The destination loop uses wrapped dword accumulation:

```text
raw_x = int32(x*ixx + y*ixy + itx)
raw_y = int32(x*iyx + y*iyy + ity)
```

The coefficient array corresponding to those equations is
`[ixx,iyx,itx,ixy,iyy,ity]`.

When `det == 0`, the helper does not fail. It retains
`[1,0,0,0,1,0]`; these are literal Q10 accumulators, not Q10 unity. For the
profile-sized destination this maps nearly every sample to source pixel `(0,0)`.
The output sentinel remains in locations rejected by the boundary predicate.

## Sampling

Coordinates use arithmetic floor through signed right shift:

```text
x = raw_x >> 10
y = raw_y >> 10
fraction_x = raw_x - x * 0x400
fraction_y = raw_y - y * 0x400
```

Consequently each fraction is `0..1023`, including when `raw_x` or `raw_y` is
negative. A sample is outside the usable neighborhood when:

```text
x + 1 < border || x >= source_columns - border ||
y + 1 < border || y >= source_rows - border
```

The helper writes the destination's initial byte for that case. Under
`FUN_18006f390`, that byte is `0xff`.

When all four neighbors are usable, interpolation is:

```text
top    = p00 * (0x400 - fraction_x) + p10 * fraction_x
bottom = p01 * (0x400 - fraction_x) + p11 * fraction_x
value  = (top * (0x400 - fraction_y) + bottom * fraction_y + 0x80000) >> 20
```

At an edge, including floor coordinate `-1` with border zero, it ignores the
fractions and writes the unsigned integer average of only the usable cells in
the surrounding `2x2`. Division truncates toward zero.

For binary bitmap and validity planes, reached valid output values are `0` or
`1`; rejected samples are `0xff`. `FUN_180073540` also requires the warped
bitmap value to be below two, so an out-of-bounds `0xff` validity byte cannot
admit an out-of-bounds bitmap sample.
