## Behavior

- For packed subtype 12, the input live frame and setup plane have already been
  scaled by three in `FUN_1800668f0`.
- The production specialized branch computes each source sample as
  `max(scaled_setup - scaled_live - 0x2ffd, 0)`. Since the setup plane contains
  `normalized_setup + 7095`, this is exactly
  `max(9000 + 3 * (normalized_setup - live), 0)`.
- The clamp applies to the complete signed-baseline expression. It is not
  `9000 + 3 * max(setup - live, 0)` and not
  `9000 + 3 * max(live - setup, 0)`.
- The remainder selects update admission, derives gain maps, applies Q13 map
  combinations, and conditionally evolves persistent calibration state.
- Profile-9 mask admission is initially tested at 80%, but packed subtype 12
  overrides it with the strict test `admitted_mask_pixels * 10 >
  pixel_count * 9`. The admitted count comes from the `FUN_18006a4c0` mask
  structure before later rendering-mask hole fill.
- A mask-rejected subtype-12 frame still uses the signed-baseline source above.
  The strict mask predicate controls frame-derived gain creation and entry into
  the persistent update path; it does not fall back to generic
  `max(setup - live, 0)` rendering. The temporary gain starts at Q13 unity, but
  the common subtype-12 tail still combines it with the existing application
  and auxiliary gain maps before the caller renders the working frame.
- Mask-admitted and mask-rejected subtype-12 frames share the same
  primary-divisor tail. The persistent ready flag is updated before
  mask-controlled map evolution and before that tail. An auxiliary-map sample
  count of zero with
  workspace sample count strictly greater than 5 sets it, while auxiliary-map
  sample count at least 15 clears it. When ready is clear, the tail computes
  `round(round(temporary_gain * application_gain / 8192) *
  auxiliary_gain / 8192)` with a rounding step after each product. When ready is
  set, it computes only
  `round(temporary_gain * application_gain / 8192)`.
- The mask-admission predicate does not own the ready flag. Mask admission
  controls frame-derived temporary gain creation; ready controls which
  persistent maps the shared tail applies. This distinction is reached by both
  production subtype-12 branches.
- The transition observes entry counts. After the strict subtype-12 mask
  predicate accepts, `FUN_180064170` applies a separate temporal-stability gate
  at `0x180067ac6`. The ratio pointer begins null at `0x18006790f`; a zero gate
  result branches at `0x180067acd` past ratio-plane allocation at
  `0x180067b03..0x180067b27` and both `FUN_180063a80` calls.
- When both gates accept, the call at `0x180067b46` receives the application
  map, primary auxiliary map, and process-global auxiliary counter. The call at
  `0x180067ba9` passes no application map, receives the secondary auxiliary map,
  and uses a stack-local copy of the primary call's entry counter. The first
  call advances the global counter; the second advances only its local copy.
  Both running averages therefore use the same entry counter value.
- Primary-map mutation completes before secondary-map mutation, then the common
  gain-composition tail consumes the updated or retained maps. When the temporal
  gate rejects, the ratio pointer remains null; the check at
  `0x18006834f..0x180068352` therefore skips `FUN_180067050` at `0x180068377`.
  Temporal rejection advances neither counter and performs no persistent
  calibration-map commit. When both gates accept, `FUN_180067050` runs after
  gain composition, increments the workspace sample count up to 400, and may
  normalize the application map after both auxiliary updates have consumed
  their entry planes.
- The ready pointer is descriptor slot 5. `FUN_1800668f0` always fills that slot
  with global RVA `0x1efbfc`; the only direct xrefs to the global are descriptor
  construction at `0x180066a65` and `0x180066a6c`. No generation initializer,
  profile initializer, exported entry point, or teardown writes the global.
  It is zero-initialized by PE loading, then survives calibration generation
  replacement and mask-admitted/mask-rejected calls until DLL unload/process
  exit.
- At `0x1800679f2..0x180067a05`, `R10` points to auxiliary-map sample-count
  global `DAT_1801efbf4`, `RCX` points to the workspace sample count at
  `DAT_180219670`, and `RAX` points to ready global `DAT_1801efbfc`.
  Initialization global `DAT_1801efbf8` is a separate input to
  `FUN_1800672e0` and is not read by this transition.
- In a clean native lifecycle, mask- and temporal-accepted normal calls advance
  both workspace and auxiliary counts. Mask or temporal rejection advances
  neither count. The post-render path can advance the auxiliary count with its
  temporary workspace count fixed at 5. None of these paths creates auxiliary
  count zero with workspace count greater than 5.
- A normal adapter setup refresh loads calibration before `preprocessor_init`.
  If the loaded workspace sample count is zero, the first subsequent
  `FUN_1800672e0` call clears the auxiliary count before this transition. A set
  transition therefore requires a pre-existing calibration blob with workspace
  sample count greater than 5 while the process auxiliary count is zero. The
  adapter's only direct save path runs immediately after setup initialization,
  so a clean zero-state lifecycle does not produce such a blob.
- Both-gates-accepted subtype-12 frames pass the ratio plane produced by
  `FUN_180063a80` to `FUN_180067050`. Its update covers every sample, including
  the outer and second-from-edge columns.
