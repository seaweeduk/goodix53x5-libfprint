# FUN_180020b30

## Identity

- Binary: `GoodixEngineAdapter.dll` 2.0.310.900
- Address: `0x180020b30`
- Logged name: `EngineAdapterIdentifyFeatureSet`
- Role: compare the current processed feature set against WBF storage records
  and return the first match or terminal no-match result.

## Operation Path

`WbioQueryEngineInterface` publishes this function in the
`EngineAdapterIdentifyFeatureSet` slot. It queries storage, iterates records in
order, and calls `FUN_180033850` for each record with its original index and the
total count. That path reaches `FUN_18002e360`, which unpacks each record into
the corresponding handle-array slot. Only the final loaded record invokes
exported `identifyImage` over the complete array. This is not one extraction
and one single-gallery export invocation per storage record.

The function stops when engine-context match byte `+0x11c` becomes nonzero and
copies identity/subfactor/payload outputs from the stored record at the returned
matched index, not the current storage iterator position. Local records have
stride `0x40`; the public identity copy is `0x4c` bytes. The same selected
record supplies context subfactor `+0xa0` and identity `+0xa4`. If no candidate
matches and no stronger error is retained, it returns `WINBIO_E_UNKNOWN_ID`
(`0x80098003`). Candidate comparison can separately retain bad-capture detail
such as `0x80098008`.

## Iteration And Failure

The storage count and iteration index are 64-bit; comparison receives their
low 32 bits. Records remain in storage enumeration order without sorting or
compaction. Storage first/get errors terminate. Compare errors other than
`0x80098005` and `0x80098008` terminate; bad-capture status is retained across
subsequent storage-next handling. Storage-next `0x80098020` ends enumeration
and restores the retained bad-capture status. Other storage-next errors
terminate.

Context dword `+0x158` gates the retry count: zero selects no extra pass;
otherwise byte `+0x154` supplies the number of extra passes. A nonmatching pass
restarts at storage-first while the completed-pass count is at most that value.
Each pass reloads the ordered gallery array and reaches the final-load export
gate again. This function does not acquire another sensor sample or preprocess
the current image between passes. A match exits without another pass.

`EngineAdapterAttach` (`FUN_18001e5b0`) copies these fields from configuration
byte `+0x427` and dword `+0x428`, respectively. `FUN_1800054e0(0)` returns
configuration base `0x1800f1000`. Both compiled values are zero. Configuration
loader `FUN_1800039b0` can replace them with registry values `Retry` and
`RetrySwitch` under `HKLM\Software\Goodix\FP\`, at `0x1800041af` and
`0x18000420c`. Thus the compiled-default path performs one matching pass.

`0x8009801f` is translated to `0x80098003`. The function has no cancellation
poll inside either the storage loop or the matching export. Template study and
storage update are separate later callbacks, not part of this function.

## Reference Lifetime

This function neither consumes the raw setup frame nor clears preprocessing.
Reference selection occurred earlier in `EngineAdapterAcceptSampleData`
(`FUN_18001f610`). A success or no-match result therefore has no direct effect
on the retained profile-9 TX-on image base. A later probe uses the same
preprocessor state unless the USB/HAL sample carries the one-shot refresh marker
or the adapter has detached.
