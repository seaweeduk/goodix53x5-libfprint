## Profile-9/Type-12 Contract

`FUN_180030c40` passes the algorithm-profile index from engine context `+0x70`
by pointer (the vendor log calls it `sensorType`) and forwards context bytes
`+0x132/+0x133` as the two enrollment overlap thresholds. This function copies
the thresholds without arithmetic or range conversion to unsigned byte globals
`DAT_1800f240c/DAT_1800f240d` at `0x18002b467..0x18002b483`.

Normal profile-9/type-12 attach sources context `+0x132/+0x133` from
configuration bytes `DAT_1800f1421/DAT_1800f1422`, whose values are
`0x55/0x4b` (85/75). These attached values are the thresholds consumed by
`FUN_18002d4b0`; the second global's pre-attach image byte `0x46` is overwritten
before normal enrollment.

The function also copies the algorithm-profile index unchanged to
`DAT_1800f2408`, passes that same value to `ppp_param_init`, and uses it to select
dimensions. On the profile-9/type-12 path this forwarded value is **9**, not the
packed preprocessing sensor type **12**. Profile 9's `ppp_param_init` table row
selects sensor type 12; the outer configuration path selects profile 9, not USB
IDs. See [FUN_18002bfa0](FUN_18002bfa0.md) for the adapter dimension-table use of
`DAT_1800f2408` and the profile-index/type distinction.
