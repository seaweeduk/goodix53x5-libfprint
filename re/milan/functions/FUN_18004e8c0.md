## Exact Behavior

This path is entered only when retained reference count is greater than 20. Its
source is the 88x108 retained `profile9_history_reference`. Its byte mask is
zero at the outer three rows/columns and one elsewhere only when both the
eroded-valid mask is nonzero and:

```text
profile9_reference_age[i] * 100 >= profile9_history_count * 50
```

It first calls `FUN_18004ef90(source, qualified_mask, 9504, ..., 9000, ...)` and
writes the resulting 0/1 state to classifier context `+0x04`.

The separate threshold output from that call is passed as both the start
threshold and current-source floor to `FUN_180052b80`
(`0x18004ea46..0x18004ea67`). It is derived from the original masked histogram,
not its clipped copy used for the 0/1 state. The first cumulative bins reaching
35% and 50% of the original histogram weight give values
`t35 = minimum + (range * bin35 + 128) / 255` and similarly `t50`.
Use `t50` only when `t50 - t35 > 500`; otherwise use `t35`, then cap at 9000.
There is no histogram-mode cap on this threshold. A nonpositive signed-16
range returns the signed minimum as threshold before this cap.

`FUN_18004ef90` initializes signed minimum to 32767 and maximum to zero, then
updates them only for nonzero mask bytes. It subtracts minimum from maximum in
a word and tests that word as signed (`0x18004f030..0x18004f058`). If nonpositive,
it writes minimum, returns `0x80000003`, and leaves the separate histogram-state
output untouched (`0x18004f05a..0x18004f065`). Thus an empty mask yields 32767;
a nonnegative constant plane yields its constant, even above 9000. Neither
case reaches the ceiling. The caller initializes the histogram-state output to
zero and continues with the threshold despite this return status. For a positive
signed range, the ceiling uses a signed comparison against the caller's 9000
argument after percentile-gap selection (`0x18004f2b1..0x18004f2c3`).

It then uses `FUN_180051bd0`, `FUN_180052b80`, and `FUN_180051160` with temporal
configuration `[1600,768,384,0,700,800]` and score mode zero. Every nonzero
adaptive-mask byte assigns class 3 to context `+0x20`'s class plane; zero bytes
leave existing classes unchanged (`0x18004ea98..0x18004eaac`). This is assignment,
not a bitwise OR. The current counterpart is `milan_profile9_temporal_class3()`.

Finally, `FUN_1800514e0` and `FUN_180051af0` with configuration `[400,512]`
form a separate strict score mask. Its count writes context `+0x08` as 2 above
600, 1 above 300, and 0 otherwise.
- The `+0x08` count state does not become one of the three auxiliary bytes, but
  a nonzero value suppresses the fallback replacement of a zero `+0x04` state.

## Class-Plane Lifetime

The adaptive mask and score/gradient/direction planes are temporary allocations
freed before return. The class plane belongs to the caller. The later strict
score pass reuses the temporary score and mask planes, not the class plane.
Its scalar output and any secondary-state fallback do not remove temporal
class-3 assignments. In `FUN_1800508a0`, the subsequent interior low-intensity
pass preserves existing class 3 and can add further class-3 pixels
(`0x180050de0..0x180050df6`). The subtype-11-only postpass at `0x180050e12` is
not used for profile 9. Flood mechanics are documented in
[`FUN_180051160.md`](FUN_180051160.md).

The outer `FUN_18006b290` consumer counts classes 1, 2, and 3 and clears only
classes 1 and 2 from the render mask (`0x18006b350..0x18006b378`). Class-3
coverage contributes to its mode, mask-application, and classification-retry
outputs; temporal assignments are not merely internal scratch state. See
[`FUN_18006b290.md`](FUN_18006b290.md) for that publication contract.
