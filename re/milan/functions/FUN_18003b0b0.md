## Recovered Behavior

The function constructs the anti-fake candidate records at block offsets
`0x0000..0x12bf` and writes their count through the pointer to `+0x12c0`.
It scans `(x,y) = [4,width-5] x [4,height-5]` in row-major order, requires the
dense morphology byte at `dense_mask[y*width+x]` to be nonzero, and requires
the unsigned 16-bit center to be no smaller than each of the 44 offsets in table

center-minus-neighbor differences. Each difference and the accumulator are

accumulator cannot overflow.

The function allocates and zeroes exactly `400*48 = 0x4b00` temporary bytes.
It continues scanning after 400 admissions but stores no later maximum. Each
stored temporary record has signed dword `x` at `+0x00`, signed dword `y` at
`+0x04`, and the metric at `+0x18`; every other byte remains zero. Suppression
uses the metric slot itself as an invalid marker (`INT32_MAX`). For each earlier
record `i`, later records are considered in admission order. A pair conflicts
exactly when `-3 <= dx,dy <= 3` and `dx*dx+dy*dy < 10`. The lower metric loses;
equal metrics invalidate the later record, so the earlier row-major admission
owns the tie. If a later metric wins, `i` is invalidated and its inner loop ends.

The copy pass visits the temporary array in original admission order, copies
the complete 48 bytes of each survivor, and stops at 100 outputs. Thus the
published order is surviving scan order, not metric order, and the count at
`+0x12c0` is a 32-bit word in `0..100`. `FUN_1800392f0` has already zeroed the
complete `0x1abc` anti-fake object. This function explicitly zeroes only its
temporary allocation and initializes the count to zero; untouched destination
slots retain the owner's zeros.
