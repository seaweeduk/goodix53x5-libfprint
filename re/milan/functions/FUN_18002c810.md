# FUN_18002c810 — adapter preprocessing and sample admission

## Identity And Callers

`_PreProcessor_E`, `0x18002c810`, is the production adapter wrapper of
`preprocessor` (`0x180002ab0`). The engine interface table at `0x1800f2290`
routes AcceptSampleData through
`FUN_18001c5f0 → FUN_18001f610 → FUN_180032040 → FUN_18002c810`.
These calls are synchronous and expose no operation-cancellation token.

## Inputs, Buffers And Purpose

- Required status, workspace, image, descriptor-purpose and output arguments
  are checked before allocation; invalid required pointers call `abort`.
- The wrapper allocates and copies the raw frame and creates a zeroed processed
  image. Length must equal the active profile's width times height times two
  and not exceed `0x75f8`; failure writes `0x81`. Checked allocation failures
  write `0x82`. Type12 uses 19,008 raw bytes and 9,504 processed bytes.
- Both image descriptors carry the supplied purpose. Quality and coverage are
  zeroed before the exported preprocessing call.
- Identify passes purpose0, liveness0 and the caller's mode byte. Its call is
  at `0x18002cf3a`, with purpose/mode/liveness writes at
  `0x18002cefa..0x18002cf0e`.
- Enrollment sets purpose1. With its preprocessing flag set, the call at
  `0x18002cd7b` passes liveness0 and mode0. Without that flag the wrapper skips
  the export; subsequent admission still examines the retained status and the
  zeroed metric fields.
- Purpose remains distinct from preprocessing generation state. Profile9 fixes
  subtype12 and configuration field7 to zero; the purpose1 threshold arm in
  `FUN_18006c510:0x18006c747..0x18006c766` requires field7 equal to2 and cannot
  change this profile's processing result. Its separate purpose1 threshold
  reduction requires configuration field5 nonzero; profile9 clears its packed
  source bit2. Both exclusions are detailed in `FUN_18006c510.md`.

## Status And Metric Admission

Identify compares the raw status with `0x29aa`, `0x7531`, and `0xc351` at
`0x18002cfb2..0x18002cfe0`. Equality to any of them writes status zero at
`0x18002cfea`. Other statuses are preserved.

Enrollment compares the same statuses at `0x18002ce7f..0x18002cead`, but equality
returns directly with the raw status, before metric admission.

Both remaining paths inspect quality at `0x18002cff0` and coverage at
`0x18002cff9`. Either equal to zero writes status `0x80` at `0x18002d00a` and
skips the calibration snapshot. The tests are equality-to-zero, not positive
threshold tests. Supported quality/coverage producers return nonnegative values.

Consequences for the type12 caller:

- Early raw rejection has zero metrics and cannot become an accepted identify
  sample when its raw status is cleared.
- A completed late retry with nonzero metrics can be admitted for identify;
  enrollment preserves that same raw retry status.
- Raw status zero with a zero metric is rejected before extraction.
- Nonzero metrics do not clear any other failure status.

With both metrics nonzero, the wrapper obtains the calibration workspace through
`preprocessor_get_CalibParam`, copies it into the adapter snapshot at
`0x18019c186`, and stores the three supplied sensor metadata bytes as words at
`0x18019c180`, `+2`, and `+4`. This does not otherwise rewrite the status.
`FUN_180032040` forwards it; `FUN_18001f610:0x180020068..0x180020076` tests the
resulting adapter status rather than the original raw preprocessing status.

The wrapper returns zero as its own function result. Sample status is the
caller-owned output word, independent of that return value. See
`preprocessor.md` and `FUN_18006d540.md` for processed-image and retained-state
publication before this admission boundary.

## Retained State And Lifetime

The export mutates persistent process globals. The wrapper has no rollback after
the call, including after sample rejection or subsequent host abandonment.
The engine interface has no operation-cancellation entry. Clear-context
(`FUN_18001f090 → FUN_180031330 → FUN_18002b960`) ends enrollment and frees
adapter buffers; it does not restore a pre-call preprocessing snapshot. Detach
is teardown rather than an operation rollback.
