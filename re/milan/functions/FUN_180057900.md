## Class Selection And Guide Ownership

Either incoming word0 or word1 above8 skips all sibling construction and goes
directly to the bonus. Equality8 still enters.

When word1 is below4, `FUN_180075220` builds two class-filtered sets from the
feature owners, configuration at `+0x18`, and the same distance/layout matrices
produced by `FUN_18005a3c0`. It consumes the stored `+0x118` partition endpoints;
record byte12 is a separate class field, not that partition or the foreground
bits. `FUN_1800770e0` reads the supplied matrix eligibility/layout and applies
the configured tail limit16. See `FUN_180075220.md` and `FUN_1800770e0.md`.

Both class affines are initialized to identity before their independent
`FUN_18005b900` calls. The first class wins only on a strictly greater filtered
count. A tie chooses the second affine (`0x180057afb..0x180057b1a`). The chosen
count raises word0 only when strictly larger (`0x180057b1e..0x180057b22`),
**before** the guided-count-at-three gate. This does not write word1, word2,
bitmap/record metrics or the separate ranked affine. The selected guide is local.

With incoming word1 at least4, neither class search runs: selected count is word1
and the guide is the incoming ranked affine.

At selected count>=3, `FUN_1800749c0 -> FUN_180075dc0` builds a fresh guided set
using `[23,47,40,38,0,16]`, stored partitions and the guide. Unlike the class
search it independently computes the minimum of the two tail Hamming distances,
admitting at inclusive<=16, with wrapped inverse/scan arithmetic. It then calls
`FUN_18005b900` with an identity-initialized output affine.

Only a guided filtered count **strictly greater** than selected count reaches
bitmap ranking or strength admission (`0x180057bc1..0x180057bc4`). Thus a missing,
losing, tied or rejected guided result does not undo earlier word0 publication.

## Independent Bitmap Ranking And Strength Admission

On a greater guided count, `FUN_180071d40` and `FUN_180070e90` execute first.
Bitmap ranking requires signed overlap score>128 and strict larger signed rank:

```text
guided_detail - 4*(guided_scale_penalty + guided_orthogonality_penalty)
  > candidate[5] - 4*(candidate[12] + candidate[13])
```

Arithmetic wraps at32 bits. Scale penalty is unsigned `average_scale-234 >47`;
orthogonality penalty is absolute normalized dot>=0x147b. A rank tie or score128
retains all incumbent bitmap and affine state. A win at
`0x180057ca7..0x180057cf4` writes only words4,5,9,12..14 and the separate affine.
Coverage word9 uses configuration[12] (246) times returned coverage, low dword
then arithmetic right shift8. Strong orthogonality word14 is dot>=0x28f6.

Next `FUN_180074e80` computes a local11-word record result from the **guided
affine and guided count**, irrespective of bitmap rank. A second diagnostic call
supplies the separate strength test at `0x180057d47..0x180057d84`:

```text
average_scale in inclusive [234,281]
&& absolute_normalized_dot_q16 < 10486
&& ((topology > 40 && matched_records > 23)
    || (topology > 45 && matched_records > 11)
    || topology > 75
    || guided_count > 16)
```

Folded rotation and geometric percentage are not strength operands. Admission
writes word2, words10/11, and all words66..76 from that local result. Only66..70
can be nonzero for type12. It does **not** replace the ranked affine or bitmap
fields when their independent comparison lost.

Consequently a strength-rejected rank winner retains its new bitmap affine but
the prior record metrics/counts. A strength-admitted rank loser retains incumbent
bitmap affine while publishing guided-affine record metrics and sibling count.
No selected-count, bitmap, or record owner may be inferred solely from another.
Neither operation materializes affine words15..20; those remain caller-owned.

## Final Bonus And Caller Admission

The common tail (`0x180057dee..0x180057e37`) always runs. If word10>30:

1. If word70<10, increment words0 and1 independently.
2. Clamp both counts to42, even when no increment occurred.

Word2 is never incremented or clamped by this tail. Equality topology30 or
distance10 does not increment. It consumes the **published record owner**, which
can differ from the ranked bitmap owner; a rejected guided record result has no
effect on the bonus. Ordinary incoming correspondence counts are already0..42.

The caller subsequently assigns word1=max_signed(word1,word2), retaining word1
on equality, and requires word1>4 and word10>=30 before affine admission and
overlap recomputation. These gates run after the bonus. Words0/1 can therefore
belong to class selection/prior retained count plus bonus while word2 belongs to
the admitted guided result. See `FUN_180055a40.md` and `FUN_180074e80.md`.

## Failure Handoff

Primary insufficient-pair, attempted-no-model and valid-model/zero-filtered
states all enter this function with count0. The below4 branch uses independent
class fits and never consumes the incoming affine as a guide; it can recover
only after a class result>=3 establishes its own fitted guide. Subsequent guided
count greater than that positive count also establishes a fitted model before
bitmap or record consumption. Below3 class counts do not reach guided scanning.
See `FUN_18005b900.md` for fitting validity and output semantics.

The incoming primary/alternate state follows the established deterministic
invalid-alternate policy described in `FUN_18005a3c0.md`. No private
indeterminate alternate scratch is an input to sibling construction.
