# FUN_18001ed10

## Identity

- DLL: `GoodixEngineAdapter.dll`
- Address: `0x18001ed10`
- Logged name: `EngineAdapterDetach`
- Role: engine/preprocessor lifetime teardown callback.

## Findings

- The callback is stored in the adapter callback table at `0x1800f22b8`, after
  `EngineAdapterAttach` at `0x1800f22b0`, and has no direct in-DLL code caller.
- Frees the engine-owned `0x1c` object at context `+0x190` and the `0x4c98`
  auxiliary object at `+0x198`.
- Calls `_Detach_Unify` (`FUN_180030f40`) at `0x18001ee7d`.
- `_Detach_Unify` calls `FUN_18002b7e0`, whose `0x18002b84a` call reaches the
  preprocessing exit routine at `0x180002a00`. That routine first writes zero
  to setup-ready dword `DAT_180249afc`, then clears the preprocessing workspace
  at `DAT_180219670` for `0x3048c` bytes, and returns zero.
- `_Detach_E` also frees and nulls the image allocation at `DAT_180196c80`,
  finishes and nulls enrollment object `DAT_18019b968`, and frees and nulls
  temporary allocation `DAT_18019ba08`. These are separate from the
  process-global preprocessing/classification owners.
- On successful detach it releases cached templates, frees the complete engine
  context, clears adapter field `+0x38`, and restores adapter state `+0x08` to
  `-1`.

## Lifetime Consequence

The preprocessing workspace survives multiple probes and biometric operations
only while this engine attachment remains alive. It does not survive adapter
detach, even if the lower usbinterface hardware context remains attached.

Process-global ownership is distinct from attachment ownership. The classifier
and gain globals outside the cleared `0x3048c` workspace
are not reset by `preprocessor_exit`. Setup readiness at `DAT_180249afc` is
explicitly cleared outside that workspace; it must not be conflated with the
gain-ready state owned by the live calibration wrapper. Classifier import state,
live history and extraction history remain process-owned across this call.
The workspace's serialized history packet is cleared even when those live
owners survive; see `preprocess_load_calidata.md` for reload ownership.

Microsoft defines detach as the callback immediately before removal of the
engine adapter from the biometric-unit processing pipeline. It is not the
normal per-operation reset; `EngineAdapterClearContext` prepares the reusable
pipeline for each new operation without removing its context. Successive
operations can therefore ordinarily share one attachment even though idle,
power, service, or device-removal events may eventually detach it. See
<https://learn.microsoft.com/en-us/windows/win32/api/winbio_adapter/nc-winbio_adapter-pibio_engine_detach_fn>
and
<https://learn.microsoft.com/en-us/windows/win32/api/winbio_adapter/nc-winbio_adapter-pibio_engine_clear_context_fn>.

## External Invocation Boundary

The adapter exports its callback table to WBF; it contains no scheduler for its
own attach/detach callbacks or host module unloading. The callback's teardown
effects are therefore distinct from the host-selected idle, power, and removal
events that invoke it. Retained process globals require the same loaded module;
ordinary operation clear does not remove that module or its engine context.
