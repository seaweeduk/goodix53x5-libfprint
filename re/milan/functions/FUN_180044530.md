# FUN_180044530

## Identity

- Binary: `GoodixEngineAdapter.dll` 2.0.310.900.
- Address/body: `0x180044530..0x1800446ee`, configurable masked image quality
  combiner.

## Call Graph

- Callers: `FUN_180043cb0` and `FUN_180044300`.
- Substantive callees: `FUN_180043d90`, `FUN_180044b50`, and optionally
  `FUN_18007e4b0`.

## Behavior

- Copies the supplied mask and computes its propagated-valid Q16 coverage as
  `floor(nonzero_count * 0x10000 / pixel_count)` with signed-32 arithmetic.
- The coverage count reads the supplied mask before `FUN_180043d90` runs.
  That callee receives the allocated copy, not the original validity mask;
  its mask rewrites cannot change the already computed propagated coverage.
  The copied mask is released before this function returns.
- Obtains the unadjusted base patch score from `FUN_180043d90` and returns that
  base regardless of later output adjustment.
- When configured component adjustment is enabled and the base is strictly
  below its cutoff, calls `FUN_180044b50`. A component percentage strictly below
  its cutoff produces factor `floor(percent * 256 / cutoff)` and applies two
  sequential `score = score * factor >> 8` reductions. A percentage at least
  the boost cutoff adds the configured boost.
- When raw correction is enabled, calls `FUN_18007e4b0` at strict gradient
  threshold 120 to obtain raw Q16 coverage. If
  `propagated_valid_q16 - raw_q16 > 0x3333`, it applies two sequential
  `score = raw_q16 * score / propagated_valid_q16` reductions. Equality does
  not reduce the score.
- Writes adjusted quality through the first optional output. Percentage
  coverage is `raw_q16 * 100 >> 16` when raw correction is enabled, otherwise
  propagated-valid coverage. This is truncation, not nearest rounding.

`FUN_180044300` supplies configuration `[1,1,1,35,70,25,0]`: base `<70` and
component `<35` select the quadratic reduction, the nominal `>=25` boost is
zero, and raw correction is enabled. `FUN_180043cb0` instead supplies its
residual-mask configuration: base `<70`, component `<25`, and a 15-point boost
at component `>=30`.

For subtype 12, let `P` be the base patch score, `F` the component percentage,
`V` propagated-valid Q16 coverage, and `R` threshold-120 raw Q16 coverage. The
complete adjusted producer is:

```text
Q = P
if F < 35 and P < 70:
    factor = floor(F * 256 / 35)
    Q = floor(Q * factor / 256)
    Q = floor(Q * factor / 256)
if V - R > 0x3333 and V != 0:
    Q = floor(R * Q / V)
    Q = floor(Q * R / V)
if Q > 0:
    Q = Q + 7
quality  = clamp(Q, 0, 100)
coverage = floor(R * 100 / 65536)
```

The validity and raw-coverage producers consume the same final byte image but
different predicates, so neither value bounds the other. The live caller's
later coverage gate is not redundant with either combiner reduction; see
`FUN_180044300` for the distinction between direct and live scalar outputs.

On the fixed 108x88 byte-image boundary, all combiner products fit signed
32-bit arithmetic: both Q16 coverages are in `0..65536`, base patch score is
in `0..100`, and the largest coverage/score product is 6,553,600. A selected
raw correction implies positive propagated-valid coverage because raw coverage
is nonnegative. The two signed divisions truncate separately; combining them
into a single division changes rounding. The final percentage conversion
truncates the already-truncated Q16 fraction, rather than counting pixels
directly in percentage units.

The base patch scorer always receives fixed-threshold mode 1. Its rewritten
mask retains the valid portions of 24x24 footprints around scored centers
whose integer-percent score is at most the histogram median. The component
fraction uses that rewritten mask; raw coverage uses the original byte image
and does not consume either mask. Rewriting does not change the base score
returned to the helper-status classifier.
