## Profile-9 / Type-12 Behavior

The function requires a byte image. A different element type writes zero to
both outputs and returns `0x80000003`. For a byte image it allocates a dense
mask, builds it with `FUN_1800446f0`, and calls `FUN_180044530` with this fixed
seven-word configuration:

```text
[raw_correction=1, patch_rewrite=1, component_adjust=1,
 component_cutoff=35, base_cutoff=70, boost_cutoff=25, boost=0]
```

The combiner writes a preliminary quality and percentage coverage and returns
the unadjusted base patch score. A base score strictly below 45 selects helper
status `0x7532`; equality 45 does not. Subtype 12 adds 7 only when preliminary
quality is positive. Zero remains zero. It then clamps quality and coverage
independently to `0..100` and writes them as signed 32-bit values. Those values
are final for `getQuality` and remain provisional for live preprocessing.

The `0x7532` result is quality metadata, not the exported live-preprocessing
result. `getQuality` ignores it. `FUN_18006d540` records it in optional result
bit 2 and later returns its independently owned preprocessing status.

`FUN_18006d540` also owns one final policy after this function returns: coverage
`<=5` forces live-preprocessing quality to zero, while coverage 6 is unchanged.
Coverage itself is preserved. Direct `getQuality` does not apply that gate.

## Scalar Publication And Extraction

For positive type-12 quality, the `+7` store at `0x18004448f` jumps directly
to the clamps at `0x180044471`. It does not execute the coverage-squared
attenuation at `0x18004444d`. The zero-quality path also leaves zero unchanged.
The combiner's raw-Q16 correction and the live caller's coverage gate are
separate transformations, not this attenuation.

Exported `getQuality` (`0x180002400`) consumes the complete byte image, passes
quality as the second dword of its output pair and coverage as the first, and
stores their low bytes in image descriptor `+0x28` and `+0x29` respectively.
It ignores the helper status. Exported `preprocessor` writes the same descriptor
fields from its final live scalars, after the coverage gate. Neither descriptor
field is part of the pixel buffer.

`identifyImage` reads those descriptor bytes with unsigned loads and supplies
them as quality/coverage to `FUN_18004ae70`. That extraction helper does not
recompute image quality: it stores its argument 3 at feature `+0x11c`
(`0x18004b1c9`) and argument 4 at `+0x120` (`0x18004b1d6`). The same supplied
coverage determines the type-12 record limit, `max(1, coverage * limit / 100)`.
Thus extracted scalar provenance depends on which descriptor publisher ran
last, not on the extracted bitmaps, record counts, or a cropped-image quality
calculation. See `FUN_18006d540` for live ordering and `FUN_180044530` for the
image-derived arithmetic.

The low-coverage gate is not implied by the combiner. For example, the native
arithmetic admits propagated-valid Q16 14680, raw Q16 2889, base patch 96,
and component percentage 2: the base bypasses component reduction and the
valid-minus-raw difference 11791 bypasses raw correction. Direct quality clamps
to 100 and coverage truncates to 4, while live publication is 0/4. The
corresponding initialized image construction uses setup 2000 outside rows
23..65/columns 31..73 and 3799 inside; live is 2000 outside and, inside, adds
alternating two-column +/-100 stripes plus repeating `[-88,44,44]`. Replacing
that repeat with `[-65,33,32]` gives direct/live 100/6. The gate changes only
the scalar, not finalized image publication or selected-workspace commit.
