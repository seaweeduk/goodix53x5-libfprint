## Profile-9 / Type-12 Behavior

The function requires a byte image. A different element type writes zero to
both outputs and returns `0x80000003`. For a byte image it allocates a dense
mask, builds it with `FUN_1800446f0`, and calls `FUN_180044530` with this fixed
seven-word configuration:

```text
[raw_correction=1, patch_rewrite=1, component_adjust=1,
 component_cutoff=35, base_cutoff=70, boost_cutoff=25, boost=0]
```

The combiner writes a preliminary quality and percentage coverage and returns
the unadjusted base patch score. A base score strictly below 45 selects helper
status `0x7532`; equality 45 does not. Subtype 12 adds 7 only when preliminary
quality is positive. Zero remains zero. It then clamps quality and coverage
independently to `0..100` and writes them as signed 32-bit values. Those values
are final for `getQuality` and remain provisional for live preprocessing.

The `0x7532` result is quality metadata, not the exported live-preprocessing
result. `getQuality` ignores it. `FUN_18006d540` records it in optional result
bit 2 and later returns its independently owned preprocessing status.

`FUN_18006d540` also owns one final policy after this function returns: coverage
`<=5` forces live-preprocessing quality to zero, while coverage 6 is unchanged.
Coverage itself is preserved. Direct `getQuality` does not apply that gate.
