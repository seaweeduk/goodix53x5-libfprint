## Cache-Queue Allocation On Unpack

The allocator always resets all 20 ranks at `+0x8db0` to `-1`. For nonlegacy
types including type 12, it allocates the 20 cache feature bodies only when
serialized state `+0x8e00` is not 1. Thus type-12 state 0 reconstructs an empty,
allocated queue, while state 1 reconstructs no queue owners. Queue bodies and
ranks are not decoder inputs.

Allocation failure unwinds both gallery and cache owners. Direct controls show
state 0 unpack as allocated/occupied `20/0` and state 1 as `0/0`.

The allocator tests only serialized state `==1`. Noncanonical state 2 therefore
also allocates 20 owners, although production queue callers require state 0 and
will not use them. Counter `+0x8e04` does not affect allocation. Unit-6 direct
round trips independently cover state 0/1, counters 7/`UINT32_MAX`, and state 2.
