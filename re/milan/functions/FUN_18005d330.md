## Complete Profile-9/Type-12 State Machine

The helper initializes the ordinary type-12 matcher policy, passing `R9D=1` to
`FUN_18005e230` via the move at `0x18005d39c`. It then seeds a 20-element ring
with the primary selected gallery index and scans occupied cache slots in
physical order `0..19`; ranks control occupancy/age but not traversal order. For
each occupied slot it calls `FUN_180055a40(queued_feature, current_gallery, ...)`.
Only recognition evidence with its acceptance field nonzero reaches
`FUN_1800469f0` against the already primary-mutated gallery.

If the queued study selector returns a nonnegative selected index, the helper:

1. writes follow-up status 5;
2. removes the consumed entry by setting its rank to `-1`;
3. decrements every rank greater than the consumed rank;
4. appends the returned selected gallery index to the modulo-20 continuation
   ring;
5. stops the current physical scan if that selected index equals the stack-local
   trigger set at `0x18005d447` and compared at `0x18005d56f`; otherwise it
   continues and then processes later ring items.

A selected return `-1` leaves the entry and ranks unchanged. The helper itself
does not clear the feature body; its preallocated owner is reused by the next
enqueue. Empty and no-positive queues return status zero.

Controlled exported calls prove one occupied physical slot is consumed and
causes feature count `9 -> 11` (primary append plus queued append), while two
occupied slots at physical indices `0` and `5` are visited in that order,
consumed, and cause `9 -> 12`. Breakpoint evidence records both queued re-matches
selecting the primary-appended gallery index 9. Both calls export and adapter-pack
action 5 exactly. A one-entry nonmatching control leaves rank 0 occupied and
preserves primary action 1.

An independent authoritative sequence-3 control supplies the normally extracted
retained live probe with 115 active 56-byte records, not an unpacked substitute.
Production enqueue followed by untouched study consumes occupancy `1 -> 0` and
exports 5 in two byte-identical fresh processes.

For profile 9/type 12, independently owned does not mean byte-preserving. The
earlier queue `P->Q` copy passed nonzero transform mode to `FUN_180037690`, so

bytes `36..39` or `48..55`.

Matcher exit semantics are not queue-specific. Direct positives immediately
increment every direct-positive gallery feature. Aggregate no-direct success
increments contributor features but keeps selected index `-1`, so the selector
returns `-1`, the entry remains, status stays zero, and the matcher writes are
not rolled back. Aggregate rescue adds no new write but may provide a selected
index that can commit an ordinary action. Positive fallback adds no write and
keeps selected index `-1`; rejection reaches no selector. An entry is consumed
only after the selector returns nonnegative.

Ordinary selector normalization remains immediate: a capacity-reaching append
and actions 3/4 call `FUN_180047120` before continuation, so later ring items see
normalized state; below-capacity append and action 2 do not. Final type-12 order

## Sparse V3 Traversal Correction

The profile-9/type-12 action-5 traversal contract is stricter than object handoff.
Live `0x38`-byte record ownership is keyed by physical feature slot and only
selects the record source for that slot; it must not promote or otherwise reorder
the slot. At the queued call at `0x18005d4b3`, `FUN_180055a40` always traverses
the unfinalized order already stored at gallery `+0x87e8`. Append writes the
old-count feature index at the tail at `0x18004585e`; replacement leaves the
target in its existing order position. `FUN_1800607b0` is absent from this helper
and runs only at `FUN_180044fc0:0x1800451c1`, after queue exhaustion.

The sparse v3 12-stage replay at epochs `8`, `12`, and `19` exposed this
boundary in an intermediate experiment: removing the synthetic live-owner
prefix without changing the matcher loop changed action `5` to `0` and removed
the candidate. That result is historical evidence for the stored-order rule,
not a defect in current production.

Production commit `5cdb2a12` completed the correction. The matcher now always
reads traversal indices from packed `tail_state/+0x87e8`; sparse live owners are
looked up by that physical feature index and only replace the record source and
partition count for the indexed feature. Queue physical slot is not gallery
record provenance: `FUN_18005d330` passes the queued owner pointer itself as the
probe and the continuation value as matcher configuration word 14. Current
`GoodixStudyFollowupContext` preserves each primary or queued mutation at its
returned gallery feature index, while the packed feature and live copy both
derive their record count from the same transformed probe owner.

Full-record normalization, stored-order traversal, and trigger propagation were

to Windows, and the independent v5 campaign had 45 replayable operations with
