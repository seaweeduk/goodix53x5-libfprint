## Consequence For Oracle Replay

The production persistence boundary is `study update code > 0`, not merely a
successful `identifyImage` call. Match-time lifecycle mutations and a
zero-update after-study object must remain diagnostic artifacts and must not be
fed into the next production-persistence replay row.

## Positive-Code And Failure Closure

Assembly uses `update >= 2` only to call the no-op `identifyUpdate`; its actual
pack gate is independently `update > 0`. Direct calls with updates 2 and 3 both
return the same action and embed the exact exported post-study template at outer
offset `0x30`. Update 0 does not pack and returns zero.

Wrapper allocation failure sets adapter error `0x8001`, skips packing, and still
deletes all cached candidate handles. The return from `templatePack` is ignored,
so no action rollback occurs on encode failure. The helper finalizes the outer
CRC and reports the positive action regardless. This makes caller-side pack
validation and transactional persistence mandatory in a native implementation.

## Queue And Action-5 Boundary

Action 5 follows the same `update > 0` pack branch, the `update > 1`
`identifyUpdate` no-op call, and unchanged wrapper return as codes 2/3/4. A
controlled exported action-5 template is embedded exactly at wrapper offset
`0x30` and the adapter reports update 5.

The unconditional 200-handle cleanup runs after both positive and zero updates.
It destroys every live template and its cache owners. Together with omission of
queue bodies from `templatePack`, this proves the queue is not Windows service
state surviving adapter transactions; it exists only during the current live
identify/study/update operation.

## Action-0 Publication Control

Unit-5 breakpoint traps confirm that update 0 never reaches `templatePack` at
`0x18002bdcd`. The helper allocates and zeroes scratch space sized from the old
record, copies that zero buffer to its caller, reports update 0, and then deletes
the gallery handle and all transient queue owners in the unconditional 200-slot
cleanup. Every action-0 wrapper is entirely zero; a positive action-1 sanity
control reaches `templatePack` exactly once and produces a nonzero wrapper.

Thus transient action-0 order, tail, retained-state, shutdown, or late-enqueue
mutations cannot become an adapter publication. Any manual pack used to inspect
them would be test-only and is not production behavior. Evidence is under
`study-action0-finalization-unit5-v1`; confidence is high.

The native diagnostic API intentionally cannot call the template codec. Unit-5
controls report null update output for all nine action-0 cases and a positive
candidate only for action 1, preserving this publication gate.
