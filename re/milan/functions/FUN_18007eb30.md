## Recovered Behavior

It allocates an output matrix matching the input, builds local enhancement state
with `FUN_18007ebe0`, then writes the enhanced image through `FUN_18007f2c0`.
This is both the source of descriptor gradients passed into `FUN_180049b90` and
the first matrix passed to extraction classifier `FUN_180048260` at
`0x18004b4ba`.

The profile-9/type-12 input is the centered `104x88` byte image. The wrapper
passes radius `6` to `FUN_18007ebe0` through the fifth stack argument and keeps
the resulting orientation bytes in its 19,600-byte stack workspace. It then
passes orientation, the original input, the newly allocated output payload,
width, and height to `FUN_18007f2c0`. The returned matrix owns the enhanced
payload; the orientation workspace is transient. The DLL assumes its internal
allocation succeeds and has no failure result.

The matrix header carries signed dword width at `+0x00`, height at `+0x04`,
row-byte stride at `+0x08`, payload byte count at `+0x0c`, element size at
`+0x10`, and the payload pointer at `+0x18`. `FUN_180068700` allocates the
32-byte header and payload together; for this byte-image path the element size
is 1, stride is 104, and payload size is 9152. `FUN_180068b70` releases the
allocation through a pointer-to-matrix and clears that pointer.

The input payload is not modified. The orientation producer completes before
the seven-tap consumer starts, and the output allocation is distinct from both
input and orientation. Current `goodix_milan_feature_enhance` exposes both
planes to its caller; `feature_extract_records` consumes the enhanced plane
and eventually frees the otherwise transient dense orientation.

The orientation and interpolation arithmetic are documented under
`FUN_18007ebe0` and `FUN_18007f2c0`.
