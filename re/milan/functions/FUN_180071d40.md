# FUN_180071d40

## Identity And Interface

- Body: `0x180071d40..0x180072199`.
- Role: warp a source bitmap into a target frame, classify primary and optional
  secondary overlap, and return the selected score.

```c
int32_t FUN_180071d40(
    image_desc *source,
    image_desc *target,
    const int32_t affine[6],
    const int32_t mode[3],
    int32_t *primary_score_or_null,
    int32_t *secondary_score_or_null,
    int32_t *selected_detail_or_null,
    int32_t *primary_coverage_or_null,
    int32_t context_count,
    int32_t *max_filtered_mismatch_count_or_null,
    mask_configuration *mask_configuration_or_null);
```

The return is the selected primary/secondary score. Arguments five and six
receive raw pass scores, argument seven receives selected detail, argument eight
receives primary coverage, and argument ten receives the maximum filtered
mismatch count from the two passes. Argument eleven controls an independent
masked reclassification path.

## Inputs And Callees

The affine is six signed Q8 dwords `[a,b,tx,c,d,ty]`. The image descriptor has
width/height at `+0/+4`, primary matrix owner at `+8`, secondary owner at
`+0x10`, and bitmap fields consumed by `FUN_1800721a0` at `+0x28`.

Argument one is the warped source and argument two is the direct target.
The primary context puts argument-one `+8` at context `+0`, argument-two
`+8` at context `+8`, and their respective expanded masks at `+0x10/+0x18`.
`FUN_1800717e0:0x180071818..0x1800718c4` expands and warps context `+0`;
`0x1800718eb..0x180071918` supplies the second bitmap as the direct classifier
input. Secondary uses the same order with descriptor `+0x10`. The current
`goodix_milan_match_overlap_metrics_with_context(enrolled, probe, ...)` interface
has the opposite positional order: native receives probe first, enrolled second.

Mode is a separate three-dword descriptor. When `mode[0] != 0`, this function
rounds and halves affine translations and changes the internal interpolation
descriptor to `[3,2,3]`. `mode[2]` participates in selected-detail relatching.
Translation scaling is signed `(translation + 1) / 2`, truncating toward zero;
it is not an arithmetic right shift for negative values. Thus a full-resolution
translation of `-5632` becomes `-2815` before inverse interpolation.

Direct callees are:

- `FUN_1800721a0`, which expands packed one-bit bitmap fields.
- `FUN_1800717e0`, the primary and secondary warp/classification pass.
- `FUN_180072710`, optional masked reclassification.
- `FUN_180068b70`, descriptor cleanup.
- `FUN_180003800`, temporary mask allocation.
- `FUN_18008a9c0`, temporary bitmap copy.
- `free`, for temporary mask buffers.

`FUN_1800721a0` derives packed rows from `(width+3)>>2` and
`(height+3)>>2`. Mode zero expands each packed sample to `4x4`; mode one expands
to `2x2`. Bits are consumed least-significant first, and trailing columns reuse
the last packed byte.

`FUN_18006f390`, beneath `FUN_1800717e0`, transforms all four image corners,
sorts coordinates, clamps the destination rectangle, allocates cropped matrices,
and records crop origin in context words six and seven. Before inverse sampling,
it subtracts `origin_x*256` and `origin_y*256` from affine translations.

`FUN_180068bb0` computes inverse coefficients in Q10 from a wrapped dword
determinant. Out-of-bounds pixels use the destination's initial byte. Four valid
neighbors use bilinear interpolation with `0x80000` before shifting by 20;
boundary pixels average only valid neighbors. Negative floor coordinate `-1`
can enter that boundary path. A singular determinant continues with the helper's
literal inverse-accumulator state `[1,0,0,0,1,0]` rather than returning an error.

## Classification

After warping, `FUN_180073540` counts pixels accepted by both validity masks:

```text
class_index = direct_target + warped_source * 2
```

Both values must be below two, so array order is `00,01,10,11` in
`(warped_source,direct_target)` notation. The helper always receives a local
filtered-mismatch output for each ordinary pass, even when this function's
argument ten is null. It can build a mismatch mask, apply two morphology
helpers, and report the resulting nonzero count. Argument ten controls only
publication to this function's caller.

The two passes share one scoring-context object. Its confidence/state field
starts at `-1` before primary and is not reset before secondary. Initialization
performed by a zero-valid primary is therefore visible to secondary scoring.
The context also retains the primary warped-validity owner at `+0x20`.
Secondary reuses that owner rather than rewarping the source validity mask;
the enclosing function releases it after both passes. This reuse requires the
same affine, crop geometry, bitmap dimensions, and source/target validity owners
throughout the invocation.

For an allocated crop with zero classified support, `FUN_1800717e0` still
executes the scoring path: requested coverage is zero and requested detail is
`-10`, from the zero match-fraction adjustment. This is distinct from a null
cropped-owner failure. The unmasked fallback supplies the same affine and
expanded validity masks to both binary passes. On equal-sized valid bitmaps,
changing primary to secondary changes the four class populations, not their
total classified support. Empty support in both passes cannot pass the
fallback's selected-detail `>195` gate; it does not undo the caller's earlier
geometry-seen latch.

## Selection Order

```text
copy affine and mode
apply nonzero-mode translation scaling and interpolation selection
construct target and source views
run primary FUN_1800717e0
publish primary score, primary coverage, selected detail, and primary mismatch
if primary failed: cleanup and return 0
if either secondary owner is absent:
    publish secondary score 0
    cleanup and return primary score
run secondary FUN_1800717e0 with the same scoring context
if masked mode is enabled: build masks and call FUN_180072710
cleanup temporary descriptors and masks
if (masked enabled ? masked failed : secondary failed): return primary score
publish secondary score and max(primary_mismatch, secondary_mismatch)
apply selected-detail relatch
return secondary only when secondary_score > primary_score
                           and secondary_detail > 195
otherwise return primary
```

The secondary-success publication order is exact: maximum mismatch first at
`0x1800720fb..0x180072108`, selected detail second at
`0x18007210a..0x180072134`, and returned-score selection last at
`0x180072137..0x18007217a`.

Score replacement uses signed strict comparisons. Equal scores retain primary;
secondary detail 195 retains primary and 196 permits replacement. Detail has an
independent rule: relatching requires a nonnull argument seven and `mode[2] != 0`
in both output variants. The mode word is copied at `0x180071dc6..0x180071dcf`
and tested at `0x18007210f` and `0x180072120`. With argument ten null, detail
can relatch to a strictly larger secondary detail only when primary score is
strictly greater than 220. When argument ten is nonnull, the larger secondary
detail can relatch without that primary-score gate. Detail may therefore change
while returned score remains primary.

Type-12 direct registration supplies mode `[1,0,0]`, context count zero and null
argument ten. It consumes primary detail and coverage even when enhanced scoring
changes the returned score; the zero third mode word forbids detail relatching.
See `FUN_180041ac0.md` for its exact count/detail/coverage admission predicate.

The optional secondary-score output receives zero when either secondary bitmap
is absent. Argument ten receives primary mismatch after the primary pass and,
after a successful secondary pass, the larger mismatch.

The optional masked descriptor has enabled word at `+0`, three output counts
at `+4/+8/+0xc`, and a borrowed class-plane pointer at `+0x10`. Its source is
the live probe's extraction projection, including its final summary overwrite.

Masked reclassification allocates two byte planes with `FUN_180003800`, a
direct `malloc` thunk. Class byte one writes zero to the first plane; class
byte two writes one. Every other class byte instead clears the **original
expanded probe validity** at that coordinate and leaves the temporary byte
unwritten. The second plane is a byte-for-byte copy of the first, including
these unwritten bytes. Neither temporary allocation is zero-initialized.
This distinction matters near invalid source pixels under interpolation; it
must not be described as an unconditional other-byte-to-zero mapping.
The allocations return at `0x180071fc7` and `0x180071fea`. The class loop's
only temporary-plane stores are `0x18007205d` (zero) and `0x180072068` (one);
the other-class store at `0x180072072` addresses expanded validity instead.
The complete second-plane copy is at `0x180072087`, followed by the masked
consumer call at `0x1800720ad`.

`FUN_180072710` receives the first temporary as warped source and its copy as
direct target, so both classification images describe the probe, not one plane
from each feature. Direct validity is the just-modified expanded probe mask.
Warped validity remains the independently owned mask produced by the earlier
ordinary bitmap pass **before** the invalid class-byte clearing. The helper
folds four class populations into `[class00, class01+class10, class11]`, with
no morphology output. The temporary planes are freed before returning; the
borrowed live class plane is not modified or freed.

Consequently a mode-5 projection's zero border can remain admitted as a warped
source even though the corresponding direct validity has been cleared. A
nonidentity affine can interpolate unwritten temporary bytes into an admitted
destination; values above one are then excluded by `FUN_180073540`. Such counts
depend on allocator contents and have no single deterministic byte-parity
value. Defined-count comparison requires that every nonzero-weight source
sample contributing to an admitted destination was written as class1 or2.
Identity affine satisfies that condition for interior admitted samples because
only the matching direct coordinate has nonzero interpolation weight; boundary
averaging must still be checked against the masks.

Integer-coordinate sampling does not itself eliminate this dependency. A
positive even full-resolution translation halves to an exact integer shift;
after crop-origin adjustment, an admitted direct coordinate can still select
an unwritten source coordinate with weight one. The earlier source validity
can admit zero-class border pixels, while the direct coordinate has class1 or2.
The summary overwrite is another source of this asymmetry: byte2 can be class1
even on the otherwise zero first row. A defined-output check must therefore
follow actual source coordinates and both validity owners, rather than merely
test affine integrality or disregard the summary pixels.

The mode3/4 producer in `FUN_180048260` writes every projected byte as one or
two before overwriting the three summary bytes. Mode5 instead projects the
preprocessor's auxiliary plane. Thus mode3/4 confines unwritten temporary
sources to nonclass summary bytes, whereas mode5 can also expose nonclass
pixels elsewhere. This is a producer constraint, not permission to substitute
an independently fabricated class plane for a live probe.

For the defined-count domain, the pixel contract is finite. The crop depends
on dimensions and the affine, not on validity byte values. Both temporary
images have the probe's dimensions, so their crop origin and adjusted affine
match the earlier source-validity warp. Each counted destination requires a
nonzero earlier warped validity byte, a nonzero class-filtered direct validity
byte, and binary source/target samples. If every source sample with nonzero
interpolation weight was written, replacing class1/2 by packed bits0/1 gives
the same bilinear sum and rounding; the edge arm averages the same in-bounds
neighbors. In that edge arm every included neighbor must have been written,
even when its bilinear weight would have been zero in the interior arm.
The four populations are folded without reordering into
`[class00,class01+class10,class11]`.

Each population and their total is at most `52*44 = 2288`. The contextual
veto's factors25 and100, and finalization's ratio numerator scaled by256,
therefore fit signed dwords. Counts are candidate-local; their only matcher
decision consumers are the contextual veto and final flag ratio described in
`FUN_180055a40.md`. Substitution of an equal count tuple cannot itself change
either consumer for a fixed surrounding candidate and class context; this does
not require treating the tuple as irrelevant.

The masked helper's return replaces the secondary pass's success discriminator:
the return value from `FUN_180072710` supplies the success test after cleanup.
Null incoming warped validity therefore skips secondary publication and score
selection, retaining the primary result. The masked helper does not check for
an empty crop after its warp call; its classifier requires a nonnull result.
With a valid masked crop, the ordinary secondary score/detail remain eligible
for publication;
the three masked counts do not replace either ordinary score.

## Queue Duplicate Caller

`FUN_1800462a0` supplies incoming probe first, newest queued owner second,
identity affine, descriptor `{gallery[+0x0c],0,0}`, context count 10, nonnull
argument ten, and null argument eleven. Descriptor word two zero selects
`FUN_1800740f0` beneath both passes; this is not the ordinary nonzero-mode or a
single low-bitmap equality call.

Insertion consumes this function's complete returned two-pass score. Secondary
replaces primary only under the strict score/detail rule above, and insertion
suppresses a new entry only when that final score is strictly greater than 190.

## Result Ownership And Failure

Each primary or alternate call's affine, context count, score, detail, coverage,
mismatch fields, and rank form one result owner. A caller choosing between
primary and alternate results must copy the complete winning result; it cannot
recompute or combine the winning affine with the other call's count. Equal rank
retains primary.

The primitive has no affine-validity argument. A caller must omit an alternate
call when its model/affine is invalid; zero or indeterminate bytes are otherwise
treated as ordinary input and may produce a score. Target/source descriptor
aliasing is permitted because this function allocates its warped/cropped
temporaries before classification. Input bitmaps are read-only.

An empty clamped geometry fails without publishing class outputs. Primary-pass
failure cleans temporary owners and returns zero. Secondary-pass failure cleans
temporary owners and returns the already published primary result. Temporary
allocation/copy failures follow helper failure exits; there is no transaction or
caller-state rollback beyond local cleanup.
