## Recovered Behavior

After maps, anti-fake data, and records, the helper maps live feature dwords to
tags `b5..be` consecutively from offsets `+0x110..+0x134`; tag `c0` comes from
`+0x14c`, and optional `c7` comes from `+0x150`. Consequently the
`FUN_1800607b0` sort keys are serialized exactly as `b5` (`+0x110`), `be`
(`+0x134`), and `bc` (`+0x12c`).

The complete `b5..be` run, including `bb` at `+0x128`, is always emitted as
five-byte tag/dword elements even when a value is zero. `c7` is different: it is
emitted only when `+0x150 != 0`, adding exactly five bytes to the feature
element. Setting `bb` to zero therefore cannot explain a five-byte size delta;
adding or removing `c7` can.

The helper writes feature bytes only. It does not read or write the template
order vector.

The anti-fake subencoder `FUN_180040840` emits a two-byte absent form when live
feature `+0x160` is null, while paired size helper `FUN_180040980` includes the
fixed populated anti-fake cost. Calling this pair before `FUN_1800392f0`
therefore cannot produce a size-consistent profile-9 probe element. After
`identifyImage` returns, `+0x160` is populated and the size/encode pair can be
used before `templateStudy` destroys the retained probe.
