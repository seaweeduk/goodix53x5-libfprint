## Binary And Body

- Entry/body: `0x180058700` / `0x180058700-0x180058ed1`.
- Inferred signature: `int32_t f(probe, metrics77, subtype, transform6, state3, status_counter, inout_flag60)`.

## Behavior

This is a late per-feature rejection/policy stage. It classifies the transform
against mode and threshold classes, combines those classes with count,
detail/coverage, context quality, and packed mode scalars, and can clear the
caller-owned flag. A final transformed-overlap-area calculation can also reject
the flag. Returning one increments the supplied counter; ordinary accepted
status is zero.

### Side Effects And Caller Continuation

The function never reads or writes flag64. It only clears flag60; it never sets
or normalizes it. Incoming flag60 values `0`, `1`, and the dispatcher-bypass
value `2` are preserved unless a clear predicate fires. Every status-one return
increments the caller-owned cumulative counter exactly once, including when
its initial value is nonzero. Status zero does not increment it.

At `FUN_180055a40:0x180056365..0x180056367`, status one skips
`FUN_1800553f0`, Q8 contribution, winner/evidence updates, direct-positive `be`,
fallback staging, and every remaining operation for that feature. The existing
flag64 stack value is therefore not consumed. Status zero continues to
`FUN_1800553f0` with flag64 unchanged and the possibly cleared flag60. The two
caller dispatcher bypasses (`flag60==2 && accumulated state0<=1`) still call
this helper and follow the same status/continuation rule.

the separate counter at `0x180058e9e`, returns one, and causes

including fallback workspace staging. The counter is passed by address from
