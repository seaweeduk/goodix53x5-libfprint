# FUN_1800392f0

## Identity

- Binary: `GoodixEngineAdapter.dll` 2.0.310.900.
- Address/body: `0x1800392f0`, profile-9/type-12 anti-fake builder.
- Callers: `enrolAddImage` at `0x18000171b` and `identifyImage` at
  `0x180001dd3`.

## Inputs

The callers pack profile geometry and chip information in the third argument:
rows are bits `14..22`, columns are bits `23..31`, and chip type is bits
`3..8`. Profile 9 decodes to rows `88`, columns `108`, and chip type `12`.
The live feature supplies a `52x44` one-byte matrix at feature `+0x20`. The
calibration workspace supplies the `88x108` setup map at `+0x9924`, primary
contrast plane at `+0x1cb64`, and selected-plane entry value at `+0x26484`.

These inputs are a same-invocation handoff. `identifyImage` passes its retained
calibration/raw arguments after successful `FUN_18004ae70` and before the first
candidate match; `enrolAddImage` does so after successful extraction and before
registration. Neither call site tests the extracted feature-record count before
calling the builder. A successful empty feature therefore still receives a
complete anti-fake object; extraction failure bypasses construction. See
`identifyImage.md` and `enrolAddImage.md` for the enclosing status paths.

The matrix at feature `+0x20` is the independently owned half-resolution
validity sample made before optional broken-mask filtering. It is not the
finalized inline mask at `+0x28` or expanded rescue matrix at `+0x140`; see
`FUN_18004ae70.md`. Neither the feature's ordinary record count nor those
ordinary records are inputs to anti-fake candidate collection. Enrichment uses
the feature's `104x88` matrix geometry, but processes the newly collected
anti-fake records, not the extractor's ordinary records.

`enrolAddImage` and `identifyImage` derive the fifth argument with wrapping
32-bit multiplication followed by signed division toward zero:

```c
uint32_t difference = (uint32_t)dac_high - dac_low;
uint32_t product = difference * t_code * 0x11b;
if (chip_type == 0x11)
  product = (difference + 0x55) * t_code * 0x146;
int32_t sensor_offset = (int32_t)product / 1000;
```

Only chip type `0x11` selects the alternate addend and scale. Type 12 uses the
`0x11b` path.

The classification copy scratch is populated on the nonzero-chip branch but is
not consumed afterward. Boundary classification instead consumes workspace
`+0x1cb64` directly. Descriptor update takes the first 9,152 contiguous
residual values under the live feature's `104x88` geometry; it does not crop two
columns from each `108`-wide row.

The workspace setup map, retained contrast, raw frame and feature source matrix
remain borrowed and unmodified. Residual construction's mask-dependent min/max
scan has no returned consumer (`FUN_18003a150.md`); the completed residual is
subsequently changed only by the impulse filter before statistics, candidate,
model and descriptor consumers. No scalar stage mutates the mask or candidate
set. The dense mask and residual must remain alive through enrichment, while
the unused classification copy has no published alias.

## Type-0 Comparison

The type-zero branch packs 104 bits per raw row from dense columns 2..105,
giving 1,144 meaningful mask bytes for 88 rows, rather than type 12's
1,188-byte full-width mask. It then subtracts two from each 48-byte anti-fake
record's X dword. Both branches clear all 2,000 mask bytes first and then call
`FUN_18004b770` with the actual subtype. Residual owner `FUN_18003a150` leaves
type 0's border zero but replicates the interior edge for type 12; filter
`FUN_18003a9b0` receives but does not consume subtype.
See `../PROFILE0-MATCH-TEMPLATE-CONTRACT.md`.

## Packed Mask

For type 12, the final mask is the complete morphology plane in row-major
`88x108` order. Dense pixel `i` maps to byte `i >> 3`, bit `i & 7`, least
significant bit first. Exactly 9,504 bits, or 1,188 bytes, are addressable; the
remaining 812 bytes retain the preceding zero clear. Candidate construction
receives the dense plane before serialization, and type 12 does not apply the
chip-zero coordinate subtraction.

The function clears the fixed 2,000-byte destination at anti-fake offset
`+0x12dc` with `memset(..., 0, 0x7d0)` at `0x18003961b..0x180039632`.
For nonzero chip type, including type 12, `0x180039740..0x180039787` packs every
bit of the full `rows * columns` dense mask. The loop has no independent bound
against the 16,000-bit destination capacity; it relies on profile geometry.
Profile 9 is within that capacity.

## One-Past Feature Read

The active producer `FUN_18006eff0` halves the `104x88` matrix, requests an
exact `52x44x1` allocation through `FUN_180068700`, and writes only indices
`0..2287`. `FUN_180068700` requests exactly `0x20 + payload_size` from `malloc`
and sets matrix data to allocation `+0x20`. No constructor, producer, clone, or
caller initializes index 2,288 as a sentinel or halo.

This function iterates destination columns `2..105` while indexing the
crop-relative 52-column source as `x / 2`. The first destination pair therefore
uses source column 1, the final pair rolls into the following row's column 0,
and the final row reaches index 2,288. At `y=86/87` and `x=104/105`, the same
one-past byte is read four times while producing the lower-right `2x2` output.

```asm
18003943d MOVSXD RAX,dword ptr [RCX]       ; matrix width (52)
180039443 SHR    ECX,0x1                   ; x / 2
180039445 IMUL   RAX,R11                   ; width * (y / 2)
180039449 ADD    RAX,RSI                   ; matrix data
18003944c MOVZX  EDX,byte ptr [RCX+RAX]    ; final index is 2288
```

The instruction normalizes the loaded byte to zero or one, but the source byte
is outside the allocation and has no native producer. Allocation adjacency can
contain allocator metadata or another allocation's contents; no
profile-9/type-12/WBF field constrains it. The reachable semantic classes are
therefore zero and nonzero, but their selection is allocator-dependent.
Enrollment preserves resulting anti-fake bytes while updating the separate pair
score at `+0x1ab4`.

The packed mask retains the morphology result of this read. Study does not
rebuild that mask: `FUN_1800469f0` changes only four matched-owned registration
dwords in the probe anti-fake object, and `FUN_1800458c0` copies the complete
object into a replacement feature. Consequently an allocator-dependent mask
can survive into a successfully packed replacement even when the gallery's
match-time mutations do not depend on the differing mask bits. See
`FUN_1800458c0.md` for the copy boundary.

## Boundary Score

The boundary score is written directly from `FUN_18003ad10`:

```asm
1800395ce CALL 0x18003ad10
1800395e3 MOV  dword ptr [RDI + 0x12d0],EAX
```

The call receives the impulse-filtered residual, dense morphology mask,
primary contrast image from calibration workspace `+0x1cb64`, and geometry
`88x108`. `FUN_18006b510` initially produces that plane, but its consumed value
is the retained publication of `FUN_18006d540`: primary selection replaces it
with the finalized metadata-encoded image; a quality-arm call to `FUN_18006c510`
first copies the selected image into it before metadata, including refined
selection. Thus refined selection does not imply that the original primary
render survives. A successful, nonretry quality arm is possible under the
component-mask predicates in `FUN_18006c510.md`.

The class-map producer reads full primary bytes, applies thresholds 26 and 231,
and uses their intensity differences in watershed priorities. The later boundary
ratio consumes its `class == 2` and `class != 0xfe` projections along with the
filtered residual. The selected-image feature mask and residual do not replace
the retained primary input at this boundary. Mask packing, record enrichment and
pair-score initialization do not overwrite boundary dword `+0x12d0`; it remains
part of the feature's serialized anti-fake object.

Boundary scoring consumes the dense `88x108` morphology mask before packing.
The type-12 field at `+0x12dc` later serializes that complete dense mask in the
row-major layout described above.

## Failure Surface

An empty feature matrix or empty collected candidate set does not bypass
`FUN_18003a9b0`. That filter does not receive the dense mask; its full-frame
replacement pass is therefore independent of foreground support. The residual
allocation is exactly 19,008 bytes without an initialized halo. If replacement
is selected at an allocation-end pixel, its flat nine-word loads have the
out-of-allocation behavior described in `FUN_18003a9b0.md`. This is separate
from the feature-matrix one-past-byte read above. The builder neither checks
the replacement predicate in advance nor repairs the filtered plane before
its later consumers.

Upstream raw admission and an all-one rendering-mask clone do not exclude
this allocation-end filter path. The bounded type-12 subtraction family in
`FUN_18003a150.md` retains both raw and normal-calibration coverage admission
and obtains an all-one clone from `FUN_18006bce0`, yet permits a replicated
65535 residual impulse. That clone is not this builder's feature mask: the
latter comes from the later selected, metadata-encoded image. With a supplied
dense mask selecting the outer impulse, the nonconstant-background bound in
`FUN_18003a9b0.md` proves a surviving mean-field dependency despite the later
inner-pixel replacement. Establishing that supplied-mask condition requires
the selected-image mask producer as well as the earlier rendering-mask
producer.

The same-call support condition can hold across the inner-edge unsigned
underflow boundary: successful type-12 preprocessing can retain positive
quality/coverage, select refined output, and preserve byte-identical selected
images, retained primary images and feature-derived masks across a one-unit
raw change from 3000 to 3001. The dense mask can select the replicated outer
impulse in both cases. On this path the unowned-word
dependency survives into the completed object's residual mean, texture and
enriched records. Positive runtime admission and feature-mask construction
therefore do not supply an exclusion invariant for the filter's allocation-end
loads. The fixed rendering-mask argument in `FUN_18003a150.md` is compatible
with, rather than contradicted by, this later feature-mask support.

The function returns `void`, performs no pointer, dimension, product, capacity,
or allocation checks, and dereferences allocation results immediately. Its
fixed profile-9 inputs satisfy the intended dimensions and packed-mask
capacity. Malformed geometry, missing objects, allocation failure, or an
oversized packed plane can fault or corrupt memory. Already-published fields
remain partial in the construction order above.
