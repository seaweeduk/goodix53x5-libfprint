# FUN_180037690

## Identity

- Binary: `GoodixEngineAdapter.dll` 2.0.310.900.
- Entry/body: `0x180037690..0x18003785f`.
- Role: bounded deep copy and optional normalization of a live feature's
  `0x38`-byte records.

## Call Graph

Callers are `FUN_1800456b0`, `FUN_1800458c0`, and `FUN_180045a50`. Relevant
callees are `FUN_180003800`, `FUN_180037480`, `FUN_18008a9c0`, and the compact
record ranking helper at `0x18006eed0`.

## Copy Contract

```c
void FUN_180037690(
  void *source_feature,
  void *destination_feature,
  int32_t maximum_records,
  int32_t transform_mode);
```

If destination record storage at `+0xf8` is null, the helper allocates
`maximum_records * 0x38` bytes. It then compares signed source count `+0xf0`
with the signed bound.

When `source_count <= maximum_records`, it copies the complete record array,
copies source count to destination `+0xf0`, and copies source partition count
`+0x118`. When `source_count > maximum_records`, it forms compact
`(record_dword_at_+8, original_index)` entries, ranks them, copies the first
`maximum_records` records, stores that bound as destination count, and invokes
`FUN_180037480` to derive destination partition state.

The truncating copy explicitly transfers record bytes `0..39`; bytes `40..55`
are not copied in that branch. This distinction is erased for the fields below
when transform mode is enabled.

## Transform Mode

When `transform_mode != 0`, the helper walks every copied destination record and
clears:

```text
record +0x24: 4 bytes
record +0x30: 8 bytes
```

Both profile-9/type-12 append (`FUN_1800456b0`) and queue copy
(`FUN_180045a50`) select this mode. The destination owns an independent record
array and the source remains unchanged. These cleared spans are live-only:
template record packing serializes `+0..+7`, `+0x10..+0x23`, and
`+0x28..+0x2f`, not the cleared bytes.

For type-12 study, the effective maximum is 150 and ordinary extraction emits
at most 150 records, so the truncating branch is not reached by ordinary probe
production.

## Failure Behavior

The helper has no status return. It trusts nonnull feature owners and a usable
record allocation. Allocation failure is not converted into a recoverable copy
error before later writes.
