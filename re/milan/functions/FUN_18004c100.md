## Recovered Behavior

It scans interior scale-space points in scale/row/column order, detects extrema,
refines them, rejects duplicate refined pixels through a visited plane, and
materializes accepted candidates. For shipping subtype 12 it passes capacity
`300` and the running returned count to `FUN_18004bbb0`; each successful call
appends one record. The caller marks the refined pixel visited and stops the
candidate scan after an append makes the returned count reach 300. This is the
raw materialization bound, not a later final-record selection limit. Sequence
72 pass 0 has `75/60/6/54` refine-calls/accepted/duplicates/materialized; pass
100 has `73/55/7/48`.

For fixed post-crop `104x88` type-12 geometry, the primary domain at
`0x18004c1d3..0x18004c36f` is scales `1..3`, rows `6..81`, and columns
`6..97`, all ascending. Duplicate suppression keys the final integer x/y after
refinement, not the original extremum or Q8 subpixel coordinate. The first
accepted convergence point owns that pixel.

Subtype-12 materialized-record admission has no additional quality predicate:
every discovered point that passes refinement and is first at its converged
integer pixel is appended. Curvature is computed but discarded; foreground,
histogram peak, and the auxiliary secondary-orientation flag are outputs rather
than gates. Refinement guarantees a one-pixel-interior converged coordinate, so
the materializer's five-byte source neighborhood is in bounds even when movement
leaves the original six-pixel scan interior.

Current source splits the same ownership across
`feature/extrema.c:17..72`, `:255..323`, and
`feature/materialization.c:183..235`. Its collector returns zero for invalid
inputs, an empty extrema set, or failure to allocate extrema/visited storage;
the outer extractor cannot distinguish those outcomes. A successful empty pass
continues through packing with record and partition counts zero and is rejected
later by matcher admission. Native also permits an empty materialized count but
does not expose a recoverable allocation status.

Native discovers, refines, and materializes in one pass and uses fixed global
scratch; this owner performs no allocation. Capacity is a positive signed
32-bit post-append bound: mode 12 appends one record and then
`0x18004c4f5..0x18004c4fb` stops when `count >= capacity`. A zero or negative
direct capacity therefore still writes one record and is unsafe caller misuse.
Production always supplies 300. Current source uses `size_t` and safely emits
zero for capacity zero, but first counts every extremum, allocates a complete
extrema array plus `rows*columns` visited bytes, then repeats discovery before
refining until capacity. At fixed `104x88`, this is at most 20,976 extrema
(335,616 allocation bytes) plus 9,152 visited bytes and preserves the same first
300 accepted records.

The source-only `goodix_milan_feature_collect_extrema()` always returns the
total qualifying count, even when its output pointer is null or capacity is
smaller; it writes only the first `min(total,capacity)` entries. The materialized
collector uses that contract first as a count query and then with exact capacity.
This decomposition changes temporary storage and failure behavior, not scan or
admission order, for immutable production planes.

Failure of either current-only allocation returns candidate count zero, which
the outer extractor treats as a valid empty pass and may feed into the normal
retry predicate. No valid profile-9 transaction can force that outcome from
image contents: fixed `104x88` geometry bounds the allocations to 335,616 and
9,152 bytes, and all earlier extraction work buffers must already have
succeeded. The only demonstrated way to reach the collapse is allocator fault
injection or external resource exhaustion. Native's fixed scratch owner has no
corresponding recoverable allocation result and earlier native matrix
allocations are themselves assumed successful. The collapse is therefore a
source robustness/failure-reporting surface, not a parity correction under the
transaction runbook. No candidate predicate, ordering, or parity change is
warranted without a valid transaction witness.
