## Exact Widths And Ordering

At `0x180070ec0..0x180070ef9`, squared columns are **wrapping dwords**:
`S0=a*a+c*c`, `S1=b*b+d*d`. Each is passed to `FUN_180074940`.
The two root results are added in a dword and arithmetically shifted right1 to
produce average scale. In the non-overflow, nonnegative domain this is
`(floor(sqrt(S0))+floor(sqrt(S1)))/2` with downward integer rounding.

If the first root is zero, outputs1 and2 are written zero and the function
returns after publishing average scale. Otherwise:

1. Form `a<<8` and `c<<8` as dwords and divide each by the first root with signed
   truncating division (`0x180070f0a..0x180070f25`). Pass their local addresses to
   `FUN_180074290` in c-then-a order.
2. Treat the returned angle as a signed word. If negative, add0x6488 in a word.
   Sign-extend, multiply by917 in64 bits and arithmetic-shift right16. Subtract180
   when at least180, then choose the smaller of angle and180-angle. This is the
   folded rotation output.
3. Sign-extend each **dword** squared column and multiply in64 bits, then call
   `FUN_180074980` (`0x180070f61..0x180070f6e`). The returned low dword is
   zero-extended to the division denominator.
4. If that denominator is zero, output dot zero. Otherwise compute `a*b+c*d`
   with wrapping-dword products/addition, sign-extend that result, shift left16
   in64 bits and divide by the unsigned32-bit denominator using signed64-bit
   truncation. Keep the low quotient dword and negate it when signed-negative
   (`0x180070f7c..0x180070f98`).

Widening squared-column or dot products before their dword narrowing is not the
unrestricted helper contract. A caller's fitted-coefficient bounds are a separate
precondition for using the simpler non-overflow formulas.

`FUN_180074940` interprets its input as unsigned32, including squared-column
words whose signed interpretation is negative. Its output is the unsigned
integer square root. `FUN_180074980` also consumes unsigned bits, but its
trial construction doubles the accumulated root in a **dword** before widening
(`0x1800749a0`: `LEA EDX,[R10+R10]`). Starting with bit `0x80000000` and shift31,
each trial is `(uint64_t(uint32_t(root*2)) + bit) << shift`; successful trials
add bit to the dword root and subtract the trial from the qword remainder.
This differs from mathematical square root when bit31 of the root has become
set. In particular, a negative signed product of the squared-column words is
passed as an unsigned qword and can exercise this branch.

records; see that note's published-domain example. Thus the dword operations
and the unsigned-bit square-root algorithm are reachable diagnostic behavior,
not merely a contract for malformed affine inputs.
