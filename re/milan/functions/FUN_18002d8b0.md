## Behavior

The function requires four nonnull output pointers, then copies requested count,
used count, and progress from session offsets `+0x08`, `+0x0a`, and `+0x0c`.
The copies occur before the count gate at `0x18002d95b..0x18002d995`; the used
output is therefore the synchronization source for `DAT_1801ce1a8` in
`FUN_180032e80`.
The gate at `0x18002d995..0x18002d9be` sign-extends both 16-bit counts. When
signed `used < requested`, it reports adapter result `1` and does not pack;
signed `used >= requested` reaches completion. At completion it obtains the
live public template handle, allocates `packed_size + 0x34`, writes the
0x30-byte adapter prefix, packs at offset `0x30`, and appends the outer
checksum. Allocation failure reports `0x8001`.

The function returns zero on both incomplete and completed paths. Successful
packing leaves the caller's result word untouched; only incompletion (`1`) and
allocation failure (`0x8001`) write it. Completion therefore depends on the
caller's initialized result word as well as the separately returned counts.
`FUN_180032e80` initializes that word to zero before calling, so successful
packing retains its ordinary success value.
The packed allocation is retained in global `0x18019b970`, with its size at
`0x18019b978`; any previous allocation is freed before replacement.

Normal profile-9/type-12 attach supplies requested count 12. Rollback through
`enrolDeleteImage` decrements used count before this gate, so a rejected image
cannot satisfy completion and does not reduce the 12-accepted-image requirement.

Completion is count-driven. The function does not inspect relation count,
graph reference `f2`, graph-established `f5`, or the returns from
`enrolGetTemplate`, `templatePack`, and `FUN_18002fd80`; a completed graphless
live template reaches packing.
