## Behavior

The function clones the live feature's row-packed matrix at `+0x140` into a
temporary working matrix and iterates the ordered candidate indices at context
`+0x87e8`, with count at context `+0x1c`. A record is `0x134` bytes (`77`
signed words). It is eligible only when word 1 (`+0x04`) exceeds four and word 5
(`+0x14`) exceeds 189. For each eligible record it:

- applies the record transform to derive a clipped coverage workspace through
  `FUN_180071370`;
- subtracts the transformed region through `FUN_180072600`;
- measures newly uncovered area with `FUN_180047580`;
- accumulates area-weighted record words 5 and 8; and
- retains the feature index with the greatest candidate count.

When context `+0x0c` is nonzero, the working dimensions and transform
translations are arithmetic-shifted right by one, while each newly uncovered
area is multiplied by four. Linear transform terms are unchanged. Processing is
ordered and destructive: each transformed region is removed from the same
working matrix before the next candidate, so increments are marginal rather
than independent overlap areas.

The ordered list is the lifecycle-order vector at context `+0x87e8`; unlike the
fallback finalizer, rescue does not scan physical feature slots. Area,
area-weighted products, total area, count sum, and their additions are signed
32-bit operations in the DLL. `IMUL` and `ADD` wrap at dword width, and the
subsequent `IDIV` operations truncate signed quotients toward zero. Half-
resolution area scaling is also a dword multiply. The maintained profile-9/type-
12 controls stay far inside these overflow surfaces, but a clean-room model must
not describe the native arithmetic as 64-bit accumulation.

The common gate is exactly:

```text
eligible_count > 1
total_uncovered_area != 0
weighted_word5 / total_uncovered_area > 208
sum_count / eligible_count > 6
weighted_word8 / total_uncovered_area > 183
count(new_area > area_threshold) > 1
```

`area_threshold` is `1100` for types 11 and 21 and `1400` otherwise. Types
12, 13, 16, and 22 (mask `0x413000`) use score denominator 42; all others use
31. Every division is signed integer truncation and every comparison above is
strict.

When the common gate succeeds, the function writes evidence `+0x684 = 1`,
stores the strict-greatest-count feature at `+0x648`, and writes
`score = best_count * 100 / denominator`. Equal counts retain the earlier
ordered feature. It sets `+0x688 = 1` and copies that record's unscaled transform
to `+0x650..+0x660` only when the selected index is valid and at least one
strong condition holds:

```text
incoming_score > 40
or count(new_area > area_threshold) > 2
or (type in {11,21} and weighted_word5 / area > 216
                    and weighted_word8 / area > 202)
```

The ordinary acceptance write is independent of this stronger branch. Thus a
rescue may select an index and score while retaining the caller's prior
transform and leaving rejection evidence clear.
