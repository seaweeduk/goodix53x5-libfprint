## Recovered Behavior

It converts one refined, unique candidate into the pre-descriptor 56-byte
record and 24-byte auxiliary state. It obtains the orientation histogram peak,
interpolates and wraps orientation, records signed strength and coordinates,
and appends to the incoming caller count.

The selector test is `((param_10 - 9) & 0xfffffff6) == 0`, selecting the
multi-peak path exactly for `9`, `10`, `17`, and `18`. That path builds the
histogram without antipodal duplication, computes threshold
`(peak * 0xcccd + 0x8000) >> 16`, scans bins `0..35`, and accepts only bins
whose unsigned value meets the threshold and is strictly greater than both
wraparound neighbors. Each accepted bin is interpolated and appended; scanning
continues until the post-append count reaches `param_9` capacity.

The shipping profile-9/subtype-12 call instead supplies `param_9=300` and
`param_10=12`. It uses antipodal mode, bypasses both threshold and strict-
neighbor checks, interpolates the helper's single selected maximum
unconditionally, appends one record, and stops rather than scanning later bins.
This distinction is exact: a non-strict two-bin maximum is accepted in mode 12,
whereas the scan mode rejects a plateau and can continue to later strict peaks.

At `0x18004bd96`, native `IDIV` uses denominator
`2 * previous + 2 * next - 4 * current`. The scan-mode strict checks prove it
nonzero; subtype 12 provides no such invariant. Direct DLL controls fault there
for an all-zero histogram and a positive three-bin wraparound plateau. No full
extraction input has reached that fault, including 5,000 structured/random
inputs, so end-to-end reachability remains unproven.
