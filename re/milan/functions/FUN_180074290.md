## Recovered Behavior

The first pointer is the y component and the second is x. It returns a signed
fixed angle over period `0x6488` and replaces the x input with vector magnitude.
Zero-axis results are `(y=0,x>0)->0`, `(y=0,x<=0)->0x3244`,
`(x=0,y>0)->0x1922`, and `(x=0,y<=0)->0xe6de`; both zero therefore returns
`0x3244`. The 13 angle constants are at `0x1800e13d0`; the per-stop Q16 gain
table is at `0x1800e13f0`. Magnitude uses signed 64-bit
`(gain[stop] * x + 0x8000) >> 16`.

`FUN_18004cad0` calls it normally as `(vertical,horizontal)`. Dense orientation
`FUN_18007ebe0` intentionally calls it as `(second_product,cross_product)`.
Current `feature_cordic()` mirrors the direct contract; the dense-orientation
`feature_atan2()` and its caller use the corresponding transposed convention.

The DLL obtains absolute values with 32-bit `NEG`, so `INT32_MIN` wraps to
itself. Current source spells those operations as signed unary minus, which is
undefined by C at that endpoint. A parity-safe correction must express unsigned
two's-complement negation rather than widening or saturating it; natural
reachability from the clamped extraction gradient remains unresolved.
