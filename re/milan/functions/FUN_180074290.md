# FUN_180074290

## Identity

- Binary SHA-256: `6673db3874fea66a58e2da29e371d797b890c767ba0491134d4a372c5b27e3b4`.
- Entry/body: `0x180074290`, `0x180074290..0x1800743ac`.
- Role: fixed-point CORDIC `atan2` plus vector magnitude.

## Recovered Behavior

The first pointer is the y component and the second is x. It returns a signed
fixed angle over period `0x6488` and replaces the x input with vector magnitude.
Apart from requiring valid pointers, the leaf accepts every pair of signed
32-bit component bit patterns; it performs no range validation. Absolute-value
`NEG` and every vector update are dword operations wrapping modulo `2^32`, the
next `TEST`/`JG`/`JLE` interprets the wrapped dword as signed, and component
shifts are arithmetic. Angle updates wrap independently in 16 bits.
Zero-axis results are `(y=0,x>0)->0`, `(y=0,x<=0)->0x3244`,
`(x=0,y>0)->0x1922`, and `(x=0,y<=0)->0xe6de`; both zero therefore returns
`0x3244`. The 13 angle constants are at `0x1800e13d0`; the per-stop Q16 gain
table is at `0x1800e13f0`. Magnitude sign-extends the final x dword and gain,
multiplies and adds `0x8000` in 64 bits, logically shifts right 16, and stores
the low dword. On the production domain final x is positive, so this is the
usual rounded signed expression `(gain[stop] * x + 0x8000) >> 16`.

`FUN_18004cad0` calls it normally as `(vertical,horizontal)`. Dense orientation
`FUN_18007ebe0` intentionally calls it as `(second_product,cross_product)`.
Current `feature_cordic()` mirrors the direct contract; the dense-orientation
`feature_atan2(y,x)` is the angle-only transposed face of the same contract: its
result is `feature_cordic(x,&discard_y)` narrowed to signed 16 bits. There is no
second native atan helper.

The DLL obtains absolute values with 32-bit `NEG`, so `INT32_MIN` wraps to
itself. Current source spells those operations as signed unary minus, which is
undefined by C at that endpoint; arbitrary independent 32-bit arguments can
likewise overflow the source's later signed CORDIC additions or subtractions.
The current GCC `-O2` output was compared with an explicitly wrapping control
over fixed endpoint cases and five million pseudorandom pairs and matched the
native dword behavior throughout.

Production reachability is now closed. The complete type-12 Gaussian-gradient
producer bounds either raw component below `160000`, far inside the nominal
19-bit clamp. After shifting by 12, the CORDIC gain bounds every vector lane
below `1.527e9`, so vectoring remains away from signed overflow and cannot reach
`INT32_MIN`. The dense producer's independent bound is documented with
`FUN_18007ebe0`. Current source is therefore exact on every production image.
Adversarial direct calls to internal `feature_cordic()` or `feature_atan2()` are
valid at the helper's declared integer interface, but those states are not
produced by the profile-9/type-12 image paths and do not establish a production
parity discrepancy.

`FUN_180057140` passes pointers in the order `(sine,cosine)`. Under this leaf's
first-pointer-y/second-pointer-x convention that computes
`atan2(sine,cosine)`, despite decompiler variable names that can suggest the
reverse. The returned angle is narrowed to signed 16-bit by the caller before a
single negative-angle period adjustment.
