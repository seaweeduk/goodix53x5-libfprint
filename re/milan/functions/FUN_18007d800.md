## Recovered Behavior

It creates the separable Gaussian execution state. Nonnegative filter IDs are
resolved by `FUN_18007dd20`; the resulting coefficient vector is copied into an
owned kernel object and passed to the convolution backend.

## Extraction backend state

For the unsigned-word extraction descriptors, the kernel descriptor uses dword
coefficients (type 4). `FUN_18007db60` copies the descriptor into horizontal and
vertical kernel objects at context `+0x90` and `+0x98`. A negative anchor selects
half the odd kernel length. The vertical object stores bias `0` at `+0x28` and
shift `16` at `+0x2c`; the constructor supplies border mode `4` on both axes.

`FUN_18007c2a0` builds horizontal border offsets once for reuse across source
rows. `FUN_18007c6c0` materializes extended rows and keeps horizontally filtered
rows in a ring, then constructs reflected vertical row pointers. Mode `4`
maps a negative coordinate `q` to `-q` and a coordinate at or beyond length `L`
to `2*L-2-q`, repeating until in range. These offsets depend only on dimensions,
anchor and tap position, not pixel values. The extraction radii are at most 7,
so an `88`-row, `104`-column plane needs at most one reflection per coordinate.

For these square odd kernels and default workspace sizing, the ring has
`kernel_length + 3` rows. Its dword row stride is `round_up(width,16)*4`, hence
448 bytes at width 104. Source rows are consumed in ascending order. An entire
source row, including reflected horizontal borders, is copied before horizontal
filtering; the resulting ring row is retained until the vertical consumers have
passed it. Vertical publication can therefore share the source image: output
stores do not destroy an unread source row or a still-needed horizontal row.
The ring progression, reflection selection and backend dispatch are independent
of pixel values. Plane zero in `FUN_18004ac40` uses this in-place form; later
planes use distinct source and destination descriptors.

For IDs `0..5` and `100..105`, `FUN_18007be70` clears context byte `+0x88` and
`FUN_18007c6c0` selects the weighted horizontal `FUN_18007d9c0` and symmetric
vertical `FUN_18007d260` backends. ID `6` sets this byte and selects the uniform
sum backends `FUN_18007de70` and `FUN_18007e180` instead. See
`FUN_18004ac40.md` for the scale kernels and arithmetic range.
