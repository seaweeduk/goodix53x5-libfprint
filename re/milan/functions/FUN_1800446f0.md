## Behavior

The helper initializes a temporary plane to `0xff`, scans the complete input,
and changes a temporary byte to zero exactly when the image byte is `0xff`.
`0xfe` and every other byte remain valid. If no `0xff` byte was found, it fills
the complete output mask with `0xff`. Otherwise it dilates the temporary valid
plane once through `FUN_180073ff0`.

The output is therefore `0xff` exactly when the center or an in-bounds
horizontal/vertical neighbor at distance one or two is not `0xff` in the input.
It is zero only when every in-bounds member of that nine-position cross is
`0xff`. Out-of-plane positions are ignored, so an isolated valid interior pixel
produces nine admitted bytes while a valid corner produces five. An all-`0xff`
image produces an all-zero mask.

The return is the original, pre-dilation valid fraction:

```text
floor(((pixel_count - invalid_ff_count) << 16) / pixel_count)
```

`FUN_180044300` does not consume that return. The later quality combiner counts
the propagated output mask independently.

## Descriptor And Storage Contract

`FUN_180044300` creates the destination with `FUN_180068700` using the source
width and height and element size 1. For profile 9, both descriptors therefore
have width 108, height 88, row stride 108, and payload size 9,504. The scan uses
the source dimension product; the dilation uses the destination dimensions;
the all-valid fast path fills the destination payload size from header `+0x0c`.
These three extents coincide on this caller path, without padding or cropping.

The full temporary validity plane is completed before dilation begins. Dilation
reads that stack plane and writes the separately allocated destination, so
newly admitted output bytes cannot propagate farther in the same call. The
source byte image is not modified. The mask has no retained lifetime: the
quality caller frees it after the combiner returns.

All-`0xff` content is a normal result: this helper writes a zero mask and returns
zero original-valid Q16, not an error status. The byte-element type guard and its
zero quality/coverage error writes belong to `FUN_180044300`, before this helper
is entered.

On the profile-9 renderer, bytes outside the admitted render mask are `0xff`, so
raw setup/live geometry can directly control this quality-validity support.
The gradient-based coverage producer uses a different predicate; radius-two
validity propagation alone does not imply coverage above 5 or zero direct
quality. See `FUN_180044530` for the separate coverage inputs and arithmetic.
