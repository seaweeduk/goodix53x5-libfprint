## Fixed-Width Affine Arithmetic

`FUN_180075dc0` calls `FUN_1800689a0` before scanning. The inverse determinant
uses wrapped dword semantics; a wrapped-zero determinant copies all six input
words. Nonzero inversion uses signed division toward zero. With unsigned-word
coordinates `ex,ey` and inverse `[ia,ib,itx,ic,id,ity]`, the inverse-point
instructions at `0x180075ea0..0x180075ef0` are all dword operations. The x lane
forms `ia*ex` and `ib*ey`, adds the first `0x80` to the former, then adds
`(itx<<8) + ib*ey + (ia*ex+0x80)` in that order. The y lane forms `id*ey` and
`ic*ex`, then adds `(id*ey+0x80) + (ity<<8) + ic*ex`. Each lane finishes with
`SAR 8; +0x80; SAR 8`. Every multiply, shift, and add wraps as a dword. The
strict inverse border is checked at `0x180075ef3..0x180075f18`.

For probe `px,py` and forward `[a,b,tx,c,d,ty]`, the x lane at
`0x180075f40..0x180075f6b` evaluates dword `b*py`, dword `a*px`, adds them, then
adds dword `tx<<8`. The y lane at `0x180075f4a..0x180075f85` evaluates dword
`d*py`, then adds dword `c*px` and dword `ty<<8`. There is no `+0x80` before
the residual coordinates: each raw lane is arithmetically shifted by 8 at
`0x180075f6e..0x180075fa6`. At `0x180075f88..0x180075fba`, native first computes
wrapped `mapped-expected`; only when that signed result is not positive does it
replace it with wrapped `expected-mapped`. The signed result must be
`<=0x1500`, so equality is accepted and `0x1501` is rejected. Pixel coordinates
are separately formed at `0x180075fc3..0x180075fe3` by dword
`+0x80; SAR 8; +0x80; SAR 8` and use signed `5 < coordinate <= dimension-5`.
The x and y lanes have the differing product/add orders above but no differing
admission formulas.

Current `goodix_milan_match_cross_class_alternate_correspondences()` uses widened
`int64_t` products for the forward transform instead of this dword wrap. Direct
DLL/current execution with transform `[65536,0,5120,0,65536,5120]`, enrolled
coordinate `(0,0)`, probe coordinate `(65535,0)`, and equal ordinary tails is an
output discriminator. The mathematical determinant is `2^32`; the recovered
wrapped determinant is zero, so both the DLL and current checked inverse accept
the transform by copying it. Native forward dword raws are `0x00130000` and
`0x00140000`, giving residual coordinates `0x1300/0x1400`, pixels `19/20`, and
final pair `[0,0]`. Current x raw is widened to `0x100130000`, fails the residual
gate, and returns no pair. The mismatch survives ratio and spatial selection.
The reverse output difference is not representable from widening alone: current
can admit only when its unwrapped 64-bit pixel coordinate is in `6..99` or
`6..83`, which keeps the full raw sum inside the same dword result used by the
DLL.

Current inverse expressions happen to compile as dword `IMUL`/`ADD`, but their
signed C products and sums can overflow. An exact source correction should use
the existing defined dword affine, arithmetic-shift, pixel-rounding, and residual
helpers for both inverse and forward lanes. Merely changing the forward raw x/y
types fixes the demonstrated behavior but leaves inverse and pixel arithmetic
dependent on signed-overflow or implementation-defined shift behavior.
Retained natural profile-9 rows did not approach this overflow boundary; that is
negative corpus evidence, not a general unreachability proof.

This guided cross-class affine-width difference remains in current source. It is
independent of the merged signed-dword spatial-collision and post-replacement
correction described in `FUN_180075a60.md`.

## Failure Ownership

`FUN_1800689a0` has no error return. Null input or output is a no-op. Its six
nonzero-determinant divisions occur at `0x180068a07`, `0x180068a19`,
`0x180068a34`, `0x180068a52`, `0x180068a62`, and `0x180068a6e`. A malformed
extreme transform that presents `INT64_MIN / -1` raises the native integer
division exception. Current source checks and rejects that state before pair
publication. This fail-closed result deliberately differs from a native crash;
it must not be described as parity for accepted synthetic-valid input.
For example, `[1,0,268435456,134217728,-1,0]` has wrapped determinant `-1` and
the sixth numerator `(134217728*268435456)<<8 == INT64_MIN`; direct DLL
execution faults at `0x180068a6e`, while current checked inversion returns `-1`.
