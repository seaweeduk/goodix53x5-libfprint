## Recovered Behavior

It clones the two matrix descriptors, inverse-warps the first through
`FUN_18006f390`, classifies it against the second with `FUN_180073540`, computes
coverage and detail, then selects `FUN_1800731d0` or `FUN_1800740f0` scoring
according to mode. The first bitmap is the warped input and the second is sampled
directly. `FUN_18006f390.md`, `FUN_180068bb0.md`, and `FUN_180073540.md` contain
the exact crop, inverse-sampling, and coordinate-frame contracts.

For profile-9/type-12, the original dense bitmap domain is `52x44`. The crop
origin written by `FUN_18006f390` is passed as `(origin_y,origin_x)` to
`FUN_180073540`; direct bitmap and validity reads add that origin, while warped
reads remain crop-local. The four natural geometry controls cover origins
`(0,0)`, `(0,1)`, and `(25,0)` and are exact for warped validity, all classes,
and valid total.

`FUN_180073540` clears all four class words and valid count, then increments one
class and valid count for every pixel accepted by both validity masks whose two
binary values are below two. Thus caller-produced classes are nonnegative and
sum exactly to valid count. The score leaves do not check those invariants.

Let `full_count` be the signed 32-bit product of the first matrix's rows and
columns, `valid` the classifier count, and `c0..c3` the four class counts. This
function owns the caller-visible coverage and detail formulas:

```text
coverage = ((full_count >> 1) + valid * 256) / full_count

nonmatch = c0 + c1 + c2
detail = nonmatch > 0
           ? ((nonmatch >> 1) + c0 * 256) / (nonmatch + 1)
           : 0
match_fraction = ((valid >> 1) + c3 * 256) / (valid + 1)
if match_fraction < 15:
    detail -= ((15 - match_fraction) >> 1) + 3
```

The optional coverage write occurs at `0x180071951..0x180071967`; optional
detail calculation and final write are `0x18007196b..0x1800719bc`. The `+1`
denominators belong to nonmatch detail and match fraction, not coverage. All
intermediates are 32-bit and divisions are signed, truncating toward zero.
`FUN_180071d40` also supplies the optional filtered-mismatch output on both
ordinary passes; the count is computed even when the outer caller does not ask
argument 10 to publish it.

Mode zero calls `FUN_1800740f0` and neither reads nor mutates context confidence.
For nonzero mode, `0x1800719e6..0x1800719ff` initializes confidence only when its
incoming value is negative:

```text
confidence = c3 * 256 / (c1 + c2 + c3 + 1)
```

Initialization occurs after coverage/detail publication but before
`FUN_1800731d0`. It also occurs when valid count is zero: all classes are then
zero, confidence becomes zero, the score leaf returns `128`, coverage is zero,
detail is `-10`, and the raw-score context word remains untouched. Because
`FUN_180071d40` reuses one context across both bitmap passes, a zero-valid
primary pass stores confidence zero and a later secondary pass reuses zero
rather than initializing from secondary classes. The native
`goodix_milan_match_overlap_result()` equivalent preserves this ordering.

Warp/allocation failure returns false after cleanup and writes none of score,
coverage, or detail. On success the score output is mandatory and written after
the selected leaf returns. Null optional coverage/detail pointers are accepted.
An empty clamped crop is a warp failure. A singular determinant alone is not:
the native byte-warp helper retains literal inverse accumulators
`[1,0,0,0,1,0]` and returns no status.
Native trusts the matrix dimensions and mandatory pointers: zero full area can
fault in coverage division. In nonzero mode a null scoring-context pointer
faults at `0x1800719e6` after optional coverage/detail publication and before
score publication; zero-valid scoring tolerates a null weights-array pointer
inside an otherwise valid context because the leaf does not dereference it.
The current helper instead returns `-1` for null required pointers, negative
counts, nonpositive full area, negative classes, or a class sum inconsistent
with valid count. These checks are deliberate fail-closed behavior, not native
fault parity.
The profile-9/type-12 caller supplies positive `44*52` area, nonnull outputs,
weights `{3,2,3}`, mode nonzero, and filtered affine count as context count.
