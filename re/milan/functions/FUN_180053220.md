## Fallback Classifier Table Contract

`FUN_180054930` is reached only if the candidate flag remains zero after the
initial classifier. Quality and coverage scalar arguments are unused here;

`3 * ((metrics[9] < 91) + (metrics[9] < 76)) +
5 * (metrics[13] + metrics[14])` from detail (word 5) and low detail (word 8).
Otherwise this penalty is zero. Broad classification uses index
`clamp(metrics[1] - config[1] - 4, 0, 9)`, subtracts `config[0]` from the two
penalized bitmap operands, and requires all three operands to be at least
their table thresholds. Strict classification uses index
`clamp(metrics[1] - 4, 0, 9)`, low detail at least its threshold plus two,

Additionally, primary below six with retained below 16 rejects strict
classification if primary is below five, topology is below 56, or coverage is
below 125. All these comparisons are signed.

The detail-table substitution affects only the broad fallback output. Strict
fallback classification uses the low-detail and coverage tables and the fixed
detail floor 206, not the substituted detail table. If primary is below five
and strict fallback fails, a broad fallback rejection leaves both flags zero.
It therefore skips `FUN_180053680`; `FUN_1800572e0` has no switch case below
primary five and cannot subsequently add either flag. No recognition-mode
write occurs on that route. By contrast, a broad fallback success can enter
the early post-veto mode-clearing branch even when that branch clears both
flags: the flag result alone does not describe the configuration result.

Retained-count admission does not impose a primary-count floor of five.

caller's retained-count-greater-than-four check cannot be substituted for a
