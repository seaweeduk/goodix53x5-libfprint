- Role: deep-copy one live feature into an already allocated destination.

## Recovered Behavior

Given a live template, source feature, and preallocated destination feature, the
helper copies scalar fields and deep-copies the owned matrices, active record
array, bitmap/mask storage, and optional `0x1abc` registration block. It resets
transient destination fields such as residual/action counters instead of
aliasing source pointers. Null source or destination returns `-1`; success
returns 1.

The transient reset is explicit rather than a consequence of zero allocation:
`0x180045bc5..0x180045bd9` clears live `+0x128/+0x12c`, `+0x138`, and
`+0x148`. In particular, a queued `P->Q` copy starts `Q.+0x148` at zero instead
of copying the source feature's gallery overlap count. The queue probe never
becomes the owner of the current gallery vector: replacement preserves the
target gallery slot's `+0x148`, append starts a preallocated zero slot, and only
`FUN_180047120` recomputes the complete gallery vector at its recovered
normalization boundaries.

For the profile-9/type-12 queue path, this is a transformed copy rather than a
byte-preserving record copy. Queue enqueue passes nonzero transform mode to
`FUN_180037690`; every copied `0x38`-byte record in Q has its dword at `+0x24`
and qword at `+0x30` cleared. P is unchanged. Q owns the transformed records
independently and does not preserve P's bytes `36..39` or `48..55`.

Queue enqueue therefore does not transfer or borrow the current probe. The
live template continues to own its preallocated cache slot, while the probe
remains independently owned and can be destroyed after `templateStudy`.

## Destination State And Reuse

The type-12 stores copy geometry `+0/+4`, three matrix owners `+8/+0x10/+0x18`,
the complete inline `0xc8` bytes at `+0x28`, the mask owner `+0x140`, quality
`+0x11c`, coverage `+0x120`, and metadata `+0x14c/+0x150`. Record count and
partition boundary are assigned by `FUN_180037690`. The copy sets `+0x20` to
null, `+0x124` to `-1`, and the four reset scalars described above to zero.

It does not assign `+0x110/+0x114/+0x130/+0x134` or the histogram pointer at
`+0x158`. Ordinary queue owners start with those fields zero from allocation;
the incoming probe's histogram is not transferred to the queued owner.

Quality and coverage are exact dword copies, not recomputed from the transformed
records or destination mask: source `+0x11c` is loaded at `0x180045ba9` and
stored at `0x180045bb9`; source `+0x120` is loaded at `0x180045bbf` and stored
at `0x180045bdf`. Thus every ordinary match-time queued owner inherits quality
greater than 15 and coverage greater than 65 from its caller's admission.

The optional block branch at `0x180045c50..0x180045d1a` is source-presence gated.
A nonnull source `+0x160` allocates destination storage only when absent and
copies exactly `0x1abc` bytes. A null source leaves the destination pointer and
any prior content untouched. Allocation/copy helper failures are not checked;
only null source or destination causes the explicit `-1` return.

`FUN_1800462a0` ignores that return and still assigns the rank. Thus neither
helper provides transactional failure recovery.

## Matrix-Relevant Copy Content

The deep copy retains the complete active-record count and all bytes outside the
two transformed spans, but clears descriptor bytes `36..39` and `48..55` in Q.
It does not copy either caller-stack match matrix. A later queued rematch
allocates new matrices and recomputes them from Q's transformed records; it must
not consume the corresponding source-P spans as if queue enqueue preserved them.
