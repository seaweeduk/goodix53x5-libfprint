# FUN_1800731d0

## Identity

- Binary: `GoodixEngineAdapter.dll` 2.0.310.900.
- Entry/body: `0x1800731d0`, `0x1800731d0..0x1800732b1`.
- Role: mode-aware four-class overlap score.

## Recovered Behavior

The leaf receives signed 32-bit `valid_count`, `full_count`, class-0 count, and
class-3 count. Its fifth argument is the scoring context assembled by
`FUN_1800717e0`:

```text
+0x30  int32_t weights[3] pointer
+0x3c  int32_t context_count
+0x40  int32_t context_confidence
+0x44  int32_t raw_score output
```

For nonzero `valid_count`, with every operation performed as a wrapping 32-bit
operation and every division a signed `IDIV` truncating toward zero:

```text
half = valid_count >> 1
numerator = half + class0 * 256

if valid_count > (full_count >> 1):
    raw = weights[0] + 38 + numerator / valid_count
else:
    raw = numerator / (valid_count + 1)
        + (valid_count * 19) / (full_count >> 1)
        + weights[1] + 19

quality = (half + class3 * 256) / valid_count + weights[2]
context.raw_score = raw
```

The `valid_count + 1` denominator belongs only to the low-valid-count raw-score
arm. This leaf does not initialize context confidence. It returns `raw` when
any predicate below is true, in short-circuit order, and `128` otherwise:

```text
quality > 23
quality > 18 && context_confidence > 62
quality > 19 && context_confidence > 50
quality > 17 && ((context_confidence > 40 && context_count > 7) ||
                 context_count > 8)
raw > 230 && quality > 16
```

All comparisons are signed and strict. Counts `7/8/9`, confidence
`40/41/50/51/62/63`, and quality `16..20/23/24` therefore have exactly the
boundaries shown. If `valid_count == 0`, the leaf immediately returns `128` and
does not dereference the weights array or write `+0x44`. It does load the
weights pointer from context `+0x30` before testing valid count, so a null
context faults while a null weights pointer is tolerated only on this zero
path. Arbitrary negative or inconsistent scalar arguments are trusted; they can
produce wrapped results or a hardware division exception. The production caller
prevents those states by obtaining the counts from `FUN_180073540`.

At the production `FUN_18005a3c0 -> FUN_180071d40` boundary, nonzero overlap
mode supplies weights `{3,2,3}`. The additional context word is the filtered
affine count passed as argument 9 to `FUN_180071d40`; it affects acceptance
predicates but not raw-score arithmetic.

`FUN_1800717e0:0x1800719e6..0x180071a12` initializes confidence when its incoming
value is negative before this call and writes the returned score to its caller
output. The raw score context write is at `0x180073256`; acceptance is
`0x18007325a..0x1800732a7`.

`FUN_1800717e0` initializes negative incoming confidence before calling this
leaf, including on zero classified support. `FUN_180071d40` preserves that
confidence across high and enhanced passes; the second pass does not
initialize it from its own classes. See `FUN_1800717e0.md` for the zero-support
publication order and `FUN_1800740f0.md` for the separate mode-zero path.

## FUN_18005a3c0 Result Ownership

The filtered count in this helper's context is part of overlap-call ownership,
not a later recomputation input. Primary affine/count and alternate affine/count
produce independent complete results. The caller ranks those stored results and
atomically retains the winner, so a primary affine is never rescored with an
alternate count and a lower/equal-count alternate winner keeps its own count.
