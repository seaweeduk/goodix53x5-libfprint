The main candidate path invokes `FUN_18004c100` with raw materialization capacity 300; selected candidates are materialized as `0x38`-byte records through `FUN_18004cc70`. Coordinates are rounded to 16-pixel/Q8 boundaries, orientation is rounded to a signed `0x100` step, and edge classes are assigned from image bounds. Profile 10 also emits a secondary record set.

  IDs `0..5` are used first; IDs `100..105` replace them on retry. Native
  convolution accumulates modulo 32 bits and shifts right 16. All twelve

  `feature/extraction.c:25..48`.
- Pass-local descriptor gradients use the same bank's first two kernels on the

  `gradient_input = 10*first - 9*second`. Native calls the two filters at
  `0x180049e83` and `0x180049eb1`, writes the combination at
  `0x180049ef2..0x180049f17`, clears the complete magnitude and orientation
  outputs at `0x180049f37..0x180049f58`, and calls `FUN_18004cad0` at
  `0x180049f69`. Current
  `feature_build_gradients_pass()` is equivalent at
  `feature/extraction.c:207..273`. The retry rebuilds this gradient input as

  magnitude or orientation output.
- `FUN_18004c100` scans scales `1..3` and the six-pixel spatial interior,
  refines extrema, and appends at most 300 records. It owns collision state by

- At `0x18004a097`, subtype 12 takes the non-grouped branch. If count exceeds
  the caller's selection limit, `0x18004a0b5..0x18004a15e` sorts `(signed

  `0x18004a1fc..0x18004a225` assigns only vertical boundary classes: `1` when
  unsigned refined y is below `0x1400`, `2` when it is at least

  `(uint16(value) + 8) & 0xfff0`. Signed orientation rounds to a `0x100` step at
  `0x18004a533..0x18004a5b2`: positive half ties round up and negative half ties

The type-12 truncation branch copies only materialized bytes `0..11`; descriptor
and class construction then writes `12..55`. The no-truncation branch copies the
whole 56-byte scratch record, but overwrites the same suffix. Thus every retained
final record is fully initialized. Current source zero-initializes each whole
materialized record at `feature/materialization.c:169`, copies it at `:591`, and
performs the same complete overwrite at `:592..613`. This is safer intermediate
initialization with identical final bytes.

Native uses process-global scratch at `0x180264020` (300 records),
`0x180262d60` (300 rank pairs), `0x18025f520` (300 auxiliary records),
`0x180252880` (collision bytes), and `0x18024f040` (a profile-dependent fallback
list that is populated but not consumed for subtype 12 at `104x88`). The
extractor passes the feature object's owned output pointer and count at
`0x18004b54c..0x18004b562`, then partitions that retained output at
`0x18004b6a6`. `FUN_180049b90` returns no status and frees its temporary image
descriptors at `0x18004a624..0x18004a6c9`.

Current source replaces the DLL's non-reentrant scratch with per-call storage
while preserving the raw capacity of 300 and the later caller-supplied selection
limit. Its nested collector maps invalid input or allocation failure to a zero
candidate count, so the outer extractor cannot distinguish that failure from a
valid empty pass; successful fixed-geometry output is otherwise equivalent.
The production type-12 caller guarantees a positive selection limit `1..150`.
Native selection treats that limit as signed 32-bit and its truncating copy is a
post-copy bound, so a malformed zero/negative limit would still copy one record;
current `size_t` handling returns zero and is intentionally safer. Native rank
sorting is stable insertion sort, while current `qsort` need not be stable, but
generated rank indices are unique and make every production comparison total.
The outer source extractor does distinguish failures in enhancement, the
three-tap pre-scale blur, scale filtering, and gradient filtering and returns
`-1`; on successful filtering, record count is owned only by materialization,
then the coverage-derived limit, the optional broken-pixel removal, and no other
stage before partitioning.

At fixed `108x88 -> 104x88` production geometry every allocation product is
bounded. The generic source entry validates `rows*columns` but does not separately
guard `6*count*sizeof(uint16_t)` before allocating the scale block; an
independently supplied, unrealistically huge geometry can wrap that allocation
and is a malformed-input source surface. The minimal hardening correction is a
single `count <= SIZE_MAX / (6 * sizeof(uint16_t))` guard before all work-buffer
allocations. The DLL is not a generic geometry API: its allocator takes a
32-bit size and native internal callers assume fixed valid descriptors and
successful allocation, so allocation failure or hostile dimensions are unsafe
rather than recoverable native results. This does not affect production parity.
