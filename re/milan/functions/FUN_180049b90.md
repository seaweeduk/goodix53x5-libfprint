## Recovered Behavior

It constructs scale-space planes, gradients, candidates, ranks, orientations,
and descriptors. The type-12 entry takes the enhanced byte-image descriptor
first and the blurred byte-image descriptor second, followed by output records,
output count, and configuration. Configuration dwords are type, selection limit,
raw capacity, refinement parameter, retry enable, descriptor scale, and the two
descriptor layout triples. The ordinary values are
`[12, limit, 300, 40, retry, 0x1adfe, 32, 4, 0, 32, 1, 0]`.
The final two arguments belong to the unused secondary output and count.

For profile 9/type 12, the complete pass contract is:

  IDs `0..5` are used first; IDs `100..105` replace them on retry. Native
  convolution accumulates modulo 32 bits and shifts right 16. All twelve

  entries at `0x1800f2910` and `0x1800f2bd0` match
  `feature/extraction.c:25..48`.

  with ID `marker+1`, then form signed 32-bit
  `gradient_input = 10*first - 9*second`. Native calls the two filters at
  `0x180049e83` and `0x180049eb1`, writes the combination at
  `0x180049ef2..0x180049f17`, clears the complete magnitude and orientation

  `0x180049f69`. The corresponding current owner is

The production type-12 caller bounds the positive selection limit to `1..150`.
`FUN_18004ae70` derives it as `max(1, coverage * configured_maximum / 100)`
with signed truncating division, not nearest rounding. The raw append capacity
remains 300 independently of that later selection limit. Selection treats the
limit as signed 32-bit and tests it after each truncating copy; zero or negative
limits are outside the caller contract.

With configured maximum 150 and integer coverage, the formula reduces to
`max(1, floor(3*coverage/2))`: limits congruent to 2 modulo 3 cannot be supplied
by that caller configuration. The interval bound alone is not a proof that
every helper-limit equality case is reachable through the coverage producer.

The rank-sort thunk reaches `FUN_18006ee50`, a stable insertion sort. It compares
the signed strength first, then the signed original index. Generated indices are
unique, making this a total order even when strengths tie. Descriptors use the
resulting rank indices on both the truncating and nontruncating paths.

## Retry And Lifetime

The loop at `0x180049fee..0x18004a013` repeats extraction exactly when:

```text
materialized_count <= 60 && pass_marker == 0 && configured_retry != 0
```

Only the selected pass receives descriptors and quantization. Retry clears
collision state and replaces the first pass before applying the coverage-derived
limit; it never appends to or descriptor-finalizes discarded first-pass records.

The native allocator takes a 32-bit size. This internal function assumes fixed
valid matrix descriptors, sufficient output storage, successful allocation, and
the successful interpolation preconditions in `FUN_18004bbb0.md`. It offers no
recoverable failure status for arbitrary dimensions or allocation failure.
At production `108x88 -> 104x88` geometry all allocation products are bounded.
The output records belong to the caller; temporary image descriptors are freed
on return, and process-global materialization/rank/auxiliary scratch is reusable
by the next extraction. No pointer into that scratch is published in a record.

Current corresponding owners are
`feature/extraction.c:feature_extract_records` and
`feature/materialization.c:feature_finish_pretransform_records`. The outer
caller owns any later broken-pixel removal, record transformation through
`FUN_180047ae0`, and partitioning through `FUN_180037480`; these follow this
function's complete pretransform record publication.
