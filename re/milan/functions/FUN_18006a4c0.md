## Initial Mask Construction

1. Subtract live from setup modulo 16 bits, then read the differences as signed
   words (`0x18006a760..0x18006a7b6`). The production setup/live ranges give
   differences `3000..11190`, so subtraction and sign extension lose no value.
2. Partition from row/column zero into 15-row by 16-column blocks. Clip the
   final block in each dimension; production has 6 by 7 blocks, with a final
   13-row band and 12-column band. Include a sample in its block sum only when
   unsigned live is at least 500 (`0x18006a89d..0x18006a8ab`). Divide the signed
   sum by the eligible count, or by one for an empty block; empty blocks have
   mean zero and still participate in the minimum and maximum. The divisor
   selection and signed `IDIV` are at `0x18006a8f8..0x18006a91b`.
3. Independently compute each full row's signed mean using all columns, without
   the live eligibility filter (`0x18006aac0..0x18006ab39`). Average the means
   of rows `4*g` and `4*g+3` separately for `g=6..floor(rows/4)-1`. Thus the
   production comparison uses 16 means on each side, beginning at rows 24/27
   and ending at rows 84/87. All divisions truncate toward zero. Reject only
   when either signed phase difference exceeds 400; equality passes. Rejection
   writes count zero and returns zero without writing threshold, percentage,
   or mask (`0x18006ab42..0x18006abb0`, `0x18006abf5..0x18006ac01`). Those
   fields remain zero under the caller's initialization contract.
4. Let `minimum` and `maximum` be the block-mean extrema and
   `span=maximum-minimum`. Type 12 uses `max(500,2300*70/100)=1610` as the span
   floor. If `span<=1610`, set `split=minimum-250`. Otherwise set
   `half=trunc(span*50/100)` and choose `minimum+half` when `maximum<=4095` or
   `minimum>=4095`; choose `maximum-half` otherwise
   (`0x18006abb4..0x18006ac0a`, `0x18006acc7..0x18006acdf`). An odd span
   therefore chooses opposite midpoint roundings on the two branches.
5. The function also computes column means, but the type-12 edge-column split
   adjustment cannot run: it is inside the `span>1610` branch and additionally
   requires `span<=1500` at `0x18006ac90..0x18006ac97` or
   `0x18006acb9..0x18006acc0`. No column mean changes this type's split.
6. Partition all signed differences, including live-ineligible samples, into
   high (`difference>split`) and low (`difference<=split`). Compute signed
   population means. For empty low, use `high_mean+600`; for empty high, skip
   threshold/mask construction and publish the existing count's percentage.
   On the production ranges, at least one high sample exists: each split is
   strictly below the maximum sample, including when empty blocks lower the
   minimum to zero (`0x18006acee..0x18006ad89`).
7. Set `separation=high_mean-low_mean`. When `high_count<low_count+150`, store
   `split+trunc(separation/5)` as a signed word; otherwise store
   `split-trunc(separation/4)`. The negative empty-low separation is exactly
   -600. Signed divide-by-four uses sign correction before `SAR`, not floor
   division (`0x18006ad95..0x18006adc7`).
8. Write mask byte one and increment count for `difference>threshold` and
   unsigned `live<3800`. Separately count samples satisfying the strict
   `difference<threshold` and the same live ceiling. Equality with threshold
   belongs to neither count; this is not the earlier low population. There is
   no lower live bound at this stage (`0x18006ae10..0x18006ae4e`).
9. If `below_count*100>pixel_count*30`, zero the count and whole mask, store
   `minimum+150` as threshold, and rebuild using the same strict high/ceiling
   predicate. At 9,504 pixels this requires at least 2,852 below samples;
   2,851 does not trigger it. Finally store `count*100/pixel_count` as the word
   percentage (`0x18006ae91..0x18006af11`).
