20-word configuration, a mode flag, two output flags, and an optional third
output. It applies type-specific threshold tables, count/detail adjustments,
quality/coverage gates, and overlap thresholds. The first caller invocation
uses its two outputs to decide whether post-admission refinement is requested.

### Profile-9/type-12 arithmetic

The consumed candidate fields are words `0,1,4,5,9,10,11,12,13`. Configuration
ownership is `config[0]` detail baseline, `config[1]` count shift, `config[15]`
template type, and `config[16]` affine-penalty enable. The production caller
passes mode argument one.

The initial effective values are:

```text
primary = word0
filtered = word1
detail_delta = word5 - config[0]
adjusted_detail = word5 - (word0 < 5 ? 4 : 0)
```

When `word10 > 60 && primary > 4`, both effective counts gain
`1 + (word10 - 60) / 5`. With caller mode one and word 9 below 128, both lose
`1 + (128 - word9) / 10`. Division is signed and truncates toward zero. The
filtered index, primary-minus-config index, and filtered-minus-config index are
then independently clamped to `0..7`.

The 24 threshold words are three eight-word families:

```text
[INF,INF,220,216,215,212,211,210]
[INF,206,201,196,185,185,185,185]
[INF,INF,INF,207,205,203,196,187]
```

`INF` is `0x0fffffff`. When `config[16] != 0 && filtered <= 10`,
`4 * (word12 + word13)` is subtracted from both detail values.

Flag64 is set to one, then cleared exactly when all of these signed conditions
hold:

```text

detail_delta <= family3[clamp(filtered - config[1] - 7)]
primary < 14
```

Flag60 is cleared when flag64 is zero, quality is below 16, coverage is below
65, or either of the following rejects succeeds; otherwise it is set to one:

```text

  (adjusted_detail < 195 || primary < 16) &&
  (adjusted_detail < 190 || primary < 18) &&
```

control the final promotion to two: `word0 >= 8 && word1 >= 12 && word11 >= 36`.
All candidate/config loads and outputs are dwords; arithmetic wraps at 32 bits.
Normal type-12 producer ranges do not approach overflow.

The optional flag is one exactly when:

```text

detail_delta < 205 &&
detail_delta < family2[primary_index] + 10 &&
detail_delta < family3[filtered_config_index] + 10
```
