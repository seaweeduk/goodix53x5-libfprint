# FUN_18001e5b0

## Identity

- DLL: `GoodixEngineAdapter.dll`.
- Address: `0x18001e5b0`; registered callback: `EngineAdapterAttach`.
- Allocates the attachment context and initializes the profile-9 algorithm
  adapter through `FUN_180030c40 -> FUN_18002b240`.

## Context Initialization

- Attach copies dynamic configuration Glass count byte `+0x41e` into 16-bit
  context required-count field `+0x8a` at `0x18001eaea..0x18001eafb`. Values
  below 9 are clamped to 8 at `0x18001eb02..0x18001eb37`.
- The default Glass byte is `12`; the standard default `8` and coating default
  `12` are not selected by this attach path.
- Extended-info distribution is `required - 8` at context `+0x1a0`, base
  count `8` at `+0x1a4`, and zeros at `+0x1a8..+0x1b0`
  (`0x18001eb3e..0x18001eb8a`).
- Production attach writes recognition mode `1` at context `+0x94`.
- It copies configuration byte `+0x423` to 32-bit context field `+0x1c4`.
- It allocates `0x4c98` bytes at context `+0x198` and zeroes every byte.
- The same function allocates the separate `0x1c` object at context `+0x190`.
- Its address is stored in the adapter callback table at `0x1800f22b0`;
  `EngineAdapterDetach` (`FUN_18001ed10`) follows at `0x1800f22b8`. There is no
  direct in-DLL code caller for either callback.
- Attach initializes preprocessing-valid byte `+0x7c` to zero. It does not
  receive or own the usbinterface HAL image-base buffer; that base first crosses
  into this DLL in a completed sample.

## Admission And Partial Initialization

The function clears global adapter buffers `DAT_18012d840` (`0x168` bytes) and
`DAT_18012d9b0` (`0x64010` bytes) before validating the pipeline argument
(`0x18001e616..0x18001e639`). These are separate from the preprocessing
workspace and classifier/gain globals described in `FUN_180031d00.md`.

Null pipeline returns `0x80004003`. Ordinary attach requires pipeline `+0x38`
to be null and pipeline `+0x08` to equal `-1`; otherwise it returns `0x8009800f`.
The `0x1d8` context allocation is checked for failure (`0x8007000e`), zeroed,
and published at pipeline `+0x38` before the sensor-information query. Its
setup marker `+0x7c`, frame length `+0x80`, and refresh dword `+0x98` start zero.

Sensor-information query `FUN_18001d3b0(pipeline, context + 0x48)` occurs at
`0x18001e9c0`. A negative result is deliberately replaced with zero at
`0x18001e9d0`, then branches to the common exit: it retains the allocated
context and skips `FUN_180030c40`. Thus attach success alone does not establish
that profile selection and algorithm attachment completed.

A negative algorithm-attach result instead reaches the cleanup at
`0x18001ec7a..0x18001eca9`, which frees the outer context and clears pipeline
`+0x38`. This cleanup does not free the two nested allocations. Their allocation
calls at `0x18001e934` and `0x18001e976` are followed by zeroing without null
checks. Detach's ordinary nested-owner cleanup is documented in
`FUN_18001ed10.md`.
