# FUN_18003c680

## Identity

- Binary: `GoodixEngineAdapter.dll` 2.0.310.900.
- Address/body: `0x18003c680..0x18003cbe3`.
- Caller: `FUN_18003d1a0`.
- No substantive function calls; the implementation uses a large stack-owned
  priority-queue workspace.

## Behavior

This is the watershed propagation stage for the anti-fake class map. It forces
the outer border to `0xfe`, discovers unassigned interior pixels adjacent to an
assigned four-neighbor class, and queues them by the minimum absolute source-
image difference. The queue is processed in ascending difference order.

An unassigned pixel inherits a common nonzero four-neighbor class. Conflicting
neighbor classes become `0xff`; queued-but-unresolved pixels use `0xfd` while
pending. Newly exposed four-neighbors are enqueued with their absolute image
difference, preserving the 0..255 bucket order.

Border exclusion overwrites labels, not image bytes. Initial discovery includes
every nonzero neighbor label, including the excluded border, when computing the
minimum full-byte intensity difference. First-row image metadata can therefore
change queue priorities for the next row even though the first row's own labels
are all `0xfe`.

Within each difference bucket, insertion prepends to the head and removal takes
that head, giving LIFO tie order. Neighbor inheritance also includes queued
`0xfd`, excluded `0xfe`, and conflict `0xff` labels. A popped pixel assigned
`0xff` does not enqueue any neighbors. The class map, not queue priorities or
pop order, is passed back to `FUN_18003ad10`.
There is no distinct resolved-label conversion after a pop: a common neighboring
`0xfd` label can remain `0xfd` in the returned map.

## Traversal and Queue Lifetime

The first four signed-word offsets at `0x1800dfdf0` and `0x1800dfe00` are
`dx=[-1,1,0,0]`, `dy=[0,0,-1,1]`: left, right, up, down. Both discovery and
propagation use that order. Discovery traverses increasing row, then column,
and marks a queued pixel `0xfd` immediately, so later discovery pixels can use
its full-byte image difference as an assigned-neighbor priority.

Top and bottom borders are excluded first. Each interior row's left and right
border is excluded immediately before discovering that row. Its four-neighbor
reads cannot reach another interior row's side border, so excluding all four
borders before discovery gives the same reads and labels.

The 256 buckets contain head/tail pointers; nodes retain signed-word x/y and a
next pointer. Insertion updates the head, and removal follows next; tail does
not determine tie order. Initial processing starts at the lowest populated
bucket. Propagation can lower the active priority to a newly inserted bucket;
otherwise an empty active bucket advances to the next nonempty bucket. Empty
all-bucket state returns immediately.

Only zero-labelled pixels are enqueued. Enqueue changes the label to `0xfd`,
and no later assignment writes zero, so every interior pixel obtains at most
one node over the whole invocation. For profile 9 this bounds total node
consumption by `(108-2)*(88-2)=9116`, independent of priority decreases or
conflicts. Popped coordinates are checked to be strictly interior before any
neighbor access. Labels and the source image remain borrowed; only labels are
mutated, and no queue state survives the return.
