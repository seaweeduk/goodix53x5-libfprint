# FUN_1800624c0

## Identity And Interface

`GoodixEngineAdapter.dll`, entry `0x1800624c0`, body through `0x180062686`.
This note covers sensor type 12/profile 9.

```c
int32_t proximity(const int32_t transform[6], int32_t mode,
                  uint32_t sensor_type);
```

RCX supplies the six signed Q8 affine words, EDX the mode, and R8D the sensor
type. The result is a dword Boolean. The helper writes neither the transform nor
caller configuration, flags, evidence or counters. Its only call is the security
cookie checker; the proximity calculation has no algorithmic callees.

Relevant native callers are `FUN_180055a40` (direct candidate admission),
`FUN_18005d5f0` (terminal fallback), and `FUN_180058700` (late policy).

## Type-12 Table And Exact Arithmetic

Identity is `[256,0,0,0,256,0]`. Modes outside `1..5` return zero before reading
the transform: `LEA EAX,[EDX-1]; CMP EAX,4; JA` at
`0x1800624da..0x1800624e3` is an unsigned range test with dword wrapping.

Type 12 takes the alternate sensor loop at `0x180062606`, with the following
six-word limits:

| Mode | Limits `[t0,t1,t2,t3,t4,t5]` |
|---:|---|
| 1 | `[25,21,1792,21,25,1792]` |
| 2 | `[25,21,1792,21,25,1792]` |
| 3 | `[25,21,1792,21,25,1792]` |
| 4 | `[38,38,3072,38,38,3072]` |
| 5 | `[45,40,3840,40,45,3840]` |

Mode-four/five table selection occurs at `0x18006256b..0x18006259a` before
sensor dispatch. The mode-three multiplier is not used by type 12's alternate
loop. It does not double that loop's limits.

At `0x180062630..0x180062656`, each component uses this exact operation, with
`s32` interpreting a dword as signed and `u32` retaining its low 32 bits:

```text
d = s32(u32(transform[i]) - u32(identity[i]))
if d <= 0:
    d = s32(u32(identity[i]) - u32(transform[i]))
outside |= (d > limit[i])       # signed CMP / SETG
```

Both subtractions wrap modulo `2^32`. `TEST EAX,EAX; JG` selects the first
difference only when it is signed-positive. All six components are evaluated;
the accumulated outside bits are tested at `0x180062658..0x18006265b`. Return
one when no component exceeds its limit, otherwise zero.

Where the difference and its negation are representable as signed dwords, this
is the inclusive mathematical test `abs(transform[i]-identity[i]) <= limit[i]`.
Equality at either boundary returns one; one unit beyond any boundary returns
zero. For a wrapped difference of `INT32_MIN`, the reverse subtraction also
produces `INT32_MIN`, which does not exceed a positive limit in the signed
comparison. The helper has no affine-validity or coefficient-range check.
The inclusive-distance description therefore does not establish unrestricted
mathematical absolute-value semantics or a producer bound on incoming affines.

## Direct Candidate Admission

`FUN_180055a40` calls at `0x180055f3c` after signed retained count
`candidate[1] >4` and topology `candidate[10] >=30`. The arguments at
`0x180055f22..0x180055f2b` are the selected affine, decoded probe low class,
and template sensor type 12. `FUN_180070d90`, called at `0x180055cd5`, decodes
configuration word 18 into separate locals:

- `[rbp+0x1ac]`: low class; raw low bits `0,1,2,3` map to `0,2,2,3`.
- `[rbp+0x1a0]`: initial high class, subsequently accumulated by the caller.

The call is unconditional once count/topology admission succeeds. Return one
is a veto: `0x180055f43` branches to the feature-loop increment at
`0x180056c32`. The earlier retained-count maximum store survives, but overlap,
refinement, policy dispatch, contribution and evidence publication for that
feature are skipped. Return zero continues; mode zero therefore bypasses the
proximity veto. On the representable-distance domain, a transform within all
inclusive limits is vetoed, while exceeding any one limit permits continuation.
This call cannot select modes 4 or 5 from its low-class decoder.

### Final Metadata And Identify Admission

The argument belongs to the final processed image's decoded metadata. The
renderer `FUN_18006c510` has zero-return modes 0/4 and retry-status `0x7531`
modes 2/3, but renderer status and mode are not the final matcher inputs.
`FUN_180070fc0` mode zero leaves existing pixels untouched; mode four clears the
low field. With a valid alternating metadata marker, later high-mode writes
5..9 preserve existing low bits. Constructing an absent marker clears the
metadata bits before encoding. The mode switch's default clear is distinct
from those high-mode writes.

Consequently, a sequence using modes 0/4 and 0/5..9 preserves low zero only
under the additional premise that the selected image does not already carry
valid nonzero-low metadata. The allowed mode ranges alone do not supply a
universal zero-low invariant. A renderer retry does not itself establish
identify admission either: admission must be joined to the final preprocessing
status and image, and matching follows successful extraction. Extraction and
the matcher consume the metadata remaining after the ordered encoder calls.

The separate late mode-one encoder at `FUN_18006d540:0x18006ddc0` requires
packed chip-information bit two, which ordinary profile-nine initialization
leaves zero. Excluding that particular producer does not exclude preservation
of nonzero low metadata by the other paths. The owning metadata and caller
contracts are `identifyImage.md` and `FUN_180055a40.md`.

## Terminal Fallback

`FUN_18005d5f0` decodes configuration word 18 and retains
`max(decoded_low, decoded_high)` at `0x18005d6c9..0x18005d6da`, using signed
`CMOVG` at `0x18005d6d6`. After an enabled workspace returns filtered count
`>4`, it calls proximity at `0x18005d77d`. A nonzero result skips that workspace
before `geometry_seen`, overlap/detail evaluation, accumulation and ranking.

The outer caller separately requires accumulated high class `<4` and independent
primary-histogram class `<2`. Ordinary raw high `0..5` decodes to `0,1,2,4,5,5`,
and accumulation does not lower the initial class. These gates exclude terminal
modes 4/5. High zero with positive low selects the proximity veto rather than
mode-zero bypass; replacing positive high by a larger low cannot change the
mode1/2/3 limits. Failed direct count/topology admission can enable a fallback
workspace before the direct proximity call, so the two checks have distinct
consumed paths. Full enable, score, ownership and publication contracts belong
to `FUN_18005d5f0.md`.

## Late Policy And Current Source Mapping

`FUN_180058700` uses the accumulated high class as its current-mode input and
also performs explicit mode-five and mode-four proximity checks. It can
therefore use the complete type-12 table, independently of the direct caller's
low-class restriction and terminal fallback's high-class gate. The Boolean
result feeds that helper's ordered status/flag predicates; it is not by itself
an unconditional feature veto. Status one increments the separate status
counter and makes the caller skip the remainder of the feature. See
`FUN_180058700.md` for exact predicate and scalar ownership.
