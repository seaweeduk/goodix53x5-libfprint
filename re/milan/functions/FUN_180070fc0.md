# FUN_180070fc0

## Identity

- Binary: `GoodixEngineAdapter.dll` 2.0.310.900.
- Address/body: `0x180070fc0..0x18007122d`, processed-image metadata and
  optional mask encoder.

## Call Graph

- Callers: `FUN_18006c510` and `FUN_18006d540`.
- No direct callees.

## Behavior

- Returns immediately when metadata mode is zero.
- Validates the alternating low-bit prefix in the first row. If it is absent,
  clears low bits in the final eight columns and rewrites columns before them
  as even=0, odd=1.
- Encodes modes 1..4 in first-row columns `width-8` and `width-7`; modes 5..9
  use columns `width-5` through `width-3`.
- Modes 1, 2, 3, and 4 write the low-bit pairs `10`, `11`, `01`, and `00`
  respectively at `width-8,width-7`. Thus mode 4 explicitly clears the packed
  low field. Modes 5..9 modify only the separate high field. If the alternating
  prefix already exists, these modes preserve the incoming low field; otherwise
  prefix initialization clears it. Mode zero returns before either action.
  Consequently, following mode 4 preserves a zero low field, but following mode
  zero alone does not establish zero: preexisting valid metadata can survive.
  See `FUN_180055a40.md` for the decoded-low-class admission consumer.
- When the apply-mask flag is set, column `width-6` marks mask presence and
  rows after the first carry the inverse mask in each pixel's low bit. If a
  mask marker was already present, only newly masked pixels have their low bit
  cleared.
- The ordinary profile-9/type-12 path composes two calls in order. The first is
  owned by `FUN_18006c510` at `0x18006caff`: mode is that function's
  post-render decision and apply-mask is the independent residual-mask flag
  produced by `FUN_18006c0b0`. A set flag uses that helper's residual mask; a
  clear flag uses the caller's selected render/selection mask. The residual
  allocation remains live until this call returns. Mode remains zero when
  post-render admission is false. An admitted path starts at mode 4, can
  select mode 2 on retry, and selects mode 3 when the subtype-12 retry predicate
  holds while retained sample count is below 100 and the minimum render metric
  is greater than 85.
  Retry is selected by raw disagreement greater than 40 or subtype-12
  normalized disagreement greater than 33. The alternate normalized threshold
  greater than 20 requires purpose 1 with configuration state 2.
- `FUN_18006d540` owns the ordinary second call at `0x18006dd34`. Its mode and
  apply-mask are the separate outputs of `FUN_18006b290`; this call consumes
  the first call's already encoded image. The first mode/apply pair is therefore
  not a constant and cannot be replaced generically with mode 3/apply-mask zero.
- The separate call at `0x18006ddc0` is a later conditional mode-1 encoding on
  the low-quality retry path. It requires packed configuration bit2, which is
  clear in profile9 (`0x36160061`), and is excluded from the type-12 path.
- The first call follows candidate publication, post-render status selection,
  and admitted-arm retained-workspace publication. The second call follows the
  first and classifier mode selection. Quality/coverage calculation and final
  result-to-selected-workspace synchronization occur after both calls, so a
  second mode-zero call does not overwrite first-call low-bit or mask changes.
- In a mode/apply composition `3/0` followed by `9/1`, the second call preserves
  the first call's low3 field while writing high5 and applying its mask. For
  `0/1` followed by `8/1`, the first call does nothing: mode zero returns before
  applying its nominal mask flag.
- The function changes only pixel low bits.
- For a nonzero mode outside 1..9, the default arm clears both low-field bits
  and all three high-field bits before the optional mask step. This arm does
  not describe any of the ordinary profile-9 producer modes above.
- A mask already present in a valid-prefix image is intersected with each
  subsequent applied mask: for rows after the first, the surviving usability
  bit is `old_bit && (mask[pixel] == 0)`. A previously absent mask is initialized
  to `mask[pixel] == 0`. The first row never receives per-pixel mask values;
  its marker and fields remain metadata. A call with apply-mask zero preserves
  a prior mask marker and all encoded mask pixels.

## Type-12 Decoder Handoff

`FUN_18006fb10` validates the same prefix and reverses the low-field encoding;
`FUN_180070d90` then maps the packed fields to classes:

| Encoder mode | Packed field written | Decoded class |
| --- | --- | --- |
| 1 | low1 | low2 |
| 2 | low2 | low2 |
| 3 | low3 | low3 |
| 4 | low0 | low0 |
| 5 | high1 | high1 |
| 6 | high2 | high2 |
| 7 | high3 | high4 |
| 8 | high4 | high5 |
| 9 | high5 | high5 |

The untouched field is preserved only when the prefix was already valid;
prefix initialization clears it. Mode0 preserves the entire image and does
not establish prefix validity or mask presence.

Final quality consumes the metadata-encoded byte image, not a low-bit-cleared
copy. In particular, changing255 to254 changes the exact255 predicate in
`FUN_1800446f0`, independently of the embedded usable-pixel mask decoded by
`FUN_18006fb10`. Quality's propagated validity, its rewritten patch mask, and
the decoded broken-pixel mask are separate owners; one cannot replace another.

On a status-zero ordinary type-12 preprocessing call, the first mode is0 or4:
modes2/3 carry post-render retry, and second mode9 carries classifier retry.
The second call has mode0 or5..8 and cannot introduce a nonzero low field.
Consequently a nonzero decoded low class on a successful image requires
first mode0 **and** an already valid alternating prefix with at least one
of columns100/101 odd in the selected, freshly rendered108-wide image.
For second mode0 an invalid prefix remains invalid and decoding yields the
caller-initialized zero; for modes5..8 it is repaired but both low bits are
cleared. Rendering the complete image excludes stale workspace contents,
but does not by itself establish a low-bit constraint on the new pixels.
The direct matcher consumer is owned by `FUN_180055a40`.
