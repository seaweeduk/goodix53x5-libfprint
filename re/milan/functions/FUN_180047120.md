## Behavior

Parsed scalar index 6 is packed tag `bb` and live feature dword `+0x128`.
This function is its authoritative producer. It first ensures every feature has
the derived packed-bit mask at `+0x140`, then processes features in ascending
index order:

```text
effective_rows = rows
effective_columns = columns
if half_resolution:
    effective_rows >>= 1
    effective_columns >>= 1

for feature i:
    feature[i].overlap_count = 0
    feature[i].bb = effective_rows * effective_columns
    if feature[i].b5 != 0:
        residual = clone(feature[i].mask)
        for feature j in ascending index order:
            if j != i and feature[j].b5 != 0:
                transform j's footprint into i's coordinates
                area = build clipped intervals and clear them from residual
                if half_resolution:
                    area *= 4
                if area * 100 > rows * columns * 40:
                    feature[i].overlap_count++
        feature[i].bb = popcount(residual)
        if feature[i].bb < 20:
            feature[i].bb = 0
```

Thus inactive features receive the reduced-domain area. Production geometry is
`(88 >> 1) * (104 >> 1) = 2288`. Active features receive their residual unique
mask weight after every other active transformed footprint has been removed.
The subtraction is destructive and ordered, but each feature starts from its
own fresh mask clone. Optional `c7` at `+0x150` is never read.

For active feature `i`, it obtains the reference transform from slot
`feature[max(i,reference)].b6 + min(i,reference)`. If `i<reference`, it inverts
the canonical stored transform; if `i>reference`, it copies it directly. It then
has feature-to-reference. For each other active feature `j`, it obtains the
opposite reference-to-`j` direction, then composes
`reference-to-j` after `i-to-reference` to form `i-to-j` for overlap accounting.
The outer lookup is `0x1800472ad..0x180047306`; the inner lookup and composition
are `0x180047358..0x1800473c4`.

Both lookups read only slot affine `+4` and ignore the leading rank. A missing
loaded edge therefore contributes its decoder-initialized identity affine.
Natural graphless templates keep all features inactive and do not enter these
lookups. The related source owner is
`goodix_milan_template_normalize_unpacked` in `milan/template/lifecycle.c`.
The function reads but does not change relation records, their leading values,
feature `b6`, live reference `+0x87d8`, or graph-established `+0x87e4`.

The inactive skip is also the graphless enrollment-deletion contract. A live
reference of `-1` is valid while graph-established is zero and all live active
markers are zero: unconditional initialization writes `bb=2288` and
`overlap_count=0`, then `0x180047278` branches to `0x1800474f7` without reading
the reference. Reference range is required only if an active feature enters the
transform path.

Evidence includes the `+0x140` materialization loop at function entry, relation
stride `0x1c`, transformed overlap call to `FUN_180072600`, the popcount table at
`DAT_1800df590`, and the signed `< 0x14` residual clamp at
`0x1800474ea..0x1800474f1`.

## Integer And Call Boundaries

Dimensions, effective-domain multiplication, interval-area accumulation,
half-resolution area scaling, `area * 100`, `rows * columns * 40`, popcount
accumulation, `+0x128`, and `+0x148` are signed or stored 32-bit values. Assembly
uses `SAR`, 32-bit `IMUL`/`ADD`/`INC`, and signed comparisons. There is no
saturation or visible overflow guard. The strict overlap predicate is
`area * 100 > rows * columns * 40`; equality does not increment. The residual
predicate is `< 20`, so 19 becomes zero and 20 is retained. These unchecked
boundaries describe the DLL; production profile-9 dimensions and mask lengths
remain small and positive.

`FUN_180047550` invokes this function after type-12 unpack, so a serialized `bb`
is parsed and then recomputed from masks and relation state. In study,
`FUN_1800469f0` invokes it when append reaches capacity and after actions 3 or 4.
Below-capacity append preserves prior features' `bb` and initializes the new
feature's `bb` to zero. Action 2 bypasses normalization and retains the installed
feature scalar rather than recomputing it. A no-update result does not enter the
mutator.

## Composition And Clipping Order

`FUN_180068860(reference_to_j, i_to_reference, output)` takes signed 64-bit
products, shifts each two-product sum right by eight, narrows to a dword, adds
the outer translation, and normalizes only the four linear coefficients through
`FUN_1800687c0`. Only after that call does this normalizer arithmetic-shift
translation words 2 and 5 right by one (`0x1800473ee..0x180047409`). Negative
odd translations therefore round toward negative infinity at this final step;
halving stored translations before inversion or composition is not the contract.
Inversion uses signed division toward zero in `FUN_1800689a0` and is not followed
by linear normalization until composition.

When its signed row-origin and endpoint arithmetic does not overflow,
`FUN_180071370(44,52,44,52,transform,intervals)` computes the inclusive integer
destination cells whose Q8 mapped coordinates lie in `[0,51*256]` and
`[0,43*256]`. Its row helper `FUN_180073090` uses signed division followed by
endpoint correction, so fractional endpoints are admitted by the inequalities,
not by rounding mapped coordinates to the nearest source pixel. The two axis
intervals are intersected with `[0,51]` and summed before mask removal. The
returned area counts the entire clipped rectangle footprint, independently of
either feature's mask and independently of earlier removals. See
`FUN_180072600.md` for the destructive residual operation.

In this domain the neighbor predicate is equivalent to integer area `>=916`:
`915*400 < 88*104*40 < 916*400`. Exact 40-percent equality is unattainable for an
integer half-resolution area. `overlap_count` is a descriptive name for live
`+0x148`, not a recovered vendor identifier.

The cached input masks, inline masks, graph, and relation affines are unchanged
by residual subtraction. Each active feature starts from a fresh clone, and
neither `bb` nor the previous neighbor count participates in its own production.
With the same cached masks and graph, repeating normalization is idempotent.

## Queue Timing

Queued follow-up uses the ordinary `FUN_1800469f0` call site, so this normalizer
retains its normal selector timing. If a queued append reaches capacity, or a
queued selector commits action 3/4, normalization completes before the returned
index is placed in `FUN_18005d330`'s continuation ring. Later queued re-matches
therefore observe normalized `bb` and masks. A below-capacity queued append and
queued action 2 bypass this helper.

This immediate normalization must not be confused with final type-12 order/tail
generation. `FUN_1800607b0` remains after complete queue processing. Action-5
queue continuation preserves this function at its ordinary selector boundary
while final order/tail generation remains deferred.

## Full-Capacity Retained Ordering

The primary type-12 dispatcher has an additional call through `FUN_180047550`
after retained refresh and before selector policy. It runs only for
`retained_count>0 && retained_flag==1 && feature_count==maximum_features`.
Because retained refresh changes `b5` and reference relations first, this call
recomputes every feature's `bb/+0x148` from the refreshed graph. The target set is
all live features in ascending index order, including inactive, reference,
nonreference, retained, and nonretained entries.

The post-action call in `FUN_1800469f0` is retained. Full retained actions 3/4
therefore execute this function twice: once before policy and once after
replacement. Action 0 executes only the pre-policy call. Flag-zero action 2
executes neither, and count-zero flag-one action 4 executes only the
post-replacement call. A 39-to-40 append executes only the post-append call.

The pre-policy and post-replacement calls consume different active/reference
owners when replacement changes the graph. The second call cannot in general be
removed merely because the same object was normalized before policy selection.
