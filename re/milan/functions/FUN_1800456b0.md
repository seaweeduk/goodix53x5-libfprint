## Feature Copy

The function reads the old feature count `n` from template `+0x1c`, selects the
already allocated owner at pointer slot `+0x28+n*8`, and increments the live
count before copying feature material.

It copies the probe's three matrix-backed bitmaps, the inline blocks at
`+0x28..+0xe8`, derived mask owner `+0x140`, both initial dwords, and the fixed
scalars `b7/+0x118`, `b8/+0x11c`, `b9/+0x120`, and `c0/+0x14c`. Null optional
matrix owners at probe `+0x10` and `+0x18` produce null destination owners.
The destination live-only pointer at `+0x20` is cleared.

Live optional `c7/+0x150` is neither read nor written. The preallocated
destination therefore retains its initialized zero, so packing omits `c7` even
when the identify probe carried a nonzero value.

`FUN_180037690` receives the template maximum-record count and a transform-mode
predicate equivalent to:

```text
((template_type - 9) & 0xfffffff6) != 0
```

Type 12 selects nonzero mode. After bounded copying, each destination record has
its dword at `+0x24` and qword at `+0x30` cleared. The probe remains unchanged,
and the gallery slot owns independent matrix and record allocations.

The helper itself does not copy the probe anti-fake owner at `+0x160`.
`FUN_1800469f0` has already replaced four probe anti-fake registration scalars
with matched-feature values, then copies the complete patched anti-fake object
into the appended owner immediately after this function returns.

## Row And Lifecycle Initialization

Before append, template `+0x24` is the next logical relation-slot number `P`.
The function writes new `b6/+0x114=P`, then initializes exactly `n` slots


It advances `+0x24` to `P+n`. For an ordinary admitted template,
`P=1+n*(n-1)/2`, so the new row owns `P..P+n-1` and the new next slot is
`1+(n+1)*n/2`.

The scalar and ordering tail is:

- `order[n]=n` at template `+0x87e8+n*4`; existing order entries are untouched;
- new `bb/+0x128=0`, `ba/+0x124=1`, `bd/+0x130=0`, and `bc/+0x12c=n`;
- new `b7`, quality, coverage, and `c0` retain the copied probe values;
- template append counter `+0x8cfc` increments once with dword wrap.

Existing gallery features have already passed through the type-12 decoder,
which changes a packed `b7 == record_count` endpoint to `record_count-1`. The
new feature does not pass through that decoder: append copies the live probe's
`b7` unchanged, so a newly appended all-low-class probe may retain
`b7 == record_count`, including on the `39 -> 40` normalization path.

The caller subsequently writes new `be/+0x134` from the matched feature and new
`b5/+0x110` from matched active state. For an unestablished graph it sets the
matched feature as reference, activates both matched and appended features,
installs the append relation, and then replays positive retained evidence. For
an established graph it installs the append relation only when matched `b5` is
exactly one. An append reaching configured capacity is normalized before the
selector returns; a smaller append is not.

## Failure Behavior

The function trusts the live feature count, preallocated destination owner,
relation storage, and configured record bound. It does not return an error.
Matrix clone helpers can silently leave a destination unchanged for null
arguments, while failed native allocations are not converted into a recoverable
append result. The caller has already assigned Action 1 before entry and has no
rollback path.
