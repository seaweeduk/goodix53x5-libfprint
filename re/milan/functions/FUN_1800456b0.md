## Recovered Behavior

The function claims the next preallocated feature slot, clones the probe's three
matrix pointers, fixed inline fields, derived mask, and bounded records, then
initializes relation slots and append lifecycle state. The record-copy mode is
selected from the template type; production type 12 passes nonzero mode to
`FUN_180037690`.

This helper has no evidence, quality, coverage, or score admission policy.
`FUN_180044fc0` and `FUN_1800469f0` select append action 1 before calling it.
Consequently enrollment-1 sequence 5 (`+0x688 == 0`) never reaches this helper,
while enrollment-2 sequence 5 (`+0x688 == 1`) does; no append-local threshold is
inferred from those rows.

The live scalar copy boundary is exact in assembly:

- source `+0x14c` is copied to destination `+0x14c` at
  `0x18004589d..0x1800458a3`;
- optional packed-`c7` live field `+0x150` is never read or copied;
- the destination slot is preinitialized, so its `+0x150` remains zero;
- the generic serializer emits tag `c7` only for a nonzero live field.
- live `bb` at destination `+0x128` is explicitly initialized to zero at
  `0x18004584a`; ordinary below-capacity append does not normalize prior fields.

The helper also writes the appended feature index to exactly one order slot:
template `+0x87e8 + old_feature_count * 4` at `0x18004585e`. It does not reorder
existing entries. For sequence 2 this installs index `8` after the existing
identity prefix; `FUN_1800607b0` performs the later accepted-study reorder.
The scalar-only independent reconstruction therefore starts from
`[0,1,2,3,4,5,6,7,8]`, not from allocation order or feature-pointer order.

Append assigns the new feature's persisted `b6` relation-row base from the
template's current logical relation-slot count at `+0x24`, initializes exactly
`old_feature_count` new incident records to `[leading=-1, affine identity]`,
then advances `+0x24` by `old_feature_count`. This produces row bases
`0,1,2,4,7,11,...` and logical capacity `C(50,2)=1225`; it does not materialize
an edge merely because a feature was appended.

The exact scalar tail relevant to first-graph setup is independent of graph
state: for old feature count `n` and old logical slot count `P`, the helper
returns new index `n`, writes new `b6=P`, advances slot count to `P+n`, writes
`order[n]=n`, initializes new `bb=0`, `ba=1`, `bd=0`, `bc=n`, and increments
template append counter `+0x8cfc` once. It does not read or write `f2/f5`.
`FUN_1800469f0` subsequently overwrites new `be` and `b5`, establishes the graph
when needed, and materializes the anchor.

Thus a serialized identify probe may retain nonzero `c7` for immutable matching,
while the same probe copied through the `templateStudy` append context is packed
without the optional five-byte tag. This rule is independent of feature index,
sequence, and the particular packed value.
