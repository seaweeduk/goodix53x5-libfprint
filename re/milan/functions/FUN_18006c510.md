## Profile-9 Inputs And Selection

- The first argument is the operation purpose forwarded by `FUN_18006d540`.
  Profile 9 fixes packed subtype 12 and field 7 to zero. The subtype-12
  purpose-1 alternatives in this helper require field 7 equal to 2 and are
  therefore dead for profile 9; the independent quality arm remains live.
- `FUN_18006c0b0` derives disagreement from the current 16-bit working plane
  and current render mask. It does not consume the retained broken-level class
  plane, component-age plane, or history counters.
- For subtype 12, the working-plane selector passed to `FUN_18006c0b0` is the
  persistent 16-bit plane at preprocessing-context offset `+0x13244`. The
  helper's first optional output is the working plane produced by the preceding
  normal update with its temporary secondary divisor, and its second optional
  output is the reciprocal application-gain plane.
- The two initial render-metric slots start at 200. The selected-plane scalar at
  preprocessing-context offset `+0x26484` selects which slot subtype 12
  evaluates: one selects the first slot and zero selects the second. Subtype 11
  evaluates both, but profile-9 subtype 12 does not. The retained metric is the
  minimum of the enabled slots and remains unchanged if the later fallback
  render is evaluated. Thus an ordinary subtype-12 selector-zero call can
  populate the second source slot while the first remains 200; this slot
  ordering does not make the later reciprocal-plane result the retained metric.
- For subtype 12, the quality arm first compares the selected byte image with a
  rerender of the primary optional working plane. A minimum difference strictly
  above 75 selects the arm directly. A minimum difference in `56..75` causes a
  rerender of the secondary optional plane and selects the arm only when that
  difference is strictly below 80.
- The quality differences consume the selected byte image, current
  selection/component mask, secondary working plane, and reciprocal
  application-gain plane. The helper runs after candidate selection, so its
  metadata and calibration effects do not change which candidate supplied the
  current output image.

## Conditional Post-Render Update

- For profile-9 subtype 12, only the quality arm can enter the outer block. The
  field-7/component/purpose alternative is unreachable under the profile-9
  configuration.
- The nested calibration update additionally requires the saved workspace
  sample count to be strictly below 100 and disagreement from `FUN_18006c0b0`
  to be strictly above 90 (`0x18006c9c3..0x18006ca1a`).
- Before the nested `FUN_1800668f0` call, the helper saves the workspace sample
  count, writes 5 at `0x18006ca06`, calls at `0x18006ca12`, and restores only
  the saved count at `0x18006ca17`.
- The nested call receives the normalized live frame, the hole-filled and
  recounted workspace clone from `FUN_18006bce0`, the normal call's calibration
  selector and map descriptor, a null optional-output pair, the same profile
  configuration, and the same setup/calibration context.
- Normal and nested calls alias the same persistent calibration and gain maps
  and the process-global auxiliary counter, but use different mask objects.
  The nested call's forced count 5 bypasses `FUN_1800672e0`'s profile-9
  low-count application-map reset for counts `1..3`.
- The nested `FUN_1800668f0` return is not used. Writes through aliased
  persistent maps and scalars remain live when the workspace count is restored.
  Its subtype-12 mask-admission and `FUN_180064170` temporal-stability gates are
  evaluated independently of the preceding normal call.
- The nested call also reevaluates the ready transition in `FUN_180067500`
  before either update gate. Forced workspace count 5 prevents setting ready;
  auxiliary count at least 15 clears it. This can observe a count advanced from
  14 to 15 by the preceding normal call. Restoring the workspace count does
  not restore ready. Ready selects the nested rendering divisors, not the
  auxiliary-map or calibration-map update inputs. After the nested call,
  this helper copies the already selected byte image into both retained byte
  planes; it does not rerender that image from the nested working plane.

## Status And Lifecycle

- The first metadata mode is initialized to zero before profile dispatch and
  remains zero when the outer post-render arm is not entered. Entry through the
  profile-9/type-12 quality arm initializes it to mode 4. A raw-disagreement
  retry or subtype-12 normalized-disagreement retry changes it to mode 2; on
  that retry path retained sample count below 100 and minimum render metric
  above 85 change it to mode 3. These are the only profile-9/type-12 writes to
  modes 0, 2, 3, and 4.
- The profile-9/type-12 quality arm is entered when the minimum primary render
  difference is strictly above 75, or when a primary difference in `56..75`
  causes the secondary render difference to be evaluated and that difference
  is strictly below 80. The mode-zero branch is the negation of this admission,
  not a retry/disagreement branch.
- Once the profile-9 quality arm enters the outer block, raw disagreement
  strictly above 40 sets status `0x7531` (`0x18006ca24..0x18006ca57`).
- Subtype 12 then normalizes disagreement as signed integer
  `disagreement * 100 / mask_percent` when the signed mask percentage at
  context offset `+0x0e` is positive. Normalized disagreement strictly above 33
  sets `0x7531` (`0x18006ca57..0x18006ca8d`). The alternative threshold 20 also
  requires purpose 1 and field 7 equal to 2, so it is dead for profile 9.
- A nested update requires raw disagreement strictly above 90 and therefore
  necessarily occurs on a status-bearing path. Status `0x7531` is a retry/status
  result, not an allocation or calibration-call failure.
- The raw and normalized retry checks precede the first `FUN_180070fc0` call.
  The raw check first selects mode 2 for subtype 12, and the subtype-12
  normalized check selects mode 2 independently before applying the same
  below-100/above-85 mode-3 refinement. The purpose-1 normalized threshold 20
  and its mode transition require configuration field 7 equal to 2 and remain
  dead for profile 9, whose field is zero.
- The first metadata apply flag is the independent residual-component flag from
  `FUN_18006c0b0`. When set, the encoder mask is that helper's residual mask;
  otherwise it is the selected render/selection mask supplied by the caller.
  The residual mask is helper-owned temporary storage retained through the
  first encoder call and freed only after that call returns. Mode zero returns
  before applying a nominally nonzero flag.
- Candidate selection publishes the selected byte image before this helper is
  called. On an admitted arm, the helper publishes both retained result
  workspaces before encoding metadata into the already selected image. The
  encoder call at `0x18006caff` follows status and mode selection and precedes
  the caller-owned classifier metadata call, quality/coverage calculation, and
  final selected-workspace synchronization.
- `FUN_18006d540` maps `0x7531` to caller result field 0 value 2 and sets bit 3
  of result field 9. The helper does not roll back persistent preprocessing
  writes before returning that status.
- WBF `EngineAdapterClearContext` prepares the attached pipeline for another
  operation, and Goodix clear-context does not call `preprocessor_exit`.
  Successive operations within one attachment can therefore observe retained
  preprocessing state. `EngineAdapterDetach` owns attachment teardown; exact
  idle, power, detach, and DLL-unload scheduling remains external to this
  binary. See `FUN_18001f090` and `FUN_18001ed10`.
