# FUN_18006c510

## Audit Scope

preprocessor's purpose pointer. This note was created before first Ghidra
inspection during the independent methodology audit.

## Questions

- Does purpose `0` versus `1` change profile-9 enrollment output or status?
- Is this helper active for packed subtype 12?

## Audit Findings

- `FUN_18006d540` enables this helper for subtype 12 and passes the integer
  reached through exported argument 2 as this function's first argument.
- The helper reads that integer immediately and uses value `1` in subtype-12
  threshold/status branches. Purpose is therefore semantically active and
  cannot be assumed interchangeable between production enrollment (`1`) and
  the oracle's hardcoded value (`0`).
- The earlier purpose-1/TX-off eight-capture runs produced the same 99,277-byte
  final template across independent processes. They are historical after the
  corrected paired-TX-on setup established the 99,684-byte authority.
- Historical purpose-0 enrollment artifacts remain observations of the wrong
  operation mode and must not be used as production enrollment authorities.

## Profile-9 Static Reachability

- `ppp_param_init(9)` fixes subtype 12 and `field7 == 0`. The component/purpose
  arm requiring `subtype == 12 && field7 == 2` is therefore statically dead for
  profile 9. The independent quality arm remains live.
- For subtype 12, the quality arm compares the selected result against a render
  of the first optional plane. The strict direct threshold is 75. If that
  metric is in `56..75`, it renders the second optional plane and accepts the
  quality arm only when that metric is strictly below 80.
- `FUN_18006c0b0` runs before those comparisons. Its component decision selects
  either the caller's threshold-100 selection mask or a residual component mask
  as the `FUN_180081ea0` comparison mask. Its returned disagreement must then be
  strictly above 90, and the saved workspace count must be below 100, for the
  nested update to execute.
- No profile field or range check bounds either mean-absolute-difference metric
  below 75 or the disagreement below 91. The branch is consequently not
  statically eliminated by the profile-9 configuration. A production-frame
  witness is still required before claiming observed hardware reachability.

  therefore always status-bearing when it executes.
- The mode passed to `FUN_180070fc0` starts at 4, becomes 2 when profile field 5
  is nonzero, and can become 3 for selected subtype masks when count is below
  100 and the minimum quality metric is above 85. Subtype 12 additionally
  normalizes disagreement by the mask percentage at context offset `+0xe` and
  selects mode 2 or 3 under its own strict thresholds.
- `FUN_18006d540` maps `0x7531` to caller result field 0 value 2 and later sets
  bit 3 of result field 9. This is a retry/status effect, not an allocation or
  calibration-call failure.

## Controlled Retained-State Matrix (2026-08-06)

A temporary RE-only corpus repeated one natural coverage-100 profile-9 frame
before a fixed target. Linux and the approved DLL remain exact through three
preludes (target use 4). Starting with four preludes (target use 5), Linux alone
returns `0x7531`; native returns success and continues matching. The processed
bytes remain exact at that boundary, proving the immediate divergence is in
retained post-render state or status selection rather than the selected image.

The mismatch remains through 5, 6, 10, 15, and 19 high preludes. At 20 preludes
(target use 21), processed metadata also diverges, coincident with activation of
the separate retained long-history path. Do not alter retry thresholds from
this repeated-frame witness. Recover the complete type-12 state updates feeding
disagreement, nested update, and long-history activation first.

An exhaustive controlled-generation replay of the expanded hardware snapshot
compared 141 operations and found 140 exact. The only difference was the known
generation-27 target at action epoch 59: processed bytes and the resulting
candidate differed, while the other repeated unknown-finger sequences remained
exact. Replaying preprocessing continuously from the start of the capture
session made epoch 59 exact, but this is lifetime-sensitivity evidence only.
WBF schedules adapter detach and DLL unload outside this binary, and
`preprocessor_exit` does not clear every recovered process global. Do not use a
Linux capture-session UUID as an authoritative native DLL lifetime without an
external Windows lifecycle trace.

An earlier apparent set of queue differences was invalid: Linux captured queue
occupancy after match, while the oracle measured occupancy after study. Those
fields describe different points and must not be compared.

## Action-2/Action-7 Reachability Control

A fresh unmodified replay and a DLL with only the call at `0x18006ca12` replaced
by NOPs produced byte-identical action-2 processed images, templates, complete

the independent action-7 enrollment normally. The production DLL and frozen

Therefore the conditional post-render update is not reached by either supplied
enrollment lifecycle. Its static contract remains valid, but it cannot explain
their relation difference and must not be forced into native action2/action7
processing.
