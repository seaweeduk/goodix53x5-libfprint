## Recovered Behavior

For every pixel, the function interprets the orientation byte with unsigned
arithmetic. If `(uint8_t)(orientation - 8) < 165`, direction is
`(orientation - 8) / 15 + 1`; otherwise direction is zero. This yields the 12
direction rows at table `0x1800f31d0`, each containing seven signed 32-bit
`(x,y)` offsets. The admitted byte interval is exactly `8..172`; within it
the integer subtraction is nonnegative. Bins start at `8,23,...,158`, and
direction zero handles `0..7` and `173..255`. Tap weights are

Each tap is admitted only when both coordinates are in bounds. Edge pixels
therefore discard out-of-image taps rather than reflecting or clamping them,
and divide the signed 32-bit weighted sum by the retained weight sum using
`CDQ; IDIV EDI` at `0x18007f40c..0x18007f40d`. Every table row includes the
center with weight 8; the full weight sum is 22. On separate, nonempty byte
images the retained denominator is in `8..22`, numerator in `0..5610`, and
the quotient in `0..255`. Signed truncation is therefore identical to unsigned
floor division in current code. The `0xff` zero-denominator fallback at
`0x18007f418` cannot be selected by this table on the normal image domain.

Rows and columns are visited in increasing order. Input and orientation are
read-only; the native wrapper supplies a separate output allocation. Output is
independent per pixel under that separation and cannot change record count or
ownership. Border normalization uses only retained tap weights, without adding
a rounding bias.
