## Matrix Index And Direction

For pair `(i,j)`, `i<j`, the canonical slot is
`template.features[j].b6 + i`; each feature's `b6` is live offset `+0x114` and
packed scalar tag `b6`. Storage is canonical in lower-index/higher-index pair
slots and transform direction is higher-index feature to lower-index feature.
When the supplied transform is opposite that direction, this helper
inverts it before storing. The serializer later copies the canonical record and
never changes direction.

## Exact Reference-Reanchor Arithmetic

The reference branch is direction-specific at the fixed-point operation level,
not merely affine-algebra equivalent. For a supplied new-reference-to-old-
reference transform `X`:

```text
lower feature:  stored reference->feature S := compose(S, X)
higher feature: stored feature->reference S := compose(invert(X), S)
```

Assembly `0x180045dd0..0x180045df5` passes the lower slot affine and `X`
directly to `FUN_180068860`. Assembly `0x180045db3..0x180045dbb` computes
`invert(X)`, and `0x180045e49..0x180045e5b` composes that inverse directly with
each higher slot. Both paths preserve the existing leading word and write only
the six affine words.

Current source at production head `c182b140` is exact for higher features, but
`goodix_milan_relation_matrix_reanchor()` canonicalizes a lower slot by
inverting `S`, composing `invert(X)` with `invert(S)`, and inverting the result.
That is algebraically `compose(S, X)`, but it is not byte-equivalent because
the integer inverse divides/truncates and composition normalizes. A focused
witness is:

```text
S = [241,-88,25127,88,241,-13811]
X = [268,74,-16487,-74,246,18204]
DLL direct compose      = [256,-16,3348,16,256,-2342]
current canonical route = [254,-17,2979,17,254,-2364]
```

The reference-target branch is policy-reachable through the ordinary matched-
residual-zero return in `FUN_180045530`; with retained flag exactly one,
`FUN_1800469f0` assigns action 4 and calls this helper. Action 3 shares the same
helper. Read-only parsing of the maintained 450- and 643-operation artifacts
finds `290+442` action-4 rows. The first set has no reference target; the second
has six. Five use reference zero. The reference-one witness is verify epoch 184:
its 36-record star omits lower slot 1, so only the byte-exact higher branch
executes. No captured natural operation exercises a defined lower slot, and the
arithmetic difference remains a synthetic-valid generic-input distinction, not
an actionable production discrepancy.

The same source primitive also handles a retained-evidence entry whose index is
the current reference. DLL sibling `FUN_180046430` uses the same direct operation
split: `0x180046520..0x18004654d` composes a lower slot with `X`, while
`0x180046507..0x18004650f` and `0x1800465af..0x1800465c2` invert `X` once and
compose it with each higher slot. The generic lower-slot arithmetic distinction
therefore also applies to retained-reference prepass reanchoring. Known retained-
evidence producers list inactive features and have not demonstrated that case
naturally.

The DLL's direct lower-slot composition remains part of its generic contract.
Production `c182b140` retains the canonical invert-compose-invert route because
the strict natural authority exercises only the byte-exact higher side.
