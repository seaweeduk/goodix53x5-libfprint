- Consumes the normalized live frame plus the initialized generation workspace,
  allocates temporary gain/calibration planes, and writes the working frame at
  workspace `+0x13244`.
- Profile 9 takes the specialized branch selected by the packed profile bitmask;
  it scales temporary live/setup terms by three before the downstream
  calibration stages.
- For subtype 12, `FUN_180067500` forms the first update source as
  `max(9000 + 3 * (normalized_setup - live), 0)`. The zero clamp applies after
  adding the 9000 baseline; moving it inside the subtraction is not equivalent

- `FUN_180067500` always supplies that subtype-12 source to final working-frame
  construction. Its strict 90% mask-count decision controls gain and persistent
  map evolution only. A non-admitted frame is rendered from the same source
  through the previously accumulated application and auxiliary gain maps, not
  through bare unity and not from generic `max(setup - live, 0)`.
- Output construction depends on several persistent workspace maps and scalar
  controls initialized before the live call. The setup plane alone is not the
  complete input state.
- The normal call and the conditional post-render call alias the same
  calibration workspace. The post-render call occurs after candidate selection,
  so it can change later calls without changing the already selected bytes.
- The normal call optionally receives a two-pointer output pair. For subtype 12,
  the first plane is the signed-baseline source divided by the secondary gain
  plane; the second is `8000 * 8192 / application_gain`, with the zero-divisor
  fallback preserving the DLL's 16-bit truncation. `FUN_18006c510` consumes
  these planes for quality rerenders.
- `FUN_180067500` receives the temporary primary divisor at descriptor slot 0,
  persistent auxiliary/application maps at slots 1/2, the persistent ready flag
  at slot 5, the temporary secondary divisor at slot 6, and the secondary
  auxiliary map at slot 7. The caller's final write loop consumes slot 0; the
  optional rerender path consumes slot 6. These aliases exclude the earlier
  assumption that one fused application/auxiliary product represented every
  subtype-12 call.
- Before that call, `FUN_1800672e0` receives initialization global
  `0x1801efbf8`, the calibration workspace beginning at `0x180219670`, and
  auxiliary-map sample counter `0x1801efbf4`. `FUN_180067500` then receives the

- Slot 5 always points to process-global RVA `0x1efbfc`. The two LEA/data xrefs

- The post-render call deliberately passes a null optional-output pair. It
