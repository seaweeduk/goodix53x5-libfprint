## Behavior

- Counts samples inside the two-pixel border that fall strictly between a
  profile-selected low/high pair.
- Profile value `0x0c` selects bounds `100 < sample < 0x0ed8` and a nominal
  required percentage of 15. A zero fifth argument overrides the required
  percentage to 85; a nonzero value retains the profile percentage.
- The fifth argument is not exported preprocessing purpose. On the production
  path it is the calibration/validation-ready value loaded from
  `DAT_180249afc`: `preprocessor` passes that global by pointer as internal
  `FUN_18006d540` argument 6, and `FUN_18006d540` passes `*argument6` here.
  Exported identify purpose 0 instead arrives as internal argument 10 and is
  consumed later. `preprocessor_init` reaches the same helper before setting the
  ready value, so profile-9 setup uses the 85% override. Normal initialized live
  preprocessing has ready value 1 and uses 15%.
- Returns whether the valid-sample percentage strictly exceeds the selected
  threshold. It does not transform or invert pixels.
- Dimensions and loop coordinates are read as signed 16-bit values. Each copied
  sample is loaded with signed 16-bit extension for the two strict comparisons;
  the preceding unsigned clamp limits profile-9 values to `0..0x0fff`, so the
  signed load cannot make a production sample negative.
- On the production `88x108` path, the loops cover rows `2..85` and columns
  `2..105`, exactly `84x104 = 8,736` samples. The geometry is not a cropped
  pointer: indexing remains `row * 108 + column` in the full frame.
- Total and valid counts are signed 32-bit accumulators. The final instructions
  form both products with signed 32-bit `IMUL`, compare
  `100 * valid_count > required_percent * total_count` as signed 32-bit values,
  and return that strict result. Profile 9 forms at most `873600` on either side,
  so neither product can overflow on this path.
- `FUN_180069820` has already clamped every copied u16 sample above `0x0fff`
  before calling this helper. Such an interior sample is therefore observed as
  `0x0fff` and does not satisfy the strict high bound; the helper itself neither
  rejects the frame for that value nor sees the original over-range value.
