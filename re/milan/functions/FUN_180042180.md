## Recovered Behavior

The supplied candidate list must be nonempty. The function initializes the
winner from `candidates[0]`, then replaces it only for a strictly greater direct
inlier count at `0x1800421a1..0x1800421f0`. Equal counts therefore retain the
first list entry. The production list is built in ascending prior-feature order
by `FUN_180041ac0`, so a production tie belongs to the lowest physical prior
index; the helper itself follows list order and does not numerically sort.

The winning direct relation is the 28-byte slot at
`context+0x1b8 + (row_base + prior_index)*0x1c`. A count greater than five is
required at `0x1800421f2..0x180042206`. Only that winner is passed to
`FUN_180071d40`, and its returned overlap must be strictly greater than
`param_3[6]` at `0x18004225c..0x180042264`.

On success, writes occur in this order at `0x180042266..0x1800422bb`:

1. Store the selected prior index at context `+0x87d8`.
2. Set the new feature and selected prior active words at feature `+0x110` to
   exactly `1`.
3. Set graph-established at context `+0x87e4` to exactly `1`.
4. Copy the selected direct transform's six words, excluding its leading
   inlier count, to the caller's transform output.
5. Add `0x100 + ((prior_index & 0xff) << 8)` to `param_3[7]`.

The direct slot is not rewritten, so its original leading inlier count and
transform remain the new-feature/reference relation. A winning count at most
five or overlap at most the threshold produces no writes at all. There is no
status return, rollback path, or later fallible operation after the first
success write.

Calling this helper with an empty list is outside its contract: it still reads
`candidates[0]` at `0x180042196..0x1800421a1`. A null list faults; a nonnull
zero-count list can select whatever first word is present.
