# Historical Harness Inventory

The maintained harness retains contracts, not the historical test forest.

| Historical source | Retained contract | Disposition |
|---|---|---|
| `milan-manifest.c` | DLL ABI, preprocessing/enrollment call order, schema-3 lifecycle | Reduce into the Wine runner |
| `run-manifest-oracle.py` | Sealed-prefix identity, explicit DLL selection, locking, durable records | Retain in the orchestrator |
| `milan-normal-boundary*.c` | DLL-owned 2,289-byte shadow with source index 2,288 set to zero | Retain for identify/study |
| `native-frozen-parity.py` | Defined-byte enrollment projection and exact scalar comparison | Retain as canonical record fields |
| `safe-zero-enrollment-reference.py` | Deterministic replacement, repeat identity, semantic comparison | Retain in generation validation |
| `safe-zero-matching-reference.py` | Exact controlled-zero score/decision/index authority | Retain in generation validation |
| `safe-zero-study-reference.py` and v2 | Ordered lifecycle phases and persistent links | Retain in generation validation |
| `milan-smoke.c` | Broad exploratory instrumentation | Discard |
| Per-question runners and shell wrappers | Historical execution layout | Discard after focused contracts are covered |
| Chicago/profile-0, notebooks, Ghidra helpers | Unrelated reverse engineering | Discard |

The old term `native` meant host-native C. Canonical enrollment output is the
validated host-native deterministic replacement constrained by DLL-defined
fields. Controlled-zero matching and study records are emitted directly by the
DLL under Wine.
